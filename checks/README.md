## 显式运行

本目录没有注册为根工程默认的 Maven 测试源码目录，不是独立 Maven 模块。根工程的 `test`/`test-compile` 不会自动读取这里；“根工程没有测试失败”不表示这些检查已运行。生产 `pom.xml` 保持原样。

在项目根目录运行下列命令，将占位内容替换为已安装的 JDK 25 目录：

```powershell
.\checks\run.ps1 -JdkHome '<JDK 25 目录>' -DependencyClasspathFile '.\checks\build\dependency-classpath.txt'
```

依赖文件仅包含已存在 JAR 的绝对路径，以分号或换行分隔，不包含旧编译目录。此次已为当前电脑生成 `build/dependency-classpath.txt`；它是本机文件，换电脑后需使用新电脑已有依赖重新准备。脚本不下载依赖、不修改 JAVA_HOME、IDE、Maven 仓库或 pom。

脚本每次把 `src/main/java`、`checks/java` 和运行器编译到新的 `checks/build/run-<唯一编号>/classes`，随后加载业务资源和 `checks/resources`。不读取归档或上次的 `.class`，不重建 `src/test`、`target/test-classes`。JUnit 没有发现测试、测试失败或存储检查异常时会失败退出。

新增 JUnit 检查继续使用项目包名，可由运行器发现；新增非 JUnit 的检查 main 时，需要同步更新 RunChecks 的显式调用清单。具体测试内容应验证行为，不为凑数量增加镜像实现的测试。
