# 01 - 系统总架构

> 最后更新：2026-08-10 | 项目规模：124 个 Java 源文件 / ~15,000 行代码 / ~106 个 @Tool 方法

---

## 1. 项目愿景

**MyHelper** 是一个本地化、多模态的个人 AI 智能助手，目标是实现 Jarvis 级别能力：

- **自然语音交互** — 唤醒词激活、流式对话、任意时刻打断、声纹身份识别
- **持久化记忆** — 记住偏好和习惯、语义检索历史对话、经验跨重启复用
- **自主执行任务** — 查资料、装软件、控智能家居、操控屏幕/键盘/鼠标
- **自我学习进化** — 成功执行自动提取经验、失败模式自动沉淀为规则、通用步骤自动抽象为原子计划、探索能力渐进式学习
- **设备全连接** — MCP 协议统一管理所有智能设备（GUI、智能家居、工具链）

## 6. 核心执行流程（详细）

### 6.1 语音处理全链路

```
用户说话
  │
  ▼
┌──────────────────────────────────────────────────────────────────────┐
│ Step 1: PCM 采集                                                     │
│ TargetDataLine → byte[] (16kHz/16bit/mono, 每次 3200B ≈ 100ms)      │
└──────────────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────────────┐
│ Step 2: VAD 语音分段 (Silero VAD v4)                                 │
│ acceptWaveform(samples) → hasSegment() 轮询 → nextSegment() 取段     │
│ 参数: threshold=0.5, minSilence=1.2s, maxSpeech=8s                    │
│ 回退: VAD 不可用时降级为能量检测 (ENERGY_THRESHOLD=0.02f)            │
└──────────────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────────────┐
│ Step 3: 尾部音频拼接 (200ms 环形缓冲区 trailBuf)                      │
│ withTrail = speech + trailBuf → 防止 VAD 截断丢句首                   │
└──────────────────────────────────────────────────────────────────────┘
  │
  ├── IDLE 状态? → 声纹验证 (3D-Speaker, 阈值 0.6)
  │              → ASR Online (Zipformer int8, 低延迟)
  │              → 唤醒词检测 ("那个谁")
  │
  └── VOICE_DIALOG 状态? → 声纹验证 → ASR Offline (Paraformer, 高精度)
  │
  ▼
┌──────────────────────────────────────────────────────────────────────┐
│ Step 4: SpeechAssembler 分句拼接 (500ms debounce 窗口)               │
│ 逐段 addSegment() → 超时 flush → getFullSentence() → speechQueue     │
└──────────────────────────────────────────────────────────────────────┘
  │
  ▼
┌──────────────────────────────────────────────────────────────────────┐
│ Step 5: speechQueue.poll(500ms) → 唤醒/打断/对话 路由                │
│ · IDLE 状态 + 唤醒词 → transitionTo(LISTENING) → TTS"我在"           │
│ · SPEAKING/PROCESSING 状态 → interruptCurrentAi() → 新指令处理       │
│ · LISTENING 状态 → touch() 记录交互时间 → 进入 AI 执行                │
└──────────────────────────────────────────────────────────────────────┘
```

### 6.2 对话状态机

```
状态转换规则 (DialogStateMachine):

    IDLE ──唤醒词──→ LISTENING
    LISTENING ──用户说完──→ PROCESSING
    PROCESSING ──AI 生成回复──→ SPEAKING
    SPEAKING ──TTS 播放完毕──→ LISTENING
    SPEAKING ──用户说话──→ INTERRUPTED
    INTERRUPTED ──处理打断内容──→ LISTENING

关键行为：
  · IDLE: 仅做模糊监听，只响应唤醒词，不消耗 ASR 完整算力
  · LISTENING: 5秒无语音 → 自动回 IDLE (silenceCount × 500ms 轮询)
  · PROCESSING/SPEAKING 被打断: 声纹验证（已注册用户）+ interruptCurrentAi()
  · lastInteractionTime: 每次 touch() 记录，供空闲检测使用
```

### 6.3 工具规划 — 三层缓存（核心优化点）

```
plan(userInput, allTools)
  │
  ├─ Layer 1: 内存缓存（最快，~0ms）
  │   key = AiResponseUtils.normalizeKey(userInput)（精确匹配兜底）
  │   命中 → 返回 PlanResult(fromCache=true, unit=entry.unit)
  │   LRU 上限 200 条 (access-order)
  │
  ├─ Layer 2: Unit 语义检索（跨重启持久化，~200ms）
  │   UnitStore.findSimilar(userInput, topK=3) → Qdrant unit-registry 搜索
  │     score_threshold: 0.6（embedding 只对 Unit.matchText 生成向量）
  │   命中 → 回填内存缓存 (L1) → 回 Neo4j 补全 Unit → 返回 PlanResult(fromCache=true)
  │
  └─ Layer 3: 多轮树形分类 + AI 规划
      doPlan() — 多轮渐进式交互:
        Round 1: buildL1Prompt() → 展示L1大类（name+desc+toolCount）→ AI选1-3个
                 → {"categories": [...], "reason": "..."}
        Round 2: 若有L2子类 → buildL2Prompt() → 展示子类列表 → AI选1-2个
                 → {"categories": [...], "reason": "..."}
        Round 3: 展示收集的工具列表 → planning.txt → AI挑工具+制定计划
                 → {"tools": [...], "plan": "...", "missing": [...]}
      → parseCategoryNames(): 解析reason + 硬截断>3个
      → parseFinalResponse(): 验证工具名 + 过滤脑补工具
      → 防死循环: maxCategoryRounds(3), 路径记忆visitedIds, 工具列表>50截断(放行listAllTools), 每轮硬截断≤3
      → 异常处理: 分类名不存在→模糊匹配候选→AI重试; AI不选分类→searchTool/listAllTools兜底路径
      → 降级信号: 轮次用尽/AI不选分类/工具>50 → PlanResult.allowListAllTools=true → 执行阶段放行listAllTools分页
      → 分类为空/轮次超限 → 降级 fallbackTools + 触发异步分类
      → 有新工具 → dirty 标记 → 自动重分类
```

**缓存淘汰策略（两层独立）**：
- 内存缓存：连续失败 3 次 → 清除（重启后也清空）
- Unit（Neo4j + Qdrant）：PLAN 失败 3 次 → status=ARCHIVED + unindex（数据保留，物理删除由价值评分定时清理）

**feedback 学习闭环**：
```
缓存命中 + 成功:
  → onCacheHitSuccess() → 内存 failureCount 重置
  → 异步 incrementSuccess() → successCount+1, stability 重算
  → successCount≥5 且 stability>0.9 → 升级 scriptable (可脚本化)

缓存命中 + 失败:
  → onCacheHitFailure() → 内存 failureCount+1
  → UnitFailureService.recordFailure(isPlanIssue=xxx)
  → PLAN 达阈值(3) → ARCHIVED + unindex + DISABLES；ENVIRONMENT → 仅写 notes

首次规划 + 成功:
  → 异步 UnitSedimentationService 沉淀 → 新建 Unit（scriptable 判定）
  → unitId 回填内存缓存

首次请求就失败:
  → unitId=null, 所有回调 no-op (只存成功方案)
```

### 6.4 AI 执行三条路径

```
TurnProcessor.process() → ToolPlanner.plan() 返回 PlanResult
  │
  ├─ 路径 A: 缓存命中 + 可脚本化 (scriptable=true)
  │   PlanMatcher.match(userInput, unit)
  │     → AI 判断计划是否适用当前输入
  │     → 提取变量值 ({$contact}→"张三", {$message}→"你好")
  │   UniversalUnitExecutor.executePlanStep(unitId, paramsJson)
  │     → scriptable=true → 遍历 script 逐步调用
  │     → 全程零 Token 消耗！纯脚本回放
  │   失败 → 走失败归因 → 分段继续/重新规划
  │
  ├─ 路径 B: 缓存命中 + AI 带参考执行 (不可脚本化)
  │   注入历史经验和教训到 prompt:
  │     "历史经验/教训: {unit.notes}"
  │   AI + 选中工具 + 失败警告 → 执行
  │
  └─ 路径 C: 新规划执行 (fromCache=false)
      1. AI + 选中工具 → 执行 (所有工具调用由 LoggingToolCallback 记录)
      2. ReflectService.reflectSuccess() → AI 总结 30 字成功经验
      3. UnitSedimentationService 沉淀 (异步)
         · 语义匹配去重 → 完全相同 / 某步不同 / 差异大 三分支
         · 判定 scriptable (§7.2 条件)
         · successCount+1, stability 重算
      4. cacheToMemory() → 写入 L1 内存缓存
```

### 6.5 Unit 经验闭环 — v1.7 统一单元

```
Unit 生命周期:

UnitSedimentationService 沉淀（成功执行后异步）
  │ 语义匹配去重（UnitStore.findSimilar）
  │
  ├─ 完全相同 → incrementSuccess()
  │   successCount+1 → stability 重算
  │   successCount≥5 ∧ stability>0.9 → tryUpgradeScriptable()（§7.2）
  │
  ├─ 某步不同 → appendNote() + 建 FALLBACK 变体
  │
  └─ 差异大 → 新建 Unit（判定 scriptable）
      unitKind: PLAN_STEP / TOOL / MCP_TOOL
      status=ACTIVE

关键字段（Unit）:
  · unitKind: TOOL（原子工具）/ PLAN_STEP（计划步骤）/ MCP_TOOL（MCP 底座）
  · matchText: 匹配语言字段，embedding 只对此字段生成向量（默认取 goal）
  · scriptable: 满足 §7.2 全部条件 → 可跳过 AI 直接脚本执行
  · script: 预编译线性脚本 List<ToolCallLog>
  · stability: successCount/(successCount+failureCount)
  · status: ACTIVE / ARCHIVED

失败归档（UnitFailureService，§6）:
  同一 PLAN 原因累计失败 3 次 → status=ARCHIVED + unindex + 父级建 DISABLES 边
  ENVIRONMENT 失败 → 仅写 notes，不惩罚
  MCP_TOOL 失败 → 仅记录，不归档/不禁用/无 FALLBACK
```

### 6.6 失败处理三层体系

```
失败发生
  │
  ├─ Layer 1: AI 即时归因 (ReflectService.reflectFailure)
  │   AI 分析 JSON:
  │     {isPlanIssue: true/false, lesson: "失败教训"}
  │   · isPlanIssue=true → 计划问题 (步骤错/工具错/参数错)
  │   · isPlanIssue=false → 环境问题 (目标不存在/网络中断/元素未加载)
  │
  │   计划问题 → 重新规划 + 重试
  │   环境问题 → 分段继续执行
  │
  ├─ Layer 2: FailureCause 复用 + 阈值归档 (UnitFailureService，v1.7 §5/§6)
  │   每次失败 → recordFailure(unitId, lesson, isPlanIssue, inputArgs)
  │   FailureCause 独立节点（network/environment/reason/category/timestamp）
  │     · PLAN：步骤错/顺序错/工具错/参数错 → 惩罚，累计失败
  │     · ENVIRONMENT：网络/窗口/第三方 → 不惩罚，仅写 notes
  │   PLAN 累计失败 3 次 → status=ARCHIVED + unindex + 父级建 DISABLES 边
  │   MCP 工具 → 只记录，不归档/不禁用/无 FALLBACK
  │
  └─ Layer 3: 跨案例规则归纳 (RuleInductionService @Scheduled)
      每天凌晨 3:00:
        扫描 FailureCause + 成功 Unit 摘要
        → LLM 跨案例归纳 → 通用 Rule
        → Neo4j (:Rule) 节点
        → ToolPlanner.doPlan() 注入规划 prompt
        → 未执行就避坑

失败经验注入规划 (新增):
  ToolPlanner.plan() 的 L1/L2 查询时并行调用 searchFailurePatterns()
  命中 → 作为 warning 注入 System Prompt:
    "⚠️ 历史失败警告: {描述}（失败{N}次，相似度{X}%）"
```

### 6.7.1 模型路由器 ModelRouter

**所有 AI 调用的唯一入口，项目中不得绕过。**

```
                  ┌────────────────────────────────────────────┐
                  │              ModelRouter                    │
                  │  chat() → NORMAL  │ chat(EXPLORATION)      │
                  │       ↓                  ↓                  │
                  │  normal-model      exploration-model       │
                  │       ↓                  ↓                  │
                  │  model1 ──failover──→ model2               │
                  │  (本地 Ollama)      (DeepSeek API)          │
                  └────────────────────────────────────────────┘
                          ↑                    ↑
          ┌───────────────┴────────────────────┴───────────────┐
          │  ToolPlanner  ReflectService  TurnProcessor  ...   │
          │  (只传 Mode，不读配置，不关心底层模型)                  │
          └────────────────────────────────────────────────────┘
```

**核心职责**：
1. **统一入口**：所有模块只调用 `chat()` / `chat(Mode)`，不关心模型来源
2. **配置驱动**：读取 `normal-model` / `exploration-model` 开关决定模型
3. **故障转移**：模型1 不可用 → 自动降级到模型2
4. **智能咨询**：模型1 回复不充分 → 咨询模型2 → 模型1 综合回复

**两种模式**：

| 模式 | 配置键 | 枚举值 | 说明 |
|------|--------|--------|------|
| NORMAL | `normal-model` | `model1` | 本地 Ollama 优先，失败/能力不足 → DeepSeek |
| NORMAL | `normal-model` | `model2` | 直连 DeepSeek，不调本地 |
| EXPLORATION | `exploration-model` | `model1` | 探索走本地优先 failover |
| EXPLORATION | `exploration-model` | `model2` | 探索全程 DeepSeek |

**使用方式**：
```java
// 默认普通模式（规划、执行、反思、分类…）
modelRouter.chat().prompt().user("问题").call().content();

// 探索模式
modelRouter.chat(Mode.EXPLORATION).prompt().user("问题").call().content();
```

**禁止**：
- 直接读 `props.normalModel()` / `props.explorationModel()` 判断模型
- 直接创建 `ChatClient` / 注入 `OpenAiChatModel`（除 `FallbackModelTool` 外）
- 绕过 ModelRouter 调用任何 AI 模型

**模型路由规则**：
  · exploration-model: model2 → 探索全程走云端 DeepSeek（决策+执行+评估），不同本地模型
  · exploration-model: model1 → 本地 qwen3:30b 先答，搞不定自动请教 DeepSeek（云端回复给本地做参考综合）
  · 不配置 → 默认当前模型
  · EmbeddingService → nomic-embed-text 始终走本地 Ollama (localhost:11434)，不受配置影响

能力清单（动态）:
  · 启动时扫描全部工具 → 按 CAPABILITY_RULES 自动归类
  · 只展示实际存在的工具对应的能力（工具增减自动适应）
  · 已掌握 vs 缺失 → 缺失项附带具体可执行步骤
  · 难度分级: ⭐单步操作 → ⭐⭐组合操作 → ⭐⭐⭐依赖流程 → ⭐⭐⭐⭐系统级

渐进式学习规则:
  · 能力清单显示缺失 → 必须从中选一个学习，禁止 SKIP
  · 基础未覆盖（⭐）→ 禁止跳级学 ⭐⭐⭐ 以上
  · 基础已覆盖 → 才允许往上扩展

工具搜索:
  · searchTool(keyword, keywordEn) — 始终可用，Qdrant 语义向量搜索 + 中文搜不到英文兜底，返回完整信息
  · listAllTools(page) — 默认锁死，仅分类降级场景放行（轮次用尽/AI不选分类/工具>50），分页每页50
  · 探索提示注入: "searchTool 必须传中英双语参数"

记忆维护 (MemoryMaintenanceService):
  @Scheduled(cron="0 0 4 * * ?") 凌晨4点
  占用率 = (Unit 节点数 + unit-registry 点数) / 100000
  占用率 ≥ 0.7 → 价值评分清理 status=ARCHIVED 或低价值 Unit → 目标 0.5
```

### 6.8 异常处理

| 异常场景 | 处理策略 |
|----------|----------|
| 自然打断 (AI 执行/TTS 播放中用户说话) | 声纹验证 → interruptCurrentAi() → 新指令处理 |
| 补充信息 (AI 执行中用户追加) | 语义关联判断 → 用户确认 → combinedInput 重调 AI |
| 工具调用失败 | ReflectService 归因 → 计划问题重规划 / 环境问题分段继续 |
| 脚本执行失败 (PlanExecutor) | ExecutionResult.failed → 记录 failedStepIndex → 从失败步之后继续 |
| AI 决策失败 / JSON 解析失败 | 降级到 null 或默认值，不崩溃 |
| Ollama / Qdrant / Neo4j 不可用 | 异步操作吞异常，写操作 no-op，读操作返回空列表 |
| 唤醒词误触发 | 声纹验证（已注册用户）+ 5秒无后续语音自动回 IDLE |
| TTS 回声干扰 ASR | TTS 播放/播后300ms → VAD 清空 + trailBuf 复位 → 不计入监听超时 |

## 12. 核心数据流转全景

```
用户说话
  │
  ▼
麦克风 → TargetDataLine → byte[] → float[]
  │
  ├── VAD (Silero) → SpeechSegment
  ├── 声纹 (3D-Speaker) → currentSpeaker
  ├── ASR (Zipformer/Paraformer) → text
  └── SpeechAssembler → 完整句子 → speechQueue
  │
  ▼
DialogStateMachine → 路由
  ├─ 唤醒 → transitionTo(LISTENING) → TTS"我在"
  ├─ 打断 → interruptCurrentAi() → 新指令
  └─ 对话 → touch() → TurnProcessor.process()
  │
  ▼
SkillConfig → 技能指令注入
  │
  ▼
ToolPlanner.plan() ── 三层缓存:
  L1: 内存 → 命中? 跳过 L2/L3
  L2: Unit 语义检索（unit-registry）→ 命中? 回填 L1
  L3: 树形分类 + AI → 新规划
  │
  ▼
PlanResult{selectedTools, unitId, fromCache, failureWarnings}
  │
  ├─ fromCache + scriptable → PlanMatcher → UniversalUnitExecutor (零Token)
  ├─ fromCache + !scriptable → AI + 历史经验注入
  └─ !fromCache → AI执行 → Reflect → Unit 沉淀/归档
  │
  ▼
ChatClient + selectedTools (LoggingToolCallback 包装)
  → 每步工具调用自动记录 ToolCallLog{name, args, result, success, duration}
  │
  ▼
执行完成:
  ├─ 成功 → ReflectService.reflectSuccess()
  │         → UnitSedimentationService 沉淀（完全相同/某步不同/差异大）
  │
  └─ 失败 → ReflectService.reflectFailure()
            → UnitFailureService.recordFailure → FailureCause 复用 + PLAN 失败 3 次归档
            → 计划问题? 重规划 / 环境问题? 分段继续
  │
  ▼
TtsService.speakAsync(response)
  → playQueue → SourceDataLine → 扬声器
  → 播放中持续监听 → 支持自然打断
```

## 13. 快速开始

```bash
# 1. 启动基础设施
docker compose up -d

# 2. 启动 Ollama + 拉取模型
ollama serve &
ollama pull nomic-embed-text    # 嵌入模型 (274MB)
ollama pull qwen3:30b           # 探索模型（exploration-model=model1 时使用，本地搞不定请教云端）

# 3. 编译并运行
mvn compile -DskipTests
mvn spring-boot:run

# 4. 验证
# · Neo4j: http://localhost:7474
# · Qdrant: http://localhost:6333
# · Ollama: http://localhost:11434
# · robot-mcp: http://localhost:8081/mcp
# · 应用: http://localhost:8082
```

**交互方式**：
- **语音**：说"那个谁"唤醒 → 对话 → 说"退出"结束
- **文字**：终端直接输入，AI 回复有语音播报
- **打断**：AI 在说/在想时说"停"中断
- **探索**：对 AI 说"学点新东西"手动触发
