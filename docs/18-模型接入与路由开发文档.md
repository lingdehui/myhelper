# 模型接入与路由开发文档

> 共同开发规则（2026-11-11 用户确认）：固定 LLM 文本集中到 LlmTexts；不用 Lambda，以可读性选择循环、方法和 switch，允许 `case ... ->`。所有任务继续前阅读[24-LLM文本与代码可读性规范](24-LLM文本与代码可读性规范.md)。

更新：2026-11-10。尚无独立接入/路由实现；AgentCaller 已通过外部函数解析 modelRef。本文件为建议。

## 职责与合同

ModelRegistry 将配置引用解析为可用 ChatModel；ModelRouter 根据调用方提供的任务类别、所需工具调用/输出能力、上下文长度、预算和可用性选择 modelRef。密钥由配置提供，不进入世界模型、执行链路或提示词。能力声明和实际服务错误均需记录，不能只凭模型名称假定兼容。

输入：调用用途、上下文需求、工具合同、预算、首选模型、允许的降级范围。输出：modelRef、选择原因、实际限制与关联 invocationId。模型响应保留文本、原生工具调用、结束原因、用量及协议错误。

## 与单次调用的边界

单次调用仍只请求一次模型；轮次和跨模型重试由编排器决定。配置禁用框架隐式工具循环，按项目锁定的 Java 25 / Spring AI 2.0.0-M3 核对本地 API。不能根据最新在线示例自动升级依赖。

多个独立任务可并发调用模型；设置按提供方、模型和全局的在途数限制及排队时限。具体 ChatModel/客户端线程安全性在适配时验证，不能仅因 AgentCaller 无可变消息字段就假定所有依赖可并发。

## 错误与用量

区分网络/限流、认证配置、上下文超长、响应截断、协议错误及模型拒绝。只在上层明确策略下重试，保留每次请求身份；工具执行结果不因切模型被重放。用量未知标未知，不能用零替代；记录模型耗时与等待耗时，评估并发是否真的缩短关键路径。

## 验收

modelRef 可准确解析；能力不匹配不调度；单次调用不隐式递归；工具参数协议保留；限流排队有界；用量/模型版本可追踪；模型切换保留正确消息；没有真实服务验证时仅报告模拟/接口验证。
