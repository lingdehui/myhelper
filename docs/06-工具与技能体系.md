# 06 - 工具与技能体系

## 1. 工具分类总览

> 所有工具（Java @Tool / MCP / @GeneratedTool）由 **ToolRegistry** 统一管理，启动时通过 `ToolSyncService` 自动入库（Neo4j + Qdrant + 内存三级缓存）。
> 以下列出 Java `@Tool` 注解工具的详细说明。MCP 工具由 `robot-mcp` 连接提供（GUI操控/截图/OCR/键盘鼠标等），运行时动态发现。

### MCP 工具分类

MCP 工具通过 `spring.ai.mcp.client.streamable-http.connections.robot-mcp` 连接注入，提供约 40+ 个远程 GUI 操控能力：

| 分类 | 典型工具 | 说明 |
|------|----------|------|
| 屏幕截取 | `captureScreen`, `captureRegion`, `waitForScreenStable` | 截图/稳定检测 |
| OCR 识别 | `ocrScreen`, `ocrRegion`, `findTextOnScreen`, `clickTextOnScreen`, `findPixelColor` | 屏幕文字/颜色识别与定位 |
| 窗口管理 | `listMonitors`, `focusWindow`, `listWindows`, `getActiveWindowTitle` | 窗口/显示器操作 |
| 鼠标操作 | `mouseMove`, `leftClick`, `rightClick`, `doubleClick`, `middleClick`, `mouseScroll` | 鼠标控制 |
| 键盘输入 | `typeText`, `typeTextViaClipboard`, `pressKey`, `pressKeyCombination` | 键盘输入 |
| UI 元素 | `findElement`, `getTextContent` | UI 元素查找与读取 |
| 剪贴板 | `getClipboard`, `setClipboard` | 剪贴板操作 |

## 3. 工具调用流程

### 3.1 整体架构

```
用户输入
  │
  ▼
┌─────────────────────────────────────┐
│  1. 技能匹配（SkillConfig）          │
│     扫描 skills/ 目录 → 正则匹配     │
│     命中 → 注入 instruction 到 prompt │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│  2. 工具规划（ToolPlanner）          │
│     树形分类：AI浏览分类树→选工具+分类  │
│     制定计划 → 返回 PlanResult       │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│  3. 缓存判定                         │
│     fromCache=true  → handleCacheHit │
│     fromCache=false → handleNewPlan  │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│  4. AI 执行（ChatClient）            │
│     调用选中的 ToolCallback          │
│     记录 ToolCallLog                │
│     生成 AI 回复                     │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│  5. 反馈学习                         │
│     成功 → onCacheHitSuccess         │
│     失败 → onCacheHitFailure         │
│     沉淀 / 更新 Unit                 │
└─────────────────────────────────────┘
```

### 3.2 详细步骤

**Step 1 - 技能匹配：**
- 调用 `SkillConfig.getInstructions(userInput)`
- 对 `skills/` 目录下所有 `.txt` 文件的 keywords 做正则匹配
- 命中的 skill instruction 拼接到用户输入前面，形成 `effectiveInput`

**Step 2 - 工具规划（树形分类驱动）：**
- 调用 `ToolPlanner.plan(userInput, allTools)`
- 走三层缓存逻辑（详见第 4 节），Layer 1 内存、Layer 2 Unit 语义检索
- Layer 3 未命中时：从 Qdrant 拉全量分类 → 多轮分类浏览（L1 选 1-3 个 → L2 展开子类 → 最终轮挑工具）
- 最终轮 AI 返回 JSON：`{"tools": [...], "plan": "...", "missing": [...]}`
- 系统过滤验证工具名 → 始终附加 searchTool + listAllTools → 返回 PlanResult

**Step 3 - 缓存判定与执行：**
- **缓存命中**（`fromCache=true`）：
  1. `PlanMatcher.match()` 判断计划是否适用，提取变量
  2. 附加 `unit.notes`（历史经验）到 prompt
  3. 如果 `unit.scriptable`（稳定度 ≥ 0.9 且成功次数 ≥ 5）→ 直接执行脚本
  4. 否则 → 带参考计划调 AI 执行
- **新规划**（`fromCache=false`）：
  1. 调 AI 选择工具并执行
  2. 成功 → `UnitSedimentationService.sediment()` 沉淀 Unit，写入缓存

**Step 4 - 反馈学习：**
- 成功：`onCacheHitSuccess()` → 重置失败计数 → 异步 incrementSuccess
- 失败：`onCacheHitFailure()` → 归因判断（计划问题/环境问题）→ 决定惩罚策略

## 4. 工具规划器（ToolPlanner）

### 4.1 概述

`ToolPlanner` 是三阶段工具规划器，采用**三层缓存 + Unit 语义经验**架构，实现跨重启的语义级方案复用。

### 4.2 三层缓存查询

```
plan(userInput, allTools):
  │
  ├─ [Layer 1] 内存缓存（ConcurrentHashMap）
  │     key = normalizeKey(userInput) → 标点/数字归一化
  │     命中 → 直接返回（最快，避免 embedding 开销）
  │
  ├─ [Layer 2] Unit 语义检索（Qdrant unit-registry）
  │     embed(userInput) → search(top_k=3, score≥0.6)
  │     filter: status=ACTIVE AND stability≥0.6
  │     命中 → 回填内存缓存 → 返回
  │
  └─ [Layer 3] 树形分类 + AI 规划（多轮渐进，详见 §4.3）
         1. ToolCategoryService.listAllCategories()
            → 从 Qdrant 拉全量分类 → 过滤 level=1 得 L1 大类
         2. 多轮分类浏览（parseCategoryNames()）：
            Round 1  buildL1Prompt() → AI 选 1-3 个 L1
            Round 2  对选中 L1 展开 L2 子类 → AI 选 1-2 个（无 L2 则直接收工具）
                     （轮次用尽或拒绝分类 → 降级全量前50 / searchTool 兜底）
         3. 最终轮 doFinalRound() → AI 挑工具 + 制定计划
            parseFinalResponse() → 验证工具名（过滤脑补工具）→ 附加 searchTool + listAllTools + alwaysAppendTools
         分类为空 → 降级 fallbackTools + 触发异步云端 AI 分类
         有新工具 → dirty 标记 → 自动重分类
```

### 4.3 树形分类工具选择（v1.5，2026-08-12）

**核心原则**：多轮渐进式交互（树形分类多轮设计），AI 逐步缩小范围 — Round 1 选 L1 大类 → Round 2 选 L2 子类（可选）→ Round 3 挑工具 + 制定计划。禁止一次性全量展开。

**树形分类结构（3层）**：

```
L1 大类 (8-15个) — 功能领域，简短描述（如"GUI操控 - 控制屏幕、鼠标、键盘等图形界面操作"）
  ├─ L2 子类 (可选) — 当L1下工具超过15个时拆分（如"鼠标操作 - 鼠标移动、点击、拖拽、滚轮滚动"）
  │   └─ 工具列表 (10-25个) — 实际工具名，如 mouseMove, leftClick, rightClick
  └─ 无L2时直接挂工具 — L1下工具≤15个时省略子类层
```

**分类由云端 AI（DeepSeek）自动生成**：`tool-category-sync.txt` prompt 指导 AI 生成严格 JSON 树形结构 → `flattenTree()` 展平存入 Qdrant（每个节点独立 point，含 `parentId` + `level` + `tools`）→ 运行时 `listAllCategories()` 拉全量分类，`buildL1Prompt()`/`buildL2Prompt()` 供 AI 多轮浏览。

**doPlan() 流程（多轮交互）**：

```
doPlan():
  Round 1 — L1 大类选择:
    buildL1Prompt() → 展示 L1 列表（name + description + toolCount）
    AI 返回: {"categories": ["GUI操控", "文件管理"], "reason": "需要截图和保存文件"}  (限选1-3个)
  
  Round 2 — L2 子类选择（若选中 L1 有子类）:
    对每个选中L1:
      无L2 → 直接收集工具
      有L2 → buildL2Prompt() 展示子类列表（name + description + toolCount）
            AI 返回: {"categories": ["屏幕截取", "鼠标操作"], "reason": "需要截屏和点击"}  (限选1-2个)
            → 收集选中L2下的工具
    轮次 ≥ maxCategoryRounds(默认3) → 降级为全量工具前50个，不再交互

  Round 3 — 工具选择 + 计划:
    展示收集到的工具列表（name + description）
    AI 返回: {"tools": ["captureScreen", "leftClick"], "plan": "...", "missing": [...]}
    parseFinalResponse() 解析 → 验证工具名 → 附加 searchTool + listAllTools
```

**与旧版的关键区别**：
| 项目 | 旧版（已废弃，2026-08-11） | 新版（树形分类，2026-08-12） |
|------|---------------------------|---------------------------|
| 分类结构 | 扁平列表（name+toolCount+desc） | 3层树形（L1→L2→工具，含 parentId/level） |
| AI 看到的 | 分类序号表 → 选分类名 | 分类树全文（含工具名）→ 直接挑工具 |
| AI 返回 | `{"categories": [...], "missing": [...]}` | 多轮：L1轮→`{"categories", "reason"}`, L2轮→`{"categories", "reason"}`, 最终轮→`{"tools", "plan", "missing"}` |
| 解析方法 | `parseCategorySelection()`（已删除） | `parseCategoryNames()` (L1/L2轮) + `parseFinalResponse()` (最终轮) |
| 流程 | AI选分类→系统展开工具→AI调工具 | 多轮渐进：Round1选L1→Round2选L2→Round3挑工具+制定计划 |

**跨分类工具获取**：AI 可以用 `searchTool(中文词, 英文词)` 搜索不在当前展开分类中的工具（始终可用，返回完整信息）。`listAllTools(page)` 不是随时可调的全量出口，只在分类浏览"走到头"的降级场景才放行（见下"listAllTools 放行条件"），且只返回工具名并分页。

**listAllTools 放行条件**（默认锁死，以下降级场景才解锁）：

1. 分类交互轮次用尽（`roundCount >= maxCategoryRounds`，默认 3）；
2. AI 始终不选分类、要求全部工具（L1 选择为空）；
3. 工具列表超过 `max_tools_displayed`（50）被截断。

实现链路：`doPlan()` 在以上降级出口调用 `PlanResult.withListAllToolsAllowed()` 打标记 → `executeWithTools()` 读 `plan.allowListAllTools()` → `ToolSearchService.setListAllToolsAllowed(true)` → `listAllTools()` 检查该标记，未放行时返回引导提示（不返回工具列表）。

**防死循环与异常**：
- 分类数据为空 → 降级 fallbackTools + 触发异步分类同步
- L1 选择为空 → 降级为 searchTool/listAllTools 路径（传前 50 个工具），并放行 `listAllTools`
- AI 返回脑补工具 → 过滤并标记 missing，提示用 searchTool
- 分类名不存在 → 模糊匹配 1-2 候选 → AI 重试（消耗 1 轮次）
- 路径记忆拒绝：重选已展开分类 → 拒绝 + 消耗轮次
- JSON 解析失败 / 非 JSON 响应 → 降级 fallbackTools
- 所有工具过滤后为空 → 降级 fallbackTools
- L1 > 15 个 → 自动触发 `consolidateCategories()` 精简合并
- 轮次超限（≥ `maxCategoryRounds`，默认 3）→ 降级为全量工具前 50 个，并放行 `listAllTools`
- 工具列表 > 50 个 → 截断，并放行 `listAllTools` 兜底翻页
- 每轮分类选择 > 3 个 → 硬截断 `subList(0, 3)`

### 4.4 淘汰策略

| 缓存层 | 淘汰条件 |
|--------|----------|
| 内存缓存 | 连续失败 3 次 → 清除（重启后也清空） |
| Unit | `failureCount+1`，`stability<0.3` 或 PLAN 失败 3 次 → `status=ARCHIVED` + unindex（Neo4j 保留用于追溯） |

### 4.5 脚本化执行

当 Unit 满足以下条件时，可跳过 AI 直接执行脚本：
- `successCount ≥ 5`
- `stability > 0.9`

脚本化执行通过 `PlanExecutor.executeScript()` 完成，直接复用上一次成功的工具调用序列。

### 4.6 PlanResult 结构

```java
public record PlanResult(
    List<String> selectedToolNames,          // 选中的工具名列表（分类展开后）
    List<String> missingDescriptions,        // 缺失的工具描述（MISSING: ...）
    boolean fromCache,                       // 是否来自缓存
    String unitId,                           // 关联的 Unit ID
    Unit unit,                               // 完整 Unit（含 notes 和 script）
    List<FailureCause> failureWarnings       // 历史失败原因警告
) {}
```

### 4.7 反馈学习流程

| 场景 | 内存操作 | Unit 操作 |
|------|----------|-------------|
| 缓存命中 + 成功 | 重置 `failureCount` | `incrementSuccess()`（successCount+1） |
| 缓存命中 + 失败（计划问题） | `failureCount+1`，达阈值清除 | `recordFailure()`（failureCount+1） |
| 缓存命中 + 失败（环境问题） | 保留缓存，不惩罚 | 追加 notes，保留检索权 |
| 首次规划 + 成功 | 写入内存缓存 | `sediment()` → 沉淀/复用 Unit |
| 首次规划 + 失败 | 不写入 | 失败归因 → FailureCause 归档 |
