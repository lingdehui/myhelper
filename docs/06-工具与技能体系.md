## 3. 工具调用流程

### 3.1 整体架构

```
用户输入
  │
  ▼
┌─────────────────────────────────────┐
│  1. 技能匹配（SkillConfig）          │
│     扫描 skills/ 目录 → 正则匹配     │
│     命中 → 注入 instruction 到 prompt │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│  2. 工具规划（ToolPlanner）          │
│     三层缓存查询 → 返回 PlanResult   │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│  3. 缓存判定                         │
│     fromCache=true  → handleCacheHit │
│     fromCache=false → handleNewPlan  │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│  4. AI 执行（ChatClient）            │
│     调用选中的 ToolCallback          │
│     记录 ToolCallLog                │
│     生成 AI 回复                     │
└─────────────┬───────────────────────┘
              │
              ▼
┌─────────────────────────────────────┐
│  5. 反馈学习                         │
│     成功 → onCacheHitSuccess         │
│     失败 → onCacheHitFailure         │
│     创建/更新 Episode               │
└─────────────────────────────────────┘
```

### 3.2 详细步骤

**Step 1 - 技能匹配：**
- 调用 `SkillConfig.getInstructions(userInput)`
- 对 `skills/` 目录下所有 `.txt` 文件的 keywords 做正则匹配
- 命中的 skill instruction 拼接到用户输入前面，形成 `effectiveInput`

**Step 2 - 工具规划：**
- 调用 `ToolPlanner.plan(userInput, allTools)`
- 走三层缓存逻辑（详见第 4 节）

**Step 3 - 缓存判定与执行：**
- **缓存命中**（`fromCache=true`）：
  1. `PlanMatcher.match()` 判断计划是否适用，提取变量
  2. 附加 `successLesson` / `failureLesson` 到 prompt
  3. 如果 `isScriptable()`（稳定度 ≥ 0.9 且成功次数 ≥ 5）→ 直接执行脚本
  4. 否则 → 带参考计划调 AI 执行
- **新规划**（`fromCache=false`）：
  1. 创建 DRAFT Episode
  2. 调 AI 选择工具并执行
  3. 成功 → DRAFT 转 ACTIVE，写入缓存

**Step 4 - 反馈学习：**
- 成功：`onCacheHitSuccess()` → 重置失败计数 → 异步 incrementSuccess
- 失败：`onCacheHitFailure()` → 归因判断（计划问题/环境问题）→ 决定惩罚策略

## 4. 工具规划器（ToolPlanner）

### 4.1 概述

`ToolPlanner` 是三阶段工具规划器，采用**三层缓存 + Episode 经验学习**架构，借鉴 ExpeL/MUSE 经验学习思想，实现跨重启的语义级方案复用。

### 4.2 三层缓存查询

```
plan(userInput, allTools):
  │
  ├─ [Layer 1] 内存缓存（ConcurrentHashMap）
  │     key = normalizeKey(userInput) → 标点/数字归一化
  │     命中 → 直接返回（最快，避免 embedding 开销）
  │
  ├─ [Layer 2] Episode 向量检索（Qdrant）
  │     embed(userInput) → search(top_k=3, score≥0.65)
  │     filter: archived=false AND stability≥0.6
  │     命中 → 回填内存缓存 → 返回
  │
  └─ [Layer 3] AI 规划（优先动态分类，降级硬编码兜底）
         embed(userInput) → Qdrant tool-categories 向量搜索
         → 匹配分类列表 → AI 选择分类编号 → 映射工具
         无匹配 → 降级到 5 个硬编码兜底分类
```

### 4.3 工具动态分类（Qdrant 向量存储） ✅

**旧版（已废弃）**：`ToolPlanner` 内硬编码 10 个 `Category`，工具列表写死，新工具（HA、生成的 tool）永远不在分类里。

**新版**：`ToolCategoryService` 启动时 AI 自动扫描所有 ToolCallback 分组归类，每个分类作为独立 point 存入 Qdrant `tool-categories` collection。规划时 embed 用户意图 → 向量搜索匹配分类 → 返回工具列表。

**分类流程**：
1. **启动同步**：`ToolPlanner.syncCategories(allTools)` — AI 收到全部工具名+描述 → 分组归类 → 逐条写入 Qdrant
2. **规划搜索**：`ToolCategoryService.searchCategories(userInput, topK, minScore)` — embed 用户输入 → 搜索 tool-categories → 返回匹配分类
3. **兜底降级**：Qdrant 不可用或无匹配时，使用 5 个简化硬编码分类保证基本可用

**分类特征**：
- 支持交叉分类：同一工可出现在多个分类中
- 分类数量随工具数量动态增长（无上限）
- 分类描述作为向量，AI 语义匹配更精确
- 分类同步是异步的，不阻塞启动流程

**配置项**：

| 配置键 | 默认值 | 说明 |
|--------|--------|------|
| `qdrant.category.top-k` | `5` | 向量搜索返回分类数 |
| `qdrant.category.min-score` | `0.3` | 最低相似度阈值 |

**兜底分类（5 类）**：Qdrant 不可用时的最低保障

| 编号 | 分类名 | 包含工具 |
|------|--------|----------|
| 1 | 窗口与鼠标 | `focusWindow`, `listWindows`, `getActiveWindowTitle`, `getMousePosition`, `mouseMove`, `leftClick`, `doubleClick`, `rightClick`, `middleClick`, `mouseScroll` |
| 2 | 键盘与输入 | `typeText`, `typeTextViaClipboard`, `pressKey`, `pressKeyCombination` |
| 3 | 屏幕识别 | `ocrScreen`, `ocrRegion`, `findTextOnScreen`, `clickTextOnScreen`, `findPixelColor`, `waitForPixelColor` |
| 4 | UI与剪贴板 | `findElement`, `getTextContent`, `getClipboard`, `setClipboard` |
| 5 | 联系人 | `findFriend`, `listLocalSkills` |

**兜底工具（Fallback）：** 当 AI 规划失败时使用，覆盖窗口管理、鼠标、键盘、OCR 等核心能力。

### 4.4 淘汰策略

| 缓存层 | 淘汰条件 |
|--------|----------|
| 内存缓存 | 连续失败 3 次 → 清除（重启后也清空） |
| Episode | `failureCount+1`，`stability<0.3` 或连续失败 3 次 → `archived=true`（不被检索但数据保留） |

### 4.5 脚本化执行

当 Episode 满足以下条件时，可跳过 AI 直接执行脚本：
- `successCount ≥ 5`
- `stability > 0.9`

脚本化执行通过 `PlanExecutor.executeScript()` 完成，直接复用上一次成功的工具调用序列。

### 4.6 PlanResult 结构

```java
public record PlanResult(
    List<String> selectedToolNames,   // 选中的工具名列表
    List<String> missingDescriptions, // 缺失的工具描述（补写提示）
    boolean fromCache,                // 是否来自缓存
    String episodeId,                 // 关联的 Episode ID
    Episode episode                   // 完整 Episode（含经验教训）
) {}
```

### 4.7 反馈学习流程

| 场景 | 内存操作 | Episode 操作 |
|------|----------|-------------|
| 缓存命中 + 成功 | 重置 `failureCount` | `incrementSuccess()`（successCount+1） |
| 缓存命中 + 失败（计划问题） | `failureCount+1`，达阈值清除 | `recordFailure()`（failureCount+1） |
| 缓存命中 + 失败（环境问题） | 保留缓存，不惩罚 | 存入 `failureLesson`，保留检索权 |
| 首次规划 + 成功 | 写入内存缓存 | `activateDraft()` → 持久化 |
| 首次规划 + 失败 | 不写入 | DRAFT → FAILED，仍保留步骤数据 |
