# 08 - 工具自生成与动态加载

> 用户核心设计："如果工具缺失，自己写工具能做到么？然后提醒用户重启，或者可以动态加载。"

## 1. 设计目标

当 AI 规划任务时发现**能力缺失**（用户请求需要某类工具，但当前工具分类里没有），系统自动：

1. 让 AI 生成一个带 `@Component` + `@Tool` 注解的 Java 类源码
2. 用 JDK 编译器验证语法/API 正确性
3. 持久化到 `src/main/java/com/example/desktopbrain/generated/` 目录
4. 提醒用户重启应用（重启后 Spring 自动扫描注册新工具）

## 2. 整体流程

```
用户请求 → ToolPlanner 规划 → 报告 missingDescriptions
                                      │
                                      ▼
                        triggerToolGeneration()  (异步，不阻塞当前请求)
                                      │
                    ┌─────────────────┴─────────────────┐
                    ▼                                   ▼
            ToolGenerator.generate()          (当前请求用兜底工具继续跑)
            AI 生成 .java 源码
                    │
                    ▼
            ToolCompiler.compileAndPersist()
            临时目录编译验证 → 成功 → 写入 generated 目录
                    │                           │
                    ▼                           ▼
              编译失败                TTS 提醒"已生成新工具，重启后生效"
              带错误信息重试
              (最多2次)
```

## 3. 核心组件

### 3.1 ToolGenerator（AI 生成源码）

**文件**：[ToolGenerator.java](file:///e:/projcket/my/myhelper/src/main/java/com/example/desktopbrain/autogen/ToolGenerator.java)

**职责**：调 ChatClient，根据工具功能描述生成完整 .java 源码。

**生成规范**：
- 包名固定：`com.example.desktopbrain.generated`（在 `@ComponentScan` 范围内）
- 必须带 `@Component` 注解（重启后 Spring 自动扫描）
- 工具方法必须带 `@Tool(description=...)` 注解
- 参数必须带 `@ToolParam(description=...)` 注解
- 只用 JDK 标准库 + Spring AI 注解，不引入第三方依赖
- 方法内部 try-catch，返回友好错误字符串，不外抛异常

**关键方法**：
- `GeneratedSource generate(String toolDescription)` — AI 生成源码 + 提取类名

### 3.2 ToolCompiler（编译验证 + 持久化）

**文件**：[ToolCompiler.java](file:///e:/projcket/my/myhelper/src/main/java/com/example/desktopbrain/autogen/ToolCompiler.java)

**职责**：用 JDK 自带的 `javax.tools.JavaCompiler` 编译验证，通过后才持久化。

**两阶段策略**：
1. **验证编译**：先编译到临时目录，验证语法/API 正确性
2. **持久化**：验证通过才写入 `src/main/java/com/example/desktopbrain/generated/`

**关键方法**：
- `CompileResult compileAndPersist(String source, String className)` — 编译验证 + 持久化

### 3.3 GeneratedToolRegistry（管理中心）

**文件**：[GeneratedToolRegistry.java](file:///e:/projcket/my/myhelper/src/main/java/com/example/desktopbrain/autogen/GeneratedToolRegistry.java)

**职责**：协调生成流程 + 管理已生成工具记录 + 防重复生成。

**核心能力**：
- 启动时扫描 `generated/` 目录，加载已有工具记录
- `generateAndPersist(description, maxRetries)` — 协调生成+编译，带编译错误反馈的重试循环
- `listGeneratedTools()` — 列出所有已生成工具
- `removeGeneratedTool(className)` — 删除已生成工具

**防重复**：用 descriptionHash → 工具信息映射，相同描述不重复生成。

## 4. 触发机制（missingDescriptions 钩子）

**文件**：[DesktopBrainApplication.java](file:///e:/projcket/my/myhelper/src/main/java/com/example/desktopbrain/DesktopBrainApplication.java) 的 `processAITurn` + `triggerToolGeneration`

当 `ToolPlanner.plan()` 返回的 `missingDescriptions` 非空时，**异步触发**生成（不阻塞当前请求）：

```java
if (!plan.missingDescriptions().isEmpty()) {
    for (String desc : plan.missingDescriptions()) {
        triggerToolGeneration(desc, ttsService);  // 异步
    }
}
```

生成完成后 TTS 播报结果：
- 成功："检测到缺失能力，已自动生成新工具 XxxTool，重启后生效"
- 失败："工具自动生成失败，[原因]"

## 5. 加载策略对比

| 策略 | 实现 | 优点 | 缺点 | 状态 |
|------|------|------|------|------|
| **重启加载**（默认） | 持久化到 generated 目录，重启后 Spring 扫描 | 可靠、简单、Spring 自动管理 | 需要重启 | ✅ 已实现 |
| **热加载**（预留） | URLClassLoader 运行时加载 | 无需重启 | Spring AI ToolCallbackProvider 启动时扫描，运行时注入复杂（ClassLoader 隔离） | ⬜ 预留 |

> 当前选择重启加载策略：可靠优先。热加载因 Spring AI 的工具注册机制是启动时扫描的，运行时动态注入 ToolCallback 涉及 ClassLoader 隔离和 Spring 容器管理问题，暂不实现。


## 8. 限制与注意事项

1. **JDK 环境**：编译依赖 `javax.tools.JavaCompiler`，必须运行在 JDK（非 JRE）上
2. **依赖限制**：生成的工具只能用 JDK 标准库 + Spring AI 注解，不能用第三方库（classpath 不含）
3. **编译版本**：用 `--release 17` 编译，确保兼容性
4. **重试机制**：编译失败时带错误信息让 AI 重新生成，最多 2 次重试
5. **不阻塞主流程**：生成是异步的，当前请求用兜底工具继续执行
