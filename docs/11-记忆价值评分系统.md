# 11 - 记忆价值评分系统

## 1. 概述

记忆系统的容量会随使用时间线性增长。v1.7 起，记忆统一建模为 **Unit**（Neo4j 图节点 + Qdrant `unit-registry` 检索入口），简单的 `status=ARCHIVED` 清理策略过于粗糙——一条被高频复用的黄金 Unit 可能因一次失败被归档，稳定性降低后就被误删。

需要引入**多维价值评分算法**，综合评估每条 Unit 的保留价值，优先删除低价值数据。

> **与 v1.7 §6 失败删除的分工**：
> - §6 是**触发式逻辑删除**：同一 PLAN 原因累计失败 3 次 → 置 `status=ARCHIVED` + `UnitStore.unindex()`（移除 Qdrant 检索入口）+ 给父级建 `DISABLES` 边。归档的 Unit 仍保留在 Neo4j 中，用于结构与 FALLBACK 追溯。
> - 本系统是**定时式物理清理**：每天凌晨 4:00 巡检，对已归档 / 低价值的 Unit 计算价值评分，物理删除 Neo4j 节点（Qdrant 已在归档时 unindex，无需重复处理）。

## 2. 核心算法

### 2.1 价值评分公式

```
valueScore = w1 × recencyScore + w2 × usageScore + w3 × userProducedScore + w4 × dependencyScore
```

| 权重 | 配置键 | 默认值 | 含义 | 评分逻辑（v1.7 Unit 字段） |
|------|--------|--------|------|----------|
| w1 | `weights.recency` | 0.30 | 时间新鲜度 | `1.0 - min(ageInDays / retentionDays, 1.0)` |
| w2 | `weights.usage` | 0.30 | 使用频率 | `min(successCount / 10.0, 1.0)`（10次封顶） |
| w3 | `weights.userProduced` | 0.25 | 用户直接产出 | `explorationRecords` 为空 → 1.0；有探索记录 → 0.5 |
| w4 | `weights.dependency` | 0.15 | 被依赖关系 | `min(父级 CONTAINS 入边数 / 5.0, 1.0)`（被5个父级引用封顶） |

### 2.2 评分细节

**recencyScore（新鲜度）**：
```
lastActivityAt = max(
    最新 FailureCause.timestamp（失败原因发生时间）,
    最新 ExplorationRecord.timestamp（探索记录发生时间）
)
ageInDays = (now - lastActivityAt) / 86400000
retentionDays = 根据来源类型查 retention-rules（默认 90 天）
score = 1.0 - min(ageInDays / retentionDays, 1.0)
```
- Unit 本身不存时间戳，最近活动时间由关联的 `failureCauses` / `explorationRecords` 推导。
- 无任何关联记录（从未失败、也未被探索）→ 视为旧数据，`recencyScore` 取 0。
- 示例：10 天前最近一次失败的 Unit（保留 90 天）→ `1.0 - 10/90 = 0.889`

**usageScore（使用频率）**：
```
score = min(unit.successCount / 10.0, 1.0)
```
示例：成功执行了 8 次 → `0.8`；成功执行了 15 次 → `1.0`（封顶）

**userProducedScore（来源价值）**：
```
unit.explorationRecords 为空（用户任务直接产生）→ 1.0
有探索记录（自主探索产生）→ 0.5
```

**dependencyScore（依赖关系）**：
```
parentCount = UnitRepository.findParentsOf(unitId).size()  // 反向 CONTAINS 入边数
score = min(parentCount / 5.0, 1.0)
```
被越多父级 Unit 引用（`CONTAINS`），说明越是被依赖的基础能力，价值越高。

### 2.3 计算结果

`valueScore` 范围 `[0.0, 1.0]`，其中：
- `≥ 0.7`：高价值，永久保留
- `0.3 ~ 0.7`：中价值，过期后可清理
- `< 0.3`：低价值，优先清理

## 3. Retention Rules（按来源保留天数）

| 来源类型 | 保留天数 | 配置键 | 说明 |
|----------|----------|--------|------|
| `user-task` | 365 天 | `retention-rules.user-task` | 用户直接执行的任务，最宝贵 |
| `autonomous-exploration` | 90 天 | `retention-rules.autonomous-exploration` | 自主探索产生，中等价值 |
| `failure-pattern` | 180 天 | `retention-rules.failure-pattern` | 失败模式用来避坑，保留更久 |

> v1.7 中来源类型由 Unit 推导：
> - `explorationRecords` 非空 → `autonomous-exploration`
> - `failureCount > 0`（或已有 `failureCauses`）→ `failure-pattern`
> - 其余 → `user-task`

**保留逻辑**：
```
实际保留天数 = retention-rules 中查表（无匹配则 90 天默认值）
ageInDays < retentionDays → 跳过清理（不管 valueScore 多低）
```

## 4. 清理决策流程

```
MemoryMaintenanceService.scheduledCleanup()
  │
  ├── 1. calculateUsageRate() → 占用率
  │     Unit 节点数（或 unit-registry 点数）占用率 < threshold → 跳过
  │
  ├── 2. unitRepository.findAll() → 获取所有 Unit 节点
  │     读取 successCount / failureCount / status / explorationRecords
  │
  ├── 3. 逐个 Unit 计算 valueScore：
  │
  │     for each unit:
  │       ├── status == ARCHIVED → 直接进入删除候选（§6 已逻辑删除，此处物理清理）
  │       ├── unitKind == MCP_TOOL → skip（MCP 工具失败只记录，永不清理）
  │       ├── resolveSourceType(unit) → 来源类型
  │       ├── retentionDays = retention-rules.get(sourceType, 90)
  │       ├── ageInDays < retentionDays → skip（保护期内）
  │       ├── protectedIds.contains(unitId) → skip（白名单保护）
  │       │
  │       ├── recencyScore = 1.0 - min(ageInDays / retentionDays, 1.0)
  │       ├── usageScore = min(successCount / 10.0, 1.0)
  │       ├── userProducedScore = explorationRecords 为空 ? 1.0 : 0.5
  │       ├── dependencyScore = min(findParentsOf(unitId).size() / 5.0, 1.0)
  │       │
  │       └── valueScore = w1*recency + w2*usage + w3*userProduced + w4*dependency
  │            valueScore < MIN_SCORE(0.3) → 加入删除候选
  │
  ├── 4. 按 valueScore 升序排列 → 取前 N 个（N = (占用率-target) * MAX_POINTS）
  │
  ├── 5. AI 审核清理摘要
  │     生成摘要: "将删除 {N} 条记忆（最低分 {minScore}，最高分 {maxScore}）"
  │     可选: LLM 审查摘要 → 标记异常高分删除 → 跳过
  │
  └── 6. 物理删除 Neo4j 节点
        unitStore.delete(unitId)  // 同时清理 Neo4j + Qdrant（对已 unindex 的重复删除幂等）
```

## 5. protectMemory 白名单工具

### 5.1 数据结构

`MemoryMaintenanceService` 维护一个 `ConcurrentHashMap<String, Long>` 白名单：

```java
private final Map<String, Long> protectedIds = new ConcurrentHashMap<>();
// key = unit UUID，value = 保护过期时间戳 (0 = 永久)
```

### 5.2 API

| 方法 | 说明 |
|------|------|
| `protectMemory(String unitId)` | 添加永久保护 |
| `protectMemory(String unitId, int days)` | 添加限期保护（N天） |
| `unprotectMemory(String unitId)` | 移除保护 |
| `isProtected(String unitId)` | 检查是否受保护（自动清理过期保护） |

### 5.3 集成

**清理步骤 3** 中增加 `protectedIds.contains(unitId) → skip`。

**ExplorationTool** 新增 `@Tool` 方法供 AI 调用：
```java
@Tool(description = "将重要记忆标记为永久保护，防止被自动清理删除。")
public String protectMemory(@ToolParam(description = "Unit ID") String unitId)
```

## 6. AI 审核清理摘要

### 6.1 设计

清理前生成摘要文本，可选调用本地 LLM 进行审查：

```
清理摘要:
  总记忆数: 4,523
  计划清理: 87 条 (1.9%)
  清理后占用率: 48.2% (目标: 50.0%)
  
  清理候选:
    [0.12] "尝试打开不存在的网页..." (autonomous-exploration, 82天)
    [0.18] "测试工具组合..." (autonomous-exploration, 78天)
    ...
    [0.29] "控制窗帘开关..." (user-task, 120天) ← 异常：用户任务价值低
```

AI 审核后可以标记某些条目跳过删除。

### 6.2 实现方式

```java
private String reviewCleanupSummary(List<CleanupCandidate> candidates) {
    String prompt = "审查以下记忆清理计划，标记你认为不应该删除的项：\n" + summary;
    String response = localChatClient.prompt().user(prompt).call().content();
    // 解析 AI 标记的保留项 → 从删除列表移除
}
```

## 7. Neo4j 清理与图关系处理

### 7.1 当前状态

v1.7 起清理对象就是 Neo4j `Unit` 节点（主存储），Qdrant `unit-registry` 只是检索入口，已在 §6 归档时 `unindex`。物理删除时 `UnitStore.delete()` 同时清理 Neo4j 与 Qdrant（幂等）。

### 7.2 清理时图关系处理

| 删除对象 | 图关系处理 |
|----------|------------|
| `status=ARCHIVED` 的 Unit | `UnitRepository.deleteById()` 删除节点（CONTAINS / DISABLES / FALLBACK 边随节点删除） |
| 被删除 Unit 引用的 FailureCause | 保留 FailureCause（独立对象，供其它 Unit 复用），不级联删除 |
| 被删除 Unit 的 CONTAINS 子节点 | 不级联删除子节点（子节点可被其它父级复用），仅断开关系 |

## 10. 关键决策记录

| 决策 | 内容 |
|------|------|
| 清理对象 | v1.7 起为 Neo4j `Unit` 节点（主存储），Qdrant `unit-registry` 仅检索入口 |
| 与 §6 分工 | §6 触发式逻辑删除（PLAN 失败 3 次归档），本系统定时式物理删除 |
| 清理执行时间 | 每日凌晨 4:00，业务低峰期 |
| 白名单存储 | 内存 `ConcurrentHashMap`（重启丢失，但通常清理在定时任务中自动补标记） |
| 评分计算时机 | 清理时实时计算（不预存 payload，避免写入放大） |
| valueScore 阈值 | 0.3（低于此值可清理），可在配置中调整 |
| AI 审核开关 | 默认关闭（避免额外 LLM 调用消耗），由 `ai-review-enabled` 控制 |
| 保护期优先 | `ageInDays < retentionDays` 优先级高于 `valueScore < 0.3`（保护期内绝对不删） |
| MCP 工具保护 | `unitKind == MCP_TOOL` 永不清理（§6 规定失败只记录不删除） |
