# 11 - 记忆价值评分系统

## 1. 概述

记忆系统的容量会随使用时间线性增长。简单的 `archived + stability<0.1` 清理策略过于粗糙——一条 90 天前被高频使用的黄金经验可能因一次失败被归档，稳定性降低后就被误删。

需要引入**多维价值评分算法**，综合评估每条 Episode 的保留价值，优先删除低价值数据。

---

## 2. 核心算法

### 2.1 价值评分公式

```
valueScore = w1 × recencyScore + w2 × usageScore + w3 × userProducedScore + w4 × dependencyScore
```

| 权重 | 配置键 | 默认值 | 含义 | 评分逻辑 |
|------|--------|--------|------|----------|
| w1 | `weights.recency` | 0.30 | 时间新鲜度 | `1.0 - min(ageInDays / retentionDays, 1.0)` |
| w2 | `weights.usage` | 0.30 | 使用频率 | `min(usageCount / 10.0, 1.0)`（10次封顶） |
| w3 | `weights.userProduced` | 0.25 | 用户直接产出 | `unitType == COMPOSITE 且 sourceType 为 user_task → 1.0；否则 0.5` |
| w4 | `weights.dependency` | 0.15 | 被依赖关系 | `min(parentCount / 5.0, 1.0)`（被5个引用封顶） |

### 2.2 评分细节

**recencyScore（新鲜度）**：
```
ageInDays = (now - episode.timestamp) / 86400000
retentionDays = 根据 sourceType 查 retention-rules（默认 90 天）
score = 1.0 - min(ageInDays / retentionDays, 1.0)
```
示例：10 天前的 `autonomous-exploration`（保留 90 天）→ `1.0 - 10/90 = 0.889`

**usageScore（使用频率）**：
```
score = min(episode.successCount / 10.0, 1.0)
```
示例：成功执行了 8 次 → `0.8`；成功执行了 15 次 → `1.0`（封顶）

**userProducedScore（来源价值）**：
```
episode.sourceType == "user_task" → 1.0
其他 → 0.5
```

**dependencyScore（依赖关系）**：
```
parentCount = UnitLearner 中统计被多少个 ATOMIC 引用
score = min(parentCount / 5.0, 1.0)
```

### 2.3 计算结果

`valueScore` 范围 `[0.0, 1.0]`，其中：
- `≥ 0.7`：高价值，永久保留
- `0.3 ~ 0.7`：中价值，过期后可清理
- `< 0.3`：低价值，优先清理

## 3. Retention Rules（按来源保留天数）

| 来源类型 | 保留天数 | 配置键 | 说明 |
|----------|----------|--------|------|
| `user-task` | 365 天 | `retention-rules.user-task` | 用户直接执行的任务，最宝贵 |
| `autonomous-exploration` | 90 天 | `retention-rules.autonomous-exploration` | 自主探索产生，中等价值 |
| `failure-pattern` | 180 天 | `retention-rules.failure-pattern` | 失败模式用来避坑，保留更久 |

**保留逻辑**：
```
实际保留天数 = retention-rules 中查表（无匹配则 90 天默认值）
ageInDays < retentionDays → 跳过清理（不管 valueScore 多低）
```

## 4. 清理决策流程

```
MemoryMaintenanceService.scheduledCleanup()
  │
  ├── 1. calculateUsageRate() → 占用率
  │     占用率 < threshold → 跳过
  │
  ├── 2. scrollEpisodes() → 获取所有 Episode（含 payload）
  │     需要 payload 来读取 sourceType / successCount / timestamp
  │
  ├── 3. 逐个 Episode 计算 valueScore：
  │
  │     for each episode:
  │       ├── ageInDays = (now - timestamp) / 86400000
  │       ├── retentionDays = retention-rules.get(sourceType, 90)
  │       ├── ageInDays < retentionDays → skip（保护期内）
  │       ├── protectedIds.contains(id) → skip（白名单保护）
  │       │
  │       ├── recencyScore = 1.0 - min(ageInDays / retentionDays, 1.0)
  │       ├── usageScore = min(successCount / 10.0, 1.0)
  │       ├── userProducedScore = (sourceType=="user_task") ? 1.0 : 0.5
  │       ├── dependencyScore = min(parentCount / 5.0, 1.0)
  │       │
  │       └── valueScore = w1*recency + w2*usage + w3*userProduced + w4*dependency
  │            valueScore < MIN_SCORE(0.3) → 加入删除候选
  │
  ├── 4. 按 valueScore 升序排列 → 取前 N 个（N = (占用率-target) * MAX_POINTS）
  │
  ├── 5. AI 审核清理摘要
  │     生成摘要: "将删除 {N} 条记忆（最低分 {minScore}，最高分 {maxScore}）"
  │     可选: LLM 审查摘要 → 标记异常高分删除 → 跳过
  │
  └── 6. 批量删除 + Neo4j 同步清理关联节点
```

## 5. protectMemory 白名单工具

### 5.1 数据结构

`MemoryMaintenanceService` 维护一个 `ConcurrentHashMap<String, Long>` 白名单：

```java
private final Map<String, Long> protectedIds = new ConcurrentHashMap<>();
// key = episode UUID, value = 保护过期时间戳 (0 = 永久)
```

### 5.2 API

| 方法 | 说明 |
|------|------|
| `protectMemory(String episodeId)` | 添加永久保护 |
| `protectMemory(String episodeId, int days)` | 添加限期保护（N天） |
| `unprotectMemory(String episodeId)` | 移除保护 |
| `isProtected(String episodeId)` | 检查是否受保护（自动清理过期保护） |

### 5.3 集成

**清理步骤 3** 中增加 `protectedIds.contains(id) → skip`。

**ExplorationTool** 新增 `@Tool` 方法供 AI 调用：
```java
@Tool(description = "将重要记忆标记为永久保护，防止被自动清理删除。")
public String protectMemory(@ToolParam(description = "Episode ID") String episodeId)
```

## 6. AI 审核清理摘要

### 6.1 设计

清理前生成摘要文本，可选调用本地 LLM 进行审查：

```
清理摘要:
  总记忆数: 4,523
  计划清理: 87 条 (1.9%)
  清理后占用率: 48.2% (目标: 50.0%)
  
  清理候选:
    [0.12] "尝试打开不存在的网页..." (autonomous_exploration, 82天)
    [0.18] "测试工具组合..." (autonomous_exploration, 78天)
    ...
    [0.29] "控制窗帘开关..." (user_task, 120天) ← 异常：用户任务价值低
```

AI 审核后可以标记某些条目跳过删除。

```java

    String response = localChatClient.prompt().user(prompt).call().content();
```

## 7. Neo4j 同步清理

### 7.1 当前状态

清理仅操作 Qdrant，Neo4j 中的 FailurePattern / Rule 节点保持不变，会造成数据不一致。

### 7.2 设计方案

Qdrant Episode 删除后，同步处理 Neo4j：

| 删除的 Episode | Neo4j 处理 |
|----------------|------------|
| 来源为 FailurePattern | `FailurePatternRepository.deleteById()` |
| 关联的 Rule | 检查关联 Episode 是否全被删 → 是则 `confidence *= 0.5`，低于 0.3 则删除 |
| KnowledgeSnippet 的 DERIVED_FROM 关系 | 断开关系，不删除 Snippet（知识可独立存在） |

## 9. 配置参考

```yaml
myhelper:
  memory-maintenance:
    enabled: true
    cron: 0 0 4 * * ?
    threshold: 0.7
    target: 0.5
    ai-review-enabled: false          # 是否启用 AI 审核（false=直接删）
    ai-review-model: qwen2.5:3b       # AI 审核模型
    weights:
      recency: 0.3
      usage: 0.3
      user-produced: 0.25
      dependency: 0.15
    retention-rules:
      user-task: 365
      autonomous-exploration: 90
      failure-pattern: 180
      default: 90                     # 未匹配来源的默认保留天数
```

## 10. 关键决策记录

| 决策 | 内容 |
|------|------|
| 清理执行时间 | 每日凌晨 4:00，业务低峰期 |
| 白名单存储 | 内存 `ConcurrentHashMap`（重启丢失，但通常清理在定时任务中自动补标记） |
| 评分计算时机 | 清理时实时计算（不预存 Qdrant payload，避免写入放大） |
| valueScore 阈值 | 0.3（低于此值可清理），可在配置中调整 |
| AI 审核开关 | 默认关闭（避免额外 LLM 调用消耗），由 `ai-review-enabled` 控制 |
| 保护期优先 | `ageInDays < retentionDays` 优先级高于 `valueScore < 0.3`（保护期内绝对不删） |
