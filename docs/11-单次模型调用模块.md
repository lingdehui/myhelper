## 当前职责

每次调用只请求一次指定的 LLM；根据执行模式，直接返回模型响应，或者执行响应中的工具调用后返回。下一轮由上层准备入参并发起。本模块不承担业务门禁、任务规划、世界模型查询或技能固化。

## 输入与输出

- 构造参数：模型解析函数 `Function<String, ChatModel>`、已注册的 `ToolCallback` 集合。
- `Request.modelRef`：本轮模型引用，交给模型解析函数获取已配置的模型。
- `Request.messages`：本轮消息列表，包括当前文本、必要历史和上一轮工具结果或失败反馈。
- `Request.toolNames`：本轮可用工具名，不能为空引用；不使用工具时传空列表。
- `Request.mode`：`CALL_ONLY` 或 `CALL_AND_EXECUTE`。
- `Result.response`：保留文本和结构化工具调用的模型原始响应。
- `Result.messages`：加入模型响应及已执行工具结果后的消息列表。
- `Result.executionAttempted`：是否进入工具执行阶段，不代表工具全部成功。

`CALL_ONLY` 返回的工具调用尚未执行；上层需处理对应结果，再把完整消息交给下一轮模型。工具执行异常转换为失败文本，模型调用及协议错误抛给调用方；本模块不自动重试。

## 实现与版本边界

面向项目当前的 Java 25、Spring AI 2.0.0-M3。通过 `internalToolExecutionEnabled(false)` 禁止模型内部自动工具执行，再按模式显式调用 `DefaultToolCallingManager.executeToolCalls`，执行完成后直接返回。

在执行任何工具前检查整个响应的工具名集合，拒绝本轮未提供的工具。要求模型只返回一个候选响应。代码已在主要语句上方逐行添加中文注释。

## 外层循环与能力复用接入（2026-11-10，已实现）

当前实现保持单次边界；上层 AgentOrchestrator 通过 AgentCallerPlanner 调用本类。规划适配器提供允许的实际工具合同、任务目标、参数、入口候选及历史执行反馈，模型以 submit_plan 提交计划，TASK 步骤递归求解。成功案例和世界上下文服务尚未接入。具体依赖决定并发，不按工具注册时的固定标志决定。

[固化检索模块](19-固化检索与缓存开发文档.md)在根入口按用户目标召回一次；每次模型返回 PLAN 后，再根据 LLM 给出的总体任务与子任务重新检索数据库，匹配整条/子节点并保存本计划绑定。递归子任务和下一轮不重复入口检索。可直接执行的能力无需额外调用 AgentCaller；缓存命中仍需参数及门禁检查。

已增加 `call(Request, Collection<ToolCallback> scopedTools)`：工具仅合并到本次调用，不修改全局注册表，重名拒绝；旧 call(Request) 委托此重载。增加 toolDefinitions(toolNames)，让规划适配器读取普通工具合同。两种模式都在返回/执行前校验请求 ID 非空且不重复、工具名属于本轮允许集合，补齐原 CALL_ONLY 早返回的缺口。

编排器采用 CALL_ONLY，由 AgentCallerPlanner 解析原生 toolCalls 中 submit_plan/finish_task 的 JSON arguments，再由外层执行工具或递归子任务；不会调用控制工具回调同步递归。下一轮重建任务、计划和执行反馈快照，不把未配对工具请求塞入历史。共享执行关系见[13](13-执行链路记录开发文档.md)，执行器见[14](14-工具与能力执行开发文档.md)。

Result 原有三个字段保持不变，未增加统一用量 DTO；运行上下文与结构化 Outcome 放在外层。CALL_AND_EXECUTE 仍用框架管理器执行，未迁移到新调度器。新增测试覆盖 CALL_ONLY 拒绝未允许工具及重复调用 ID，另有循环到真实 ToolCallback 的替身模型集成检查。实际测试运行记录见接续文档；没有真实 LLM 联调，未改环境配置。
