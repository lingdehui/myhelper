## A. 提高缓存匹配精确度

### 问题

L1/L2 使用 `normalizeKey(userInput)`（去数字、空白、标点、小写），不同意图的指令只要字符骨架相似就会错误命中同一个 Episode（例如"打开卧室灯" vs "打开客厅空调"）。

### A1. 语义哈希（Semantic Hash）替代纯文本归一化 — 难度 ⭐⭐

**思路**：利用已有的本地 Embedding 模型（`nomic-embed-text`），对用户输入做向量化 → 二值化（每一维 > 0 置 1，否则 0）→ 作为缓存 key。

**为什么不用直接向量检索？**
L1 内存缓存需要 O(1) 精确命中，不是每次做 KNN。二值化相当于 Cosine LSH 的特例——相似向量以高概率落入同一桶，不同意图落入不同桶。

**实现步骤**：

**Step 1 — `AiResponseUtils` 新增 `semanticHashKey()`**：

```java
public static String semanticHashKey(float[] embedding) {
    if (embedding == null || embedding.length == 0) return "";
    BitSet bitSet = new BitSet(embedding.length);
    for (int i = 0; i < embedding.length; i++) {
        if (embedding[i] > 0) bitSet.set(i);
    }
    return Hex.encodeHexString(bitSet.toByteArray());
}
```

nomic-embed-text 输出已是归一化向量，直接取符号位即可，无需额外 LSH 库。

**Step 2 — `ToolPlanner.plan()` 懒加载 Embedding**：

```java
String textKey = AiResponseUtils.normalizeKey(userInput);

// L1 先查文本 key（免费，O(1)）
PlanResult cached = cache.get(textKey);
if (cached != null) return cached;

// 未命中 → 触发 Embedding → 语义 key 再查
float[] emb = embeddingService.embed(userInput);
String semanticKey = AiResponseUtils.semanticHashKey(emb);
cached = cache.get(semanticKey);
if (cached != null) {
    cache.put(textKey, cached); // 回填文本 key 加速后续
    return cached;
}

// 仍未命中 → L2/L3
```

**Step 3 — 回写缓存时双写**：

```java
cache.put(semanticKey, planResult);
cache.put(textKey, planResult);
```

**改动文件**：`AiResponseUtils.java`、`ToolPlanner.java`  
**依赖**：`EmbeddingService`（已存在）、`BitSet`（JDK 内置）、`Hex`（Apache Commons Codec 已有）

### A2. Episode 最大复用次数与时效性衰减 — 难度 ⭐⭐

防止某个 Episode 因多次成功被无限复用，即使能力已过时。

**Step 1 — `Episode` 新增字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `maxUsageCount` | int | 最大允许复用次数，默认 50 |
| `currentUsageCount` | int | 已复用次数 |
| `ttlSeconds` | long | 存活周期（秒），默认 604800（7天） |

**Step 2 — 缓存命中时检查**：

```java
PlanResult cached = cache.get(key);
if (cached != null && cached.episode != null) {
    Episode ep = cached.episode;
    // 时效检查
    if (isExpired(ep)) {
        cache.remove(key);
        episodeCacheService.archiveEpisode(ep.getId());
        return planViaL2OrL3(...);
    }
    // 次数检查
    if (ep.getCurrentUsageCount() >= ep.getMaxUsageCount()) {
        ep.setCanScript(false);
        cache.remove(key);
    }
    episodeCacheService.incrementUsageCount(ep.getId());
}
```

**Step 3 — 配置化**（`myhelper-tool.yml`）：

```yaml
myhelper:
  tool:
    cache:
      semantic-key-enabled: true
      episode-max-usage: 50
      episode-ttl-hours: 168
```

**改动文件**：`Episode.java`、`EpisodeCacheService.java`、`ToolPlanner.java`

## B. 建立经验质量控制回路

### B1. 置信度评估 — AI 反思带确定性分数 — 难度 ⭐

当前 `ReflectService` 只要求 AI 返回成功/失败教训文本。需要让 AI 同时返回 `confidence`（0.0~1.0），低于阈值的反思不写入长期记忆。

**Step 1 — 修改 Prompt 模板**（`prompts/reflect-success.txt`、`prompts/reflect-failure.txt`）：

```
输出一个严格的 JSON 对象：
{
  "lesson": "成功经验的简洁总结，不超过30字",
  "confidence": 0.0~1.0 之间的浮点数，表示你对该经验通用性和正确性的把握
}
```

**Step 2 — `ReflectService` 门控逻辑**：

```java
ReflectResult result = parseReflectOutput(aiOutput);
if (result.confidence() < 0.7) {
    log.info("反思置信度过低({})，仅记录短期日志: {}", result.confidence(), result.lesson());
    shortTermLog.add(result); // 环形缓冲区，不写入 Episode
    return;
}
episode.setSuccessLesson(result.lesson());
```

**Step 3 — 配置**：

```yaml
myhelper:
  tool:
    reflect:
      min-confidence: 0.7
```

**改动文件**：`ReflectService.java`、`prompts/reflect-*.txt`  
**依赖**：无，纯 Prompt + 解析改造

### B2. 人工反馈机制 — "有用/没用"标注 — 难度 ⭐⭐

用户可对 AI 最近使用的经验进行即时反馈，校准经验可信度。

**Step 1 — 反馈命令识别**（`DialogStateMachine`）：

```java
// 关键词匹配
if (userInput.contains("有用") || userInput.contains("没用") || userInput.contains("不好")) {
    boolean useful = !(userInput.contains("没用") || userInput.contains("不好"));
    feedbackService.recordFeedback(useful);
    ttsService.speakAsync("收到反馈");
    return; // 短路，不进入正常管线
}
```

**Step 2 — `FeedbackService`**（新建 `service/FeedbackService.java`）：

```java
@Service
public class FeedbackService {
    private final EpisodeCacheService episodeCacheService;
    private String lastUsedEpisodeId; // 由 TurnProcessor 设置

    public void recordFeedback(boolean useful) {
        if (lastUsedEpisodeId == null) return;
        episodeCacheService.addFeedback(lastUsedEpisodeId, useful ? 1 : -1);
        lastUsedEpisodeId = null;
    }
    public void setLastUsedEpisode(String id) { this.lastUsedEpisodeId = id; }
}
```

**Step 3 — `Episode` 新增反馈字段**：

| 字段 | 类型 | 说明 |
|------|------|------|
| `feedbackScore` | double | 累计分数（+1=有用, -1=没用） |
| `feedbackCount` | int | 反馈总次数 |

**Step 4 — 负反馈惩罚**：

```java
public void addFeedback(String id, int delta) {
    Episode ep = findById(id);
    ep.setFeedbackScore(ep.getFeedbackScore() + delta);
    ep.setFeedbackCount(ep.getFeedbackCount() + 1);
    if (ep.getFeedbackScore() < -3) {
        ep.setStability(0.1);
        ep.setArchived(true);
    }
    save(ep);
}
```

**Step 5 — `TurnProcessor` 传递 episodeId**：

```java
if (planResult.isFromCache() && planResult.episode() != null) {
    feedbackService.setLastUsedEpisode(planResult.episode().getId());
}
```

**改动文件**：`FeedbackService.java`（新建）、`Episode.java`、`EpisodeCacheService.java`、`TurnProcessor.java`、`DialogStateMachine.java`

### B3. 反馈数据校准自动置信度 — 难度 ⭐⭐⭐

积累足够反馈后，对比 AI 自评 `confidence` 与人类反馈的差异，动态调整 `min-confidence` 阈值。

**方案**：在 `ReflectService` 中维护 `Map<String, Double>` 记录各意图类别对应的阈值偏移。当反馈为"没用"但 AI 自评 confidence 很高 → 提升该类别阈值，迫使后续类似反思更严格。

**改动文件**：`ReflectService.java`  
**依赖**：B1 + B2 已实现 + 足够反馈数据积累  
**优先级**：低（可后期迭代）

## 实施优先级建议

| 优先级 | 模块 | 理由 |
|:------:|------|------|
| **P0** | A1 语义哈希 | 直接解决缓存错配问题，改动量中等，依赖就绪 |
| **P1** | B1 置信度门控 | 纯 Prompt 改造，改动量最小，即时生效 |
| **P1** | A2 复用次数/TTL | 防止过期经验污染，但需要 Episode 字段扩展 |
| **P2** | B2 人工反馈 | 需要新建 Service + 多处联动，但用户体验提升大 |
| **P3** | B3 自动校准 | 依赖数据积累，可后期迭代 |

## 关键决策记录

| 决策 | 内容 |
|------|------|
| LSH 方案 | 选择二值化（符号位）而非完整 LSH 库，nomic-embed-text 归一化向量天然适配 |
| Embedding 策略 | 懒加载：先 textKey 查（免费）→ 未命中再 embed → semanticKey 查 |
| 反馈识别 | 关键词匹配（非 AI 判断），简单可靠，减少误判 |
| 低置信度处理 | 不入 Episode，写入短期环形日志（可人工查看但不参与缓存匹配） |
| 缓存双写 | semanticKey + textKey 同时写入，保证兼容性和查询效率 |
