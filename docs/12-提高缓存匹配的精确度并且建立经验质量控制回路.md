## A. 提高缓存匹配精确度

### 问题

旧版 L1/L2 使用 `normalizeKey(userInput)`（去数字、空白、标点、小写），不同意图的指令只要字符骨架相似就会错误命中同一个 Episode（例如"打开卧室灯" vs "打开客厅空调"）。

v1.7 起，记忆统一为 **Unit**，语义匹配由 `matchText` 字段 + Qdrant `unit-registry` 向量检索完成，从根源上解决字符骨架错配问题。

### A1. matchText 向量化语义检索替代纯文本归一化 — 难度 ⭐⭐

**思路**：Unit 统一通过 `matchText` 字段做语义匹配。`matchText` 是匹配语言字段，embedding **只对此字段生成向量**，默认取 `goal`，区分度不足时由 AI 重写 `goal` 加区别词。检索走 Qdrant `unit-registry` 集合，命中后回 Neo4j 补全 Unit。

**为什么不是纯文本归一化？**
`normalizeKey(userInput)` 会把不同意图但字符骨架相似的指令错配。向量检索按语义相似度召回，从根源上避免错配。

**为什么不是 LSH 二值化？**
旧方案（A1 原案）用符号位二值化作 O(1) 精确命中。但 v1.7 的统一 Unit 已落地 Qdrant 向量检索入口（`unit-registry`），直接复用 `UnitStore.findSimilar(query, topK)` 更简洁，无需额外维护 LSH 桶。

**实现要点**：

**Step 1 — `Unit.matchText` 字段**（`Unit.java`）：

```java
/**
 * matchText：匹配语言字段，embedding 只对此字段生成向量。
 * 默认取 goal；goal 为空时退回 description；区分度不足时由 AI 重写 goal 加区别词。
 */
public static String buildMatchText(String goal, String description) {
    if (goal != null && !goal.isBlank()) return goal;
    if (description != null && !description.isBlank()) return description;
    return "";
}
```

**Step 2 — 写入：embedding 只对 `matchText` 生成向量**（`UnitStore.indexToQdrant`）：

```java

List<Float> vector = embeddingService.embed(matchText);  // 只对 matchText 生成
payload.put("matchText", matchText);
payload.put("unitId", node.getUnitId());
payload.put("status", node.getStatus());
```

**Step 3 — 检索：`UnitStore.findSimilar(query, topK)`**：


### A2. Unit 稳定度 + 失败归档替代复用次数/TTL — 难度 ⭐⭐

防止某个 Unit 因多次成功被无限复用，即使能力已过时。

v1.7 用 `stability` + §6 失败归档 + §7.2 脚本化升级取代旧的 `maxUsageCount` / `ttlSeconds`：

- `stability = successCount / (successCount + failureCount)`，随环境变化自然衰退。
- 同一 PLAN 原因累计失败 3 次 → `status=ARCHIVED` + `UnitStore.unindex()` + 给父级建 `DISABLES` 边（§6）。
- 成功 ≥5 且 `stability > 0.9` → 升级为 `scriptable`（§7.2 条件3，`UnitStore.tryUpgradeScriptable`）。

**字段映射（旧 Episode → Unit）**：

| 旧 Episode 字段 | v1.7 Unit 替代 |
|------|------|
| `maxUsageCount` / `currentUsageCount` | 无（由 `stability` + `failureCount` 替代） |
| `ttlSeconds` | 无（由 §6 失败归档 + 价值评分定时清理替代） |

**改动文件**：`Unit.java`、`UnitFailureService.java`、`UnitStore.java`

## B. 建立经验质量控制回路

### B1. 置信度评估 — AI 反思带确定性分数 — 难度 ⭐

当前 `ReflectService` 要求 AI 返回成功/失败教训文本 + 归因（`isPlanIssue`）。可进一步让 AI 同时返回 `confidence`（0.0~1.0），低于阈值的反思不写入长期 Unit。

**Step 1 — 修改 Prompt 模板**（`prompts/reflect-success.txt`、`prompts/reflect-failure.txt`）：

```
输出一个严格的 JSON 对象：
{
  "lesson": "成功经验的简洁总结，不超过30字",
  "confidence": 0.0~1.0 之间的浮点数，表示你对该经验通用性和正确性的把握
}
```

**Step 2 — `ReflectService` 门控逻辑**：

```java
ReflectResult result = parseReflectOutput(aiOutput);
if (result.confidence() < 0.7) {
    log.info("反思置信度过低({})，仅记录短期日志: {}", result.confidence(), result.lesson());
    shortTermLog.add(result); // 环形缓冲区，不写入 Unit
    return;
}
// v1.7：成功经验写 Unit.notes（或作为新 Unit 的 goal），失败经验走 UnitFailureService.recordFailure
```

**Step 3 — 配置**：

```yaml
myhelper:
  tool:
    reflect:
      min-confidence: 0.7
```

**改动文件**：`ReflectService.java`、`prompts/reflect-*.txt`  
**依赖**：无，纯 Prompt + 解析改造

### B2. 人工反馈机制 — "有用/没用"标注 — 难度 ⭐⭐

用户可对 AI 最近使用的 Unit 进行即时反馈，校准经验可信度。

**Step 1 — 反馈命令识别**（`DialogStateMachine`）：

```java
// 关键词匹配
if (userInput.contains("有用") || userInput.contains("没用") || userInput.contains("不好")) {
    boolean useful = !(userInput.contains("没用") || userInput.contains("不好"));
    feedbackService.recordFeedback(useful);
    ttsService.speakAsync("收到反馈");
    return; // 短路，不进入正常管线
}
```

**Step 2 — `FeedbackService`**（新建 `service/FeedbackService.java`）：

```java
@Service
public class FeedbackService {
    private final UnitStore unitStore;
    private String lastUsedUnitId; // 由 TurnProcessor 设置

    public void recordFeedback(boolean useful) {
        if (lastUsedUnitId == null) return;
        if (useful) {
            unitStore.incrementSuccess(lastUsedUnitId);
        } else {
            // 负反馈 → 记录为一次 PLAN 失败（走 §6 阈值归档）
            unitStore.findByToolName(lastUsedUnitId); // 或按 unitId 定位
        }
        lastUsedUnitId = null;
    }
    public void setLastUsedUnit(String id) { this.lastUsedUnitId = id; }
}
```

> 注：负反馈的精确语义（直接失败计数 vs 独立 feedback 字段）待实现时对齐 §6 失败处理口径。

**Step 3 — `TurnProcessor` 传递 unitId**：

```java
if (planResult.isFromCache() && planResult.unitId() != null) {
    feedbackService.setLastUsedUnit(planResult.unitId());
}
```

**改动文件**：`FeedbackService.java`（新建）、`UnitStore.java`、`TurnProcessor.java`、`DialogStateMachine.java`

### B3. 反馈数据校准自动置信度 — 难度 ⭐⭐⭐

积累足够反馈后，对比 AI 自评 `confidence` 与人类反馈的差异，动态调整 `min-confidence` 阈值。

**方案**：在 `ReflectService` 中维护 `Map<String, Double>` 记录各意图类别对应的阈值偏移。当反馈为"没用"但 AI 自评 confidence 很高 → 提升该类别阈值，迫使后续类似反思更严格。

**改动文件**：`ReflectService.java`  
**依赖**：B1 + B2 已实现 + 足够反馈数据积累  
**优先级**：低（可后期迭代）
