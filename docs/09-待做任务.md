## P1 — 本周待办

### #3 Episode 过期淘汰 🟡

**问题**：Episode 没有时间维度的淘汰机制。旧的 Episode 即使环境变了也可能被匹配到。

**方案**：

| 时间 | 操作 |
|------|------|
| ≥90天未检索使用 | ACTIVE → archived=true，降低 stability |
| ≥180天 | 删除或移入冷存储 |
| archived 被再次匹配并成功 | 重置为 ACTIVE + 更新 last_used |

**改动点**：
- `Episode` 新增 `lastUsedAt` 字段
- `EpisodeCacheService` 新增 `@Scheduled` 淘汰任务（每周凌晨）
- `findSimilarEpisode()` 命中时更新 `lastUsedAt`

### #5 生成工具监控淘汰 🔵

**问题**：`GeneratedToolRegistry` 生成工具后没有质量监控。

**方案**：记录每个生成工具的使用次数和成功率；成功率 < 50% → 自动禁用。

### #13 KnowledgeSnippet 持久化 🔵

**问题**：`ExplorationExecutor.saveKnowledgeSnippet()` 只有 TODO 注释，知识片段生成后只打印日志，未实际持久化到 Qdrant/Neo4j。

**方案**：创建 `KnowledgeSnippetService`，将 `KnowledgeSnippet` 存入 Qdrant `knowledge-snippets` collection + Neo4j `KnowledgeSnippet` 节点。供后续检索复用。

### #14 探索上下文增强 🔵

**问题**：`AutonomousExplorationService.buildContext()` 中 `{unsolved_questions}` 和 `{tool_list_with_usage}` 为硬编码占位。

**方案**：
- `unsolved_questions`：扫描近7天所有 FAILED Episode 的 failureLesson，聚合为未解决问题
- `tool_list_with_usage`：统计工具调用频率，传入真实工具列表和使用计数
