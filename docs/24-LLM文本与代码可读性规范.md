# LLM 文本与代码可读性规范

更新：2026-11-11。以下为用户明确要求，适用于所有模块及任务窗口。它约束代码写法，不扩大任何模块的实现范围。

## 1. 已确认规则

统一管理给 LLM 的固定文本；不使用 Lambda；根据可读性选择合适的控制结构，不限定只用 if 和 for。同一个状态或类型的多个分支优先使用 switch，允许 `case ... ->`。`value -> expression` 和 `() -> expression` 才是这里要移除的 Lambda 写法。

集合操作优先清楚的循环和提前返回。异步或框架接口仍需回调时，使用明确的接口实现；复杂回调提取为有业务名称的方法，避免用大量匿名类嵌套替代原来的 Lambda 嵌套。不要仅为了隐藏 Lambda 改写为难以追踪的方法引用。

字段注释放在字段声明上方；流程注释说明目的、边界和失败含义。重构不得改变分支条件、执行顺序、返回结构、异常信息、只读集合、空值处理、并发时机、超时、取消或补偿语义。

## 2. 固定文本的唯一维护入口

实现：[LlmTexts](../src/main/java/com/example/myhelper/llm/LlmTexts.java)。该类只保存文本，不调用模型、不解析业务数据、不负责模型路由。

| 文本来源 | 维护方式 |
| --- | --- |
| 系统提示、固定任务指令 | 在 LlmTexts 定义常量或固定模板 |
| 项目自有工具的名称、说明、JSON Schema | 在 LlmTexts 定义，构造 ToolDefinition 时引用 |
| 项目在执行链路中生成的固定失败反馈 | 在 LlmTexts 定义完整文本或前后缀，动态原因仍由执行结果提供 |
| 用户原始问题、目标与参数 | 作为调用入参传递，不复制成常量 |
| 数据库实体、候选能力、历史实际结果 | 按当前数据合同动态读取与序列化 |
| 外部注册工具的合同和实际返回值 | 以注入的工具定义和执行结果为准 |
| 配置诊断、数据库协议、内部日志 | 不因包含字符串就成为提示词；若以后设计为固定模型反馈，维护其模板时纳入 LlmTexts |

当前 AgentCallerPlanner 从该类取得系统提示、submit_plan/finish_task 工具合同及输入包装字段；AgentCaller、TaskPlan、AgentOrchestrator、SpringToolExecutor 和 capability 读取相应固定反馈。JSON 对象字段、枚举和实体结构仍是各自的数据合同，不把业务模型搬进文本类。

旧 `src/main/resources/skills/*.txt` 为保留资源，当前生产源码没有加载这些技能文本的实现。本次不激活或删除这些资源。以后接入时，项目维护的固定提示模板仍须归入统一入口，技能实例内容按动态数据处理。

## 3. 开发方式

新增模型交互时先区分固定模板与运行数据；在 LlmTexts 增加有用途说明的常量，再由所属模块组织消息。提示词、工具说明和 Schema 修改会影响模型合同，需要同时核对解析与校验端。

普通集合筛选写为直接循环；多个枚举分支使用 switch。例如：

```java
switch (decision.kind()) {
    case PLAN -> executePlan();
    case COMPLETE -> verifyResult();
    case NEEDS_INPUT -> requestInput();
}
```

这是语法示意，省略了实际方法的参数和返回值；箭头为 switch 分支符号。异步逻辑则保留 CompletableFuture/CompletionStage 完成后接续的关系，显式回调只表达接续点，较长的业务处理提取到普通方法。

Neo4j 的事务接口继续使用驱动托管回调，不把事务体挪到回调外。资源锁继续按稳定顺序获取，保持去重与释放规则。原先 allOf 完成后才读取结果的位置，不提前调用 join 等待未完成任务。
