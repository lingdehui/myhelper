# 工具管理与隔离运行设计

> 共同开发规则见 [24-LLM 文本与代码可读性规范](../../24-LLM文本与代码可读性规范.md)。

2026-11-16。工具来源和按范围配置的先验已有代码与 Spring 装配入口，见第 6 节。工具自生成、动态加载、故障隔离、固化技能工具入口和公共变量仍为设计。世界模型沿用既有字段。

## 1. 模块边界

建议在现有应用内增加 `tools` 逻辑模块。应用进程负责工具目录、版本选择、变量和调用代理。生成工具的构建与执行各自在受限进程内进行，随应用部署即可。任务拆分、DAG 调度及业务验收继续使用现有编排与门禁接口。

| 对外入口（建议） | 职责 |
| --- | --- |
| `ToolDirectory.list(context)` / `resolve(ref, context)` | 返回调用方可用的工具合同或确定版本。记录来源、输入输出、版本、发布状态和运行路由 |
| `ToolInvoker.invoke(ref, args, context)` | 执行已解析的工具。入口校验权限、合同和时限，统一资源协调，返回结构化结果、实际版本、调用编号和副作用状态 |
| `ToolVariables.read(keys, context)` / `update(changes, context)` | 统一管理共享变量的定义、作用域、权限及带版本的读写 |
| 候选生成与发布入口 | 接收能力缺口，管理生成、构建、验证、审核、启用和回退。发布权限独立于调用权限 |

目录使用稳定的 `toolId` 和不可变 `toolVersion`，外部工具的稳定身份包含接入实例，避免两个 MCP 服务的同名工具互相覆盖。模型可见名称由目录快照映射到具体版本。生成制品的摘要和依赖清单由该版本的发布记录管理。外部接入需核对实例版本或合同指纹，合同发生变化时重新验证并登记版本。`EntityRef(id, revision)` 仍定位世界模型定义修订。工具目录维护 Unit 与执行版本的对应关系，源码、进程状态、变量值、先验参数均由工具模块管理。既有世界模型合同、统计和链路位置照常使用。 [统一世界模型](../world/09-统一世界模型.md)

## 2. 工具来源与固化技能

| 来源 | 世界模型表示 | 运行方式 |
| --- | --- | --- |
| 项目已审查的本地工具 | `TOOL` | 现有 `ToolCallback` 适配 |
| MCP 基础工具 | `MCP_TOOL` | 由受信 MCP 适配器按配置的实例、合同和权限调用 |
| Home Assistant（HA）工具 | `TOOL`。经 MCP 接入的工具使用 `MCP_TOOL` | 由受信适配器调用指定实例。设备实体继续使用既有 `DEVICE` 类型 |
| 生成的原子工具 | 发布后为 `TOOL` | 按指定版本送入受限运行进程 |
| 已发布的固化技能 | 复用既有 `PLAN_STEP` 的 ID 和修订 | 目录提供可调用工具合同，调用时交回同一个异步 DAG 执行器，传入父运行上下文和预算 |

每份已发布、具有确定输入输出合同且可执行的技能，都可以通过统一入口按引用调用，也可以由现有固化检索直接命中。目录项从发布定义按需生成，复用同一份 Unit、证据和统计；固化流程负责审核发布，`CapabilityLookup` 负责语义检索，目录负责精确查找与调用。组合步骤固定所引用工具的版本，组合调用继续受递归、预算和门禁约束。展开组合前释放启动阶段占用的工作名额，避免父步骤占着工作名额等待子步骤。旧 `skills/*.txt` 在迁移时先整理成有合同且经过验收的能力定义。 [技能固化](../skill/16-技能固化开发文档.md) · [固化检索](../capability/19-固化检索与缓存开发文档.md)

## 3. 接入现有接口

- `AgentCallerPlanner` 从目录快照取得本轮 `availableTools`。模型仍通过现有规划工具提交计划。接收计划时，宿主按模型看到的目录快照把 `TaskPlan.Step.toolName` 绑定到确定工具版本，执行前复查停用、门禁和截止时间。固化计划保存子工具的确定版本。历史计划若只能解析名称，须经显式核对和绑定后再启用。 [AgentCallerPlanner](../../../src/main/java/com/example/myhelper/orchestration/AgentCallerPlanner.java) · [TaskPlan](../../../src/main/java/com/example/myhelper/orchestration/TaskPlan.java)
- `AgentOrchestrator.ActionExecutor` 是原子工具的适配点，复用现有按参数解析的资源锁、执行链路和 `Checks.allow/verify`。组合技能通过编排的异步入口接入，沿用 `TaskPlan` 的依赖和参数绑定。工具结果须保留结构化状态。`SpringToolExecutor` 当前把回调正常返回标为成功，所以隔离运行结果需要在执行适配层显式映射。 [AgentOrchestrator](../../../src/main/java/com/example/myhelper/orchestration/AgentOrchestrator.java) · [SpringToolExecutor](../../../src/main/java/com/example/myhelper/orchestration/SpringToolExecutor.java)
- `AgentCaller` 的构造期工具表为固定快照，请求级工具只在当轮生效。首版新工具供编排和其他模块经统一调用入口使用。`CALL_AND_EXECUTE` 仍走现有框架执行路径，统一接入同一门禁、资源协调和结果映射后才开放新工具。 [AgentCaller](../../../src/main/java/com/example/myhelper/agent/AgentCaller.java) · [单次调用](../agent/11-单次模型调用模块.md)

## 4. 生成、动态加载与故障隔离

历史 `docs/08` 描述重启扫描，较后的桌面原稿和 `origin/main@53dacc7` 中的 `GeneratedToolRegistry` 已能用 `URLClassLoader` 即时加载。旧实现通过 `Class.forName` 在主 JVM 初始化生成类，重启兜底也会把源码纳入主应用。新设计沿用异步生成、有限修订和统一注册，应用只加载可信的合同元数据和代理。 [历史工具生成设计](../../legacy/08-工具自生成与动态加载.md)

1. 编排或探索提供明确的能力缺口、输入输出合同、权限需求和验收用例。先查已有工具和已固化技能。确有缺口时异步生成候选 Java 类，固定生成提示与项目自有工具文本沿用 `LlmTexts` 规则。
2. 在独立受限构建进程里编译和测试。工具 SDK 和批准的固定版本依赖组成构建 classpath，构建过程关闭额外编译插件和注解处理。候选源码和不可变制品存放在工具自己的制品区。审核依据包括构建记录、制品摘要、合同检查、独立用例和权限范围。
3. 隔离运行进程按指定版本加载制品，完成握手和限定范围的试运行后，由目录原子切换活动版本。新任务按快照选择版本，在途任务继续按已绑定且仍启用的版本运行。停用阻断后续调用，失败候选不覆盖活动版本。回退时恢复兼容当前变量定义的已验证版本，外部动作的补偿由相应业务合同处理。
4. Windows 首选验证 AppContainer 或 LPAC 的权限边界，加 Job Object 实施内存、CPU、进程数和进程树回收。初版按调用启动独立运行进程，构建和调用队列均设上限。隔离能力不可用时，该生成工具显示为不可用。选型需在本机用现有 JDK 验证文件权限、进程回收和 IPC。 [Microsoft AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/implementing-an-appcontainer) · [Microsoft Job Objects](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects)
5. 运行进程接收限定大小的 JSON 参数与授权变量快照，仅有工件只读访问和自己的临时空间。MCP、HA、文件和桌面能力如需开放，由宿主受信适配器按调用身份、已声明权限、实际资源和门禁代理；连接密钥留在宿主。首版可先支持纯计算工具，随后逐项开放代理能力。

| 情况 | 处理 |
| --- | --- |
| 版本不存在、拒绝调用、隔离启动失败 | 明确未执行，由编排决定是否采用其他已批准路径 |
| 子进程退出或超时，宿主能证实没有外部动作和变量提交 | 明确失败，回收工作进程和本次暂存数据 |
| 外部动作可能已经发出，调用超时、失联或结果无法验证 | 返回 `UNKNOWN`，停止自动重做，等待状态核对。关闭进程只能终止本地执行 |

按版本记录异常并可暂停故障版本。资源协调以实际动作和外部状态为准。若外部动作仍可能在途，需保留待核对标记，阻止后续计划误把该资源视为安全可重试。

## 5. 公共变量

公共变量统一由应用进程的 `ToolVariables` 管理。注册定义包含命名空间、类型、作用域、默认值、读写角色和持久化规则。首版可支持应用、会话和单次任务三个作用域。工具私有变量默认归属自己的命名空间，跨工具变量显式注册在共享命名空间。调用者必须指定作用域和名称，避免同名值隐式覆盖。应用级配置可持久化，短期变量随所属会话或任务回收。

例如 MCP 查询和固化技能可经授权共享 `shared.defaultRoom`；HA 连接密钥由适配器持有，设备实时状态仍通过世界模型查询，计划步骤间的结果仍走参数绑定。

2026-11-12 补充建议及最新边界：任务运行信息可经公共变量入口提供只读视图，查询携带 rootRunId、branchId；其中“线程”指逻辑分支，不是 Java 工作线程 ID。原由循环 BranchModelAllocator 保存绑定的方案已被移交取代，该生产类已删除。当前绑定的权威来源应为外部 ModelAdapter.Session；ToolVariables 不维护第二份可写绑定表，也不设置跨分支共享的 currentModelId。模型配置解析由同一适配器的 resolve 提供，交接见[27](../llm/27-模型适配器开发文档.md)。跨运行查询视图仍待实现；运行结束后的历史来源应为执行记录，不能把已经关闭的 Session 当作永久公共变量仓库。

调用读取不可变快照。生成工具返回允许的变量写入意图，由宿主按工具身份、类型、结果合同和期望版本校验，校验通过后原子提交。写入使用调用编号去重。超时或验证失败时丢弃暂存写入。已发出的外部动作和变量提交分别记录，版本冲突时由上层处理，避免自动重跑可能已生效的工具。

## 6. 工具可靠度先验

2026-11-16 用户确认可信来源规则。非大模型生成、非固化组合、非当前项目开发三项同时满足时，目录返回 `trustedAtomicTool = true`。结论来自宿主登记的实际来源及三项明确事实，适用于各接入协议。可信只免累计成功次数要求，评分公式、严格门限和执行门禁沿用现有逻辑。

`WorldEntity.statistics` 和 `ChainPosition.statistics` 保存对应范围内实际确认的成功、失败及归因。配置先验按工具调用名、接入实例、实现版本与已验证范围匹配。普通固化组合的先验权重为零。初始可靠度取 `[0, 1]`，权重为非负整数等效样本数。没有同范围配置时使用零权重。 [可靠度统计合同](../world/09-统一世界模型.md#可靠度统计合同)

### 来源目录与技能装配入口

`ToolDirectoryConfiguration` 从 `myhelper.tools.registrations` 创建 `ToolDirectory` Bean。每条活动登记提供 `tool-name`、`source-instance`、`implementation-version`、`source`、`model-generated`、`consolidated` 和 `project-developed`。可选 `priors` 列表内每条提供 `range-id`、`success-rate`、`weight`。未配置活动登记时目录为空。多个实例的同名工具由宿主分配不同调用名，重复调用名拒绝装配。宿主从可信接入配置确认来源和执行绑定，模型输入及外部工具自报的描述只作为工具合同数据。 [目录配置源码](../../../src/main/java/com/example/myhelper/tools/ToolDirectoryConfiguration.java) · [目录源码](../../../src/main/java/com/example/myhelper/tools/ToolDirectory.java)

技能侧可注入 `ToolDirectory`，并通过 `new ToolReliability(new RegisteredToolReliabilityLookup(directory, evidenceLookup))` 提供唯一 `ToolReliability` Bean。`VerifiedEvidenceLookup.findInVerifiedRange(ToolRef ref, Map<String, Object> arguments)` 以解析后的工具身份和完整参数查证，命中返回 `VerifiedEvidence(ref, statistics, externalFailures, verifiedRangeId)`。`ToolRef` 包含 `toolName`、`sourceInstance`、`implementationVersion`。适配器核对证据的 `ref`，按其 `verifiedRangeId` 读取同范围先验，填入既有 `Sample.prior` 和 `Sample.trustedAtomicTool`。未登记、范围未命中或证据身份不符时返回空，继续现有模型回退。 [技能适配器源码](../../../src/main/java/com/example/myhelper/skill/RegisteredToolReliabilityLookup.java)

宿主生产装配时用 `ToolDirectory.Binding(ref, callback)` 同时声明实际回调和工具身份，并调用 `SpringToolExecutor.withBindings`。名称是模型协议中的调用入口，工具身份由名称、接入实例和实现版本组成。查分接受执行器解析的完整身份，目录只核对身份并提供该版本的来源和先验。按版本执行前再次核对绑定，实际证据从同一回调绑定生成。旧的按名称执行入口仍可承接普通工具。 [执行器](../../../src/main/java/com/example/myhelper/orchestration/SpringToolExecutor.java)

应用装配需为目录和执行器提供同一组实际工具绑定。当前执行器仍按名称派发，运行时版本切换和在途版本固定依赖第 3 节的后续接线。生产范围、实际参数和统计仓储由技能侧提供，数据库读写经 `DualWriteStore` 并由上层显式指定来源或目标。目录配置与评分适配器均在内存中工作。

2026-11-16 用既有 JDK 25 和 `checks/run.ps1` 重新编译 90 个文件，154 项 JUnit 和 4 组存储检查全部通过。新增 10 项检查覆盖来源排除规则、实例与版本错配、参数范围、Spring 配置绑定以及既有门限。评分接线检查用范围证据替身，真实 MCP、HA 和数据库联调待完成。 [检查记录](../../../checks/README.md)

例如，MCP 工具初始可靠度 90%、权重 4，实际统计为零时得 90%。首次确认由方法本身造成的失败后得 72%。如果该次失败确认属于非方法失败，原始统计仍是成功 0 次、失败 1 次，计算时排除该次失败，得分维持 90%。90% 和权重 4 仅用于演算。

## 7. 首版交付与验收

1. 先接统一目录和调用入口，用一个 MCP 或 HA 基础工具与一个有明确合同的组合能力跑通按名发现、精确版本调用和编排复用。
2. 接公共变量快照与并发更新，验证两个工具共享一项变量、未授权访问被拒绝、冲突无部分写入。覆盖变量更新失败后的副作用状态。
3. 验证操作系统隔离后再开启生成工具发布。用故障样例覆盖编译失败、静态初始化失败、死循环、进程退出和超限输出，验证主进程、普通工具及其他版本仍可用。覆盖权限边界、热切换和回退、停用、动作发出后失联的 `UNKNOWN`，以及成功率先验未写入世界模型统计。
