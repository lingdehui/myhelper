## 设计评审

实时展示和权威任务记录各自处理不同的时序。编排上报的结构化事件已具备任务、运行、分支、节点及阶段身份，日志可直接复用。工具执行仍依赖 `TaskRecordPort` 对意图的同步确认。历史通过 `RunArchivePort` 读取已提交的证据，存储由记录模块经统一 persistence 维护。 [执行链路](../orchestration/13-执行链路记录开发文档.md) · [记录与归档](../records/28-执行记录与恢复端口开发文档.md#12-2026-11-16-生产记录接线合同实现进行中)

首版补齐了原建议中未定义的边界：

- `INTENT` 表示准备派发，工具可能仍在等资源锁，也可能因控制指令而跳过。工具返回、验收开始和验收结论各有事件。验收标为未执行时保留原动作状态。
- 规划待调用、真正进入 `ChatModel.call`、取得基础有效响应、解析决策、通过计划校验并采用分别显示。模型提交 `COMPLETE` 时仍须等待验收。
- 实时事件只显示白名单摘要，通过不含业务正文的任务标识、调用用途、步骤数、工具名和状态定位。等待恢复条件、模型所需输入、主动停止及运行收尾使用不同事件。完整目标、计划参数及原始证据留在各自已有业务数据中。
- 异步投递使用有界队列。接纳的消息由单消费者处理。超载时丢弃新消息并统计，消费者继续工作时报告拒绝数量。分支间日志行按入队顺序出现，事件自带发生时间和关联身份。

## 启动后使用

默认进度通过应用日志分类 `myhelper.tasklog` 以 INFO 输出。每行带事件种类、发生时间及 `task`、`root`、`run`、`node`、`branch`、`revision` 和 `ref`。同一次规划的编排事件与实际模型调用使用同一个 `node`。对持久事实，`ref` 是事件 ID。对实际模型调用，`ref` 是调用 ID。

| 配置 | 缺省 | 作用 |
| --- | --- | --- |
| `myhelper.task-log.enabled` | `true` | 装配默认实时输出，可用 `--myhelper.task-log.enabled=false` 关闭 |
| `myhelper.task-log.queue-capacity` | `512` | 实时队列容量，使用正整数 |
| `myhelper.task-log.replay-capacity` | `512` | 桌面模式下用于游标续读的缓冲容量，使用正整数 |
| `myhelper.records.enabled` | 由记录模块配置 | 控制正式任务记录及归档。关闭时仍可看到实时进度，`task` 使用本次根运行 ID |

本机终端用 `/history <taskId> <rootRunId>` 查询已提交的一次运行，ID 可从实时日志的 `task=`、`root=` 取得。输出包括图和证据完整性标志及按归档顺序排列的摘要。命令会区分未装配、未找到已提交归档和读取失败。命令只在本机操作员终端使用。未来的共享 UI 或远程查询应在调用 `TaskLogHistory.read` 前校验任务访问权限。

运行结束的业务输出保留交互模块原有行为。异步日志可能和交互回执交错。对于取消、超时或关闭，`STOP_REQUESTED` 显示停止新派发及等待在途工作的阶段，`RUN_ENDED` 对应真实收尾。 [终端交互](../interaction/20-交互与语音开发文档.md)

## 生产与消费合同

| 接入方 | 已实现 |
| --- | --- |
| 编排与记录 | `RunRecordAccess` 在 `append` 或 `endRun` 确认后发布共用投影。写入不确认时发布 `RECORD_UNCONFIRMED` 和发生阶段，并保留原业务异常。每次最终提交重试仍使用同一信封。无记录模式从现有事件点直接提取摘要。 |
| 单次模型调用 | `AgentCaller` 在实际模型调用边界发布开始、返回与失败，包含用途、模型配置名、耗时、失败阶段及异常类型。用量来自供应商响应经 Spring AI 提供的数值，缺省则省略。业务决策解析失败由编排报告。旧构造和调用签名继续兼容。 |
| 技能调用 | 候选描述生成关联来源根运行；参数范围判断使用独立调用 ID。技能归档来源没有提供的关联字段可为空。 |
| 异步输出 | `AsyncTaskLog` 单消费者与工作池独立。投递拒绝及消费失败可经计数读取。关闭时给队列一秒排空时间。 |
| 额外订阅 | 应用可注册 Spring `TaskLogPort.Listener` Bean。回调在日志消费线程调用，应快速接收并返回。默认终端输出继续使用应用日志。同期桌面窗口在该接口上接入 `TaskLogBuffer`，供当前进程有界回放。 |
| 历史读取 | `TaskLogHistory.read(ArchiveRef)` 读取固定归档的 `events`，使用与实时事实相同的 `TaskLogProjection`，保留图/证据完整性。实时专属阶段、模型用量和日志掉队计数留在进程日志。 |

默认摘要不输出提示词、用户目标原文、模型响应、工具参数与返回、回执证据或异常原文。添加事件时先选定允许展示的标识或固定状态，再构造摘要。`safeLabel` 适用于经过选择的标识。`TaskLogPort` 扩展实现须快速接收，耗时处理放入消费者。 [源码](../../../src/main/java/com/example/myhelper/tasklog) · [模型观测接线](../agent/11-单次模型调用模块.md)

## 后续跨模块接续

已向「循环可并发调用主流程」窗口同步归档身份、事件顺序、完整性与确认后的投递边界，也向「总」窗口交接桌面进度订阅。并行记录模块已提供 `StoredTaskRecords.readEvents(taskId, rootRunId, afterEventId, limit)`，供后续接入运行中回查。首版终端读取已知任务及根运行 ID 的归档。按任务列运行、跨进程订阅恢复和多用户读取权限仍需对应入口实现。若要展示实际取得资源锁并派发的时刻，执行器需提供相应的结构化观察。分支目标的可读摘要和业务等待的细分原因由相应业务及交互模块定义。 [桌面调试界面接线](../interaction/31-Swing桌面调试界面开发文档.md)
