## 职责与入口合同

文字、语音或其他入口统一产生 UserInstruction：commandId（原建议 instructionId，语义为一次输入的去重身份）、sessionId、关联 taskId、观察到的 rootRunId（可选）、正文、时间、来源、预期指令版本和明确的新增/修改/暂停/取消标记（若入口能提供）。恢复沿用稳定 taskId，不能只靠会变化的 rootRunId 找原任务。输出消费运行事件和最终结果，展示等待用户、执行中、部分失败和取消。

入口不自行拆自然语言任务；把指令交给[编排器](../orchestration/12-并行分支循环编排设计.md)。多条同时到达的指令允许并行，不用一条全局聊天消息列表承载所有任务。指代及业务先后由模型或明确入口关系解析。

## 语音流水线

音频采集 → VAD/分段 → ASR → 语句组装 → 统一指令入口；输出经文本事件 → TTS → 播放。唤醒、声纹、设备选择作为入口策略，优先恢复文字入口再接音频。旧资源路径、模型许可与兼容性实施时核对。

## 打断与追加

停止播音不等于取消工具；取消任务必须带稳定任务身份，定向取消某次运行时另带 rootRunId。用户追加要求更新受影响任务版本，无法确定指代时询问；不能把所有新发言当作取消前一任务。事件去重避免一次语音被重复提交。模型等待用户时保留关联信息，补充回复只恢复对应任务。

2026-11-12 用户确认先补设计。对明确关联原任务的“打断并修改”，应用鉴权后向记录模块持久提交 commandId、taskId、expectedInstructionRevision 和正文；同 ID 重试不重复接收，版本冲突不静默覆盖。入口不要求用户持有工作线程或 RunClaim。正文和指令顺序完整保存，由模型结合旧目标、已做事项和影响判断如何调整。

首版建议停止该任务的新派发，保存旧在途结果，旧运行真实结束后以同一 taskId 创建新运行并重新规划。应用分别展示“新指令已接收”“旧运行正在收束”“新要求已纳入计划”，不把取消 Future 当作工具已停止。暂停等待继续，取消不自动恢复原目标；独立新任务可另行并发。模型暂时不可用时，新指令及已有修改仍保留，待恢复入口接续。

完整流程见[26 第 10 节](../../planned/26-任务验收进度与断点恢复设计.md)；已实现合同见[28 第 10 节](../records/28-执行记录与恢复端口开发文档.md)。resume 加载原 TaskSpec 后绑定最新指令，模型收到原目标、按序输入及外部进度。应用可调用 instruct 接收控制命令，调用 amend 自动在真实收尾后重规划；暂停后提交 CONTINUE，再在旧运行收尾后显式 resume。任务关联、用户鉴权、输入界面与真正持久服务仍由对应模块实现。

## 验收

相同指令 ID 不重复执行；同时指令不串上下文；打断播音与取消执行分开；音频失败可以报告或回退文字；长任务持续显示真实进度；最终回复能关联执行证据；语音链路单独验证，不以资源文件存在代替可运行。
