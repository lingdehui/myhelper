## 1. 职责与边界

从[执行链路](../orchestration/13-执行链路记录开发文档.md)提取已验证子图，形成能力候选，独立审核、版本化发布、停用及追踪复用结果。复用定义仍是 WorldEntity 中的能力，不另建一套重复的长期技能实体体系。执行事实保留原样，不把固化建议写回历史节点。

不负责每轮检索，不负责线程调度，也不因一次成功自动扩大适用范围。检索与缓存归属[独立 capability 包](../capability/19-固化检索与缓存开发文档.md)。

## 2. 输入与产物

请求包含 rootRunId、图快照 sequence、候选节点集合、验证结果引用、预期复用范围。产物包括能力候选、来源子图、依赖与参数映射、版本、验证范围、已知失败限制、审核状态。

候选保存精确工具/能力引用、参数来源、步骤依赖、输入输出合同、执行条件与验收，不只是“再次让模型做某件事”的文字。确实需要 LLM 的子节点允许保留，但须声明调用点；这种能力可节省规划而非保证全程零 Token。

## 3. 固化流程

1. 取得固定版本、结果已封闭且经过验收的子图。
2. 找出外部输入与输出，把每次运行变化的参数与常量区分；不得把观察到的一个值随意泛化为任意值。
3. 保留 DATA_FROM、成功依赖、可并发关系和条件；串行发生不等于必须串行，同时发生也不证明任意环境都能并发。
4. 生成候选 Unit 合同并验证引用完整、无无界展开、实现可定位。
5. 独立审核验证范围、证据、验收和副作用处理；不足时留候选/参考状态。
6. 保存新能力版本及审核记录，完成检索索引发布后才报告可发现。

父任务未完全成功时，可对已独立验收、外部依赖明确的子图生成候选。原子工具包装、组合子流程、完整流程均可成为复用对象；避免为每次完全相同执行重复生成新能力，按合同/依赖指纹合并证据，修改合同则产生新版本。

## 4. 发布与生命周期建议

早期建议的候选状态为 DRAFT、REVIEWED、PUBLISHED、SUSPENDED。当前仓储实际使用 `CANDIDATE`、`APPROVED`、`REJECTED`、`PUBLISHING` 和 `PUBLISHED` 管理候选与发布流程。检索按权威实体的发布状态核对，发布重试保持已有停用状态。业务停用入口和通用历史修订读取待实现。 [候选及审核](../../../src/main/java/com/example/myhelper/skill/StoredSkillRepository.java#L95) · [归组发布](#18-2026-11-18-一意图多链发布与归档评分)

能力发布量持续增长时，以数据库为全量来源，不全量推送到内存，不要求通知每个运行任务。新发布能力由下一次规划前/后的检索发现。更新/撤销记录持久化；执行前以权威状态拒绝已停用版本。向量索引延迟期间不得以其旧状态绕过门禁。

存储只负责明确目标写入及补偿；业务发布状态、索引就绪、失败修复由固化/仓储层协调。补偿失败或结果未知时标为待核对，不返回“已发布”。

## 5. 建议接口

propose(traceSlice)、review(candidateRef)、publish(reviewedRef)、suspend(unitRef, reason)、recordReuse(unitRef, outcomeRef)。审核可由规则、测试及独立模型组合实现，最终机制待定；生成者的自评不能作为唯一证据。

## 6. 验收

已验证子图可独立提取；缺外部输入不能发布；失败/未知结果不当成功；版本和证据可追溯；重复轨迹不无限增加能力；范围不自动泛化；发布失败不进入候选可用集合；局部复用实际减少规划调用；含模型子工具时正确统计调用量。

## 7. 固化链路中的复用位置分析

2026-11-10 分析与结构实现记录。用户要求共享 Unit 能记录被哪条链路、哪个分支和哪个位置引用。7.6 的 chainPositions 数组已写入实体代码；完整链路图、自动反向索引和历史还原仍为候选建议，当前执行接口不因此自动升级。

### 7.1 当前已有与缺口

WorldEntity.data 可以保存任意 JSON 兼容的结构，bindings 保存字段位置到目标的连接；FieldBinding 只有 slot/target，EntityRef 只有目标身份、修订和类型。当前已通过 ChainPosition 保存链路编号、修订、分支路径和出现位置；完整边合同及反向查询仍未实现。slot 定位某一修订中的字段，不是跨修订稳定的位置编号。

TaskPlan.Step 已有计划内唯一 id、参数、dependsOn 及输入来源，适合作为位置身份的起点。当前执行图已有 rootRunId、运行节点 id、父子归属、planRevision、SPAWNED/DEPENDS_ON/DATA_FROM。它们描述运行实例，不能直接充当持久固化定义的完整版本和位置合同。Neo4j WORLD_REF.position 是引用投影数组中的顺序，不是执行位置或分支身份。

旧设计原稿的 CONTAINS 把调用参数放在关系上，并允许多个父 Unit 共享子 Unit；整体能力图按入口展开为调用树。这个原则可以保留。旧稿没有明确 chainId/occurrenceId/branchId 的版本化合同，直接父引用查询也不等于完整所属链路查询。旧稿中 order 可以区分局部顺序，但是否保存同父同子的多条边，不能仅凭文档断言。

### 7.2 推荐的身份层次

| 身份 | 用途 |
| --- | --- |
| unitId + unitRevision | 可复用能力定义，同一能力可以被引用多次 |
| chainId + chainRevision | 一份固化链路定义；可直接使用组合 Unit 的 id/revision |
| nodeId | 某个 Unit 在该链路内的一次出现，沿用或扩展 Step.id；不使用 unitId 代替 |
| edgeId | 链路内一条连接的稳定身份，避免同端点多关系被合并 |
| rootRunId + traceNodeId | 某次真实执行身份；重试或再次调用不能覆盖前一次 |

同一链路两处调用 U，需要两个 nodeId，都引用同一 U 的固定修订。这表示复用定义，不表示两次调用自动共用结果。若执行图确实只运行一次并由两个后继读取结果，应只有一个出现节点并保留两条数据依赖。

### 7.3 链路的组成结构

保持组合能力为 WorldEntity(unitType=PLAN_STEP)。建议在其 data.executionPlan 合同下增加位置与关系的结构定义，必要时新增 ChainGraph、ChainNode、ChainEdge 等 Java 数据类作为组成结构；不增加第五类世界实体，也不建立另一份长期技能主对象。

| 结构 | 建议字段 |
| --- | --- |
| 链路定义 | 固定版本的入口、位置集合、关系集合、输入输出及来源子图 |
| ChainNode | nodeId、固定版本 unitRef、可选 parentNodeId、局部 order、调用参数与参数来源 |
| ChainEdge | edgeId、fromNodeId、toNodeId、关系类型、分支标识、可选条件与参数字段映射 |

当前 executionPlan 解析器仍是 TaskPlan(goal, steps) 的最小合同。上述结构需要与 TaskPlan、执行器和能力仓储共同制定兼容或迁移规则，不能一边新增另一份 graph、一边继续独立修改原执行计划。精确 Unit 引用与外层 bindings 投影也需约定唯一来源，避免手工维护两份不一致的连接。

父子归属与执行依赖分别记录。parentNodeId 表示组成或调用归属；前驱关系、数据来源和条件由对应关系表达。数组顺序或局部 order 不能替代执行依赖。分支还应区分并行、条件选择及汇合条件，仅有 branchId 无法说明执行语义。

树形结构可以推导单条位置路径；DAG 汇合节点可能有多条到达路径，不能强行赋予一个唯一 branchId 或路径字符串。分支标识放在分叉关系上，分支路径按需要推导。嵌套复用时，用父级出现编号组成 occurrencePath；同一个子能力被调用两次，其内部节点在两条展开路径中分别定位。

### 7.4 正向展开与反向查找

查询某条固化链时，先按 chainId/revision 取得其位置与关系集合，再按 unitRef 固定修订展开组合子能力。定义可以缓存去重，但两个不同位置的出现不能因此被合并。展开使用执行合同中的组成/依赖关系，不沿所有语义及证据引用无限遍历世界模型。

反向查询可建立派生索引：

```text
(unitId, unitRevision)
  -> [(ownerChainId, ownerRevision, nodeId), ...]
```

索引首先描述直接所属链路。若要找到所有外层根链路，继续按精确修订反查父组合能力，并保留每条 occurrencePath。跨层复用不能只返回父能力 ID 而丢弃它在外层的出现位置。

不建议把权威 chainIds 数组不断写回共享 Unit。数组可以作为查询结果或派生索引；单独记录链路 ID 会丢失链路版本、同链多位置、分支和参数语境，且每次组合/删除/改版都需要改动共享节点。链路本身的位置与关系应是事实来源。

### 7.5 还原当时状态的条件

还原固化定义需要保存不可变链路修订，以及它引用的全部能力修订。还原当时真实执行还需要归档执行图快照、输入输出与验收依据，并保留固化位置到来源执行节点的映射；折叠或泛化可能使映射为多对多。

正式记录仓储已保存固定的收尾执行图及相关证据，可按 `rootRunId` 读归档。`ExecutionTraceStore` 仍是运行期内存图。发布仓储按 ID 读取当前定义，保存和读取任意实体旧修订、获取当时所有依赖定义及固化位置到来源节点的映射仍有缺口。执行归档和旧固化定义的还原分别验收。 [持久归档](../records/28-执行记录与恢复端口开发文档.md#15-2026-11-17-恢复策略边界与可读性整改)

世界知识引用允许循环，不等于执行依赖允许无界循环。当前 TaskPlan 的依赖合同要求 DAG；候选固化仍需检查有限展开、外部输入、分支与验收，不能将可存储关系自动视为可执行能力。

### 7.6 用户提出的 IDS 位置数组

用户提出 `IDS [ID-分支-位置]` 并进一步要求落到代码。已实现顶层 WorldEntity.chainPositions，元素类型为 ChainPosition(chainId, chainRevision, branchPath, nodeId, statistics)。链路编号与修订明确定位定义版本，分支使用路径，位置使用稳定编号。构造器检查必填项及修订，并复制列表；原构造方式保留，位置数组默认空列表。

当前已实现条目为 `{chainId, chainRevision, branchPath, nodeId}`。嵌套能力的同一内部位置被多次展开时，还需用父级出现编号组成 occurrencePath。DAG 汇合位置的分支归属按关系解释，不能强制假定只有一条进入路径。

该数组记录使用位置，链路定义仍需保存完整位置集合和关系，才能按链路修订读取并向下展开。正式字段为实体顶层 chainPositions，不再采用 data.chainPositions 草案。ChainPosition 是数组元素，不增加新的世界实体类别。定位信息可派生，但位置内的 statistics 需要保留，重建索引不能清空统计；数组不自动维护引用、不自动查询或还原链路，也不单独保存历史快照。此次按用户要求未编译，仅完成代码与文档静态核对。

## 8. 已实现的执行统计结构

本节记录初次加数据结构的阶段。当时用户要求先补字段。新增 `ExecutionStatistics(successCount, failureCount, failureCauses)`，挂在 `WorldEntity.statistics` 和 `ChainPosition.statistics`。归因结构为 `FailureCause`，类别为 `PLAN`、`ENVIRONMENT` 和 `UNKNOWN`。当前链级评分由第 18 节独立归档事实派生。

整条固化链路作为组合 Unit，在自身 id/revision 下记录总体结果；共享 Unit 的某个链路位置在其 chainId/chainRevision/nodeId 下记录局部结果。原因编号可复用，但每个统计范围持有各自的原因出现次数。世界实体已有 revision，链路位置已有 chainRevision，不按跨版本总次数合并。

用户倾向保存成功/失败事实，由后续公式结合归因计算可靠度，不先维护成功加一、失败减一的分数。整链失败而前面位置成功时，分别记录链失败、该位置成功；哪个位置失败记录哪个位置失败，未执行位置不变。整链成功也只对实际成功的参与位置记成功，未选择分支不算执行。这些是后续记账要求，没有写入执行器或存储更新逻辑。

旧设计原稿已有 successCount/failureCount/stability 和 FailureCause，归因分 PLAN/ENVIRONMENT；旧“环境失败不惩罚”属于处罚策略，不等于环境失败在事实计数中消失。当前类型只表达分类，不定义惩罚权重。UNKNOWN 仅表示归因未分类，执行结果未知不自动写失败。

原 WorldEntity 的 16/17 参数和 ChainPosition 的四参数构造方式保留，缺统计时设为空统计。首次加字段仅做静态核对。后续工具与整链事实已独立存储、去重和派生评分。链位置逐级记账、自动归因和通用历史版本迁移仍待补。字段、示例与版本范围见[世界模型的执行统计说明](../world/09-统一世界模型.md#执行统计与失败归因)及[链级归档事实](#18-2026-11-18-一意图多链发布与归档评分)。

## 12. 2026-11-15 工具可靠度的先验与实际统计

用户同意按先验加权计算。ToolReliability.score 入口和 Lookup 查询方式沿用。查到当前有效修订且完整入参命中已验证范围后，按（初始可靠度 × 初始权重 + 成功次数）÷（初始权重 + 成功次数 + 失败次数 − 已确认的非方法失败次数）计算。

工具评分缺少同范围先验时使用零权重。有效样本及先验权重均为零时返回空。可信第三方工具的初始可靠度与权重由工具目录按实例、实现版本和适用范围提供。非方法失败按执行身份去重。归因未知的已确认失败保留在分母中。初始可靠度 0.95 和权重 20 是演算示例。当前多链排序使用第 18 节的链分，独立于此处的工具先验。

公式输出 0 到 1。循环按严格大于配置门限判断，保留执行门禁和验收。默认 0.05、当时没有最低成功次数属于该阶段的历史配置。当前门限和次数见第 13 节，生产查询接线见第 17 节。

`SkillChainExecutionStore` 通过 `DualWriteStore` 将链使用事实保存为独立的 Neo4j 观测实体，不修改发布链及其 `WorldEntity.statistics`。当前以权威链上非空的 `scope.verifiedScope` 表示一个已批准范围，支持描述文本或结构化约束，范围 ID 由范围内容派生。先保存实际事实，再将模型明确确认匹配的事实按条件写入关联该范围。模型不可用时事实仍保留，供后续重扫。评分只读固定链修订与当前批准范围内的事实，按成功次数除以成功与有效失败次数之和计算。确认的环境失败保留事实并排除出分母。查无有效样本或适用范围时返回未知分数。

运行事实接线还有一处缺口。当前 `AgentOrchestrator` 只在操作执行成功时设置 `VERIFIED.performed=true`，没有发送链级 `chainAttemptCounted` 或结构化 `failureCategory`。这样，工具已经实际派发、但执行失败导致的整链失败，通常没有计入链分。整链执行成功后验收失败仍可记为失败。补齐真实执行失败的计数标记和归因后，需要用运行产生的归档检查分母变化。 [编排发出的验收事件](../../../src/main/java/com/example/myhelper/orchestration/AgentOrchestrator.java#L1663) · [链级归档采样](../../../src/main/java/com/example/myhelper/skill/ArchivedSkillChainReliability.java#L97)
