## 职责与边界

`WorldRepository` 负责为世界业务指定来源与目标、写入观测、按引用读取并展开。`ContextService` 负责选择本次事实和证据、解析状态、报告待刷新事项，并向编排器返回不可变的世界上下文。统一存储继续处理显式选库后的读写和条件提交。引用的适用范围和时效由世界层核对。 [统一存储接口](../../../src/main/java/com/example/myhelper/persistence/DualWriteStore.java)

正式任务进度和待恢复事项仍由 `TaskRecordPort` 提供。循环的 `Feedback` 继续保存本次任务的执行结果。固化召回及计划匹配归 `capability`，工具实际执行及验收归编排、执行与门禁。世界上下文提供证据与当前判断，各模块继续使用原合同。 [任务记录](../records/28-执行记录与恢复端口开发文档.md) · [固化检索](../capability/19-固化检索与缓存开发文档.md)

### 能力内部的设备与状态查询

2026-11-17 用户确认，找设备、查状态和控制设备沿用[循环主流程已有的固化检索和规划](../capability/19-固化检索与缓存开发文档.md#统一能力入口与世界查询接线)。「客厅空调现在开着吗」进入世界侧接口时，调用方已提供设备查询条件和 `power`。世界模块按名称、别名、房间或 `subjectId` 找设备，并读取可信观测。

世界侧按调用方给出的访问范围过滤数据，多台设备符合时保留歧义，返回状态值、时间、来源、证据及未知原因。证据过期或缺失时，提供刷新依据。实际感知工具及其注册由工具生成管理负责，业务授权和验收规则由门禁提供，工具派发走原有循环。调用方拿到实际观测后，调用世界接口追加 `OBSERVATION` 并复查。 [工具管理](../tools/25-工具管理与隔离运行设计.md) · [运行门禁](../gate/15-门禁与验收开发文档.md)

`worldContext` 仍供每轮规划补充已有可信事实，通过宿主授权选择器取得。它可以消费能力已定位的对象、结构化参数或明确提供的引用。该接点复用状态查询合同。

#### 已实现的世界查询接点

- `WorldDeviceDirectory.find(Query, Access)` 使用统一存储在明确权威库查 `ROOM` 和 `DEVICE`。`ROOM` 使用顶层 `name` 和 `data.aliases`。`DEVICE` 另有 `data.roomId` 指向房间稳定 ID。当前采用完全匹配，名称及别名查找分别分页并按 ID 合并。显式 `subjectId` 时直接核对该 `DEVICE`。范围在查询开始前授权，候选按完整范围和对象权限复核。页未读完、数据源异常或发现同一对象的不同修订时返回不完整。重名房间保留歧义。 [目录实现](../../../src/main/java/com/example/myhelper/world/WorldDeviceDirectory.java)
- `WorldDeviceStatus.read(Request, Access)` 使用同一个精确范围定位设备和读取观测。`Access` 由宿主按任务授权，核对目录、属性及其裁决需要的同设备证据。属性有可信当前证据时返回 `KNOWN`。缺失或过期且确有获准感知工具时返回 `NEEDS_REFRESH` 及固定设备和工具修订。冲突、未能读全或指定证据修订缺失继续返回未知及裁决原因。 [状态接口](../../../src/main/java/com/example/myhelper/world/WorldDeviceStatus.java)
- 执行编排调用工具后，向 `WorldDeviceStatus.complete(...)` 传实际派发的工具引用和实际观测。接口复核设备修订及授权，并核对观测的设备、属性、范围、来源和真实时间，再追加 `OBSERVATION` 并按最新查询时间复查。重试复用同一观测 ID。复查直接给出世界状态裁决，工具的派发、预算和失败处理继续由编排负责。 [观测写入与复查](../../../src/main/java/com/example/myhelper/world/WorldDeviceStatus.java)

#### 客厅空调查询场景

以下从能力已取得设备线索和 `power` 参数开始，设备值使用本地替身。

| 场景 | 世界侧行为 |
| --- | --- |
| 新鲜观测 | 登记的客厅与空调唯一匹配时返回 `KNOWN`。结果携带实际值、观测时刻、来源和精确证据修订，直接交能力组织返回 |
| 过期观测 | 初查保留 `EXPIRED` 和历史依据。已有授权工具时返回 `NEEDS_REFRESH`，编排交回实际观测后追加并复查。有新鲜可信值才返回 `KNOWN`。没有获准工具时返回未知并保留过期原因 |
| 设备歧义 | 多台可见登记设备符合时返回 `AMBIGUOUS`，由能力请求足以区分设备的信息。查询在定位阶段结束 |
| 无权限 | 未获目录或属性权限时返回 `UNKNOWN / ACCESS_DENIED`，结果不带候选和观测。无感知授权时没有待感知请求 |

正式应用将两个世界业务组件与现有 Neo4j 仓储一同装配。真实场景仍需要设备及别名数据、工具生成管理提供的生产工具、门禁提供的业务授权和验收规则，以及调用方回交实际观测。 [Spring 装配](../../../src/main/java/com/example/myhelper/world/WorldModelConfiguration.java)

固化技能的语义匹配、根任务入口和参数绑定沿用循环主流程的现有职责。世界侧接收已明确的字段及授权范围，支持能力内的状态查询。 [循环检索与规划](../capability/19-固化检索与缓存开发文档.md#统一能力入口与世界查询接线)

### 当前接口与装配

| 接口 | 当前行为 |
| --- | --- |
| `WorldRepository.append(Observation)` | 生成基于主体、属性、规范 JSON 值的 `state:v1:<SHA-256>`。按明确的观测 ID 追加，重试核对事件与固定的状态引用。每次独立感知使用新 ID |
| `WorldRepository.read(EntityRef)` | 在选定库核对当前保存的类型和请求修订。指定修订缺失时返回空。独立的通用历史修订保存与读取待实现 |
| `ContextService.current(Query)` | 精确范围下返回 `KNOWN`、`UNKNOWN`、`EXPIRED`、`CONFLICT`、`INCOMPLETE` 或 `REVISION_UNAVAILABLE`。按同来源最新观测、有效期、最大年龄及置信度裁决。保留冲突证据和可核查的上次观测 |
| `ContextService.history(Query)` | 读取真实观测时点不晚于查询截止的观测，保留可核验的过期证据。候选页或确切修订缺失时报告结果不完整 |
| `WorldReferenceExpander.expand(...)` | 根库由调用方指定，每跳由 `SourceResolver` 选库。对实体和实际请求字段执行 `ReadAccess`，按深度、条数与耗时限制读取，返回选中值、引用路径和问题 |
| `WorldConditions.requirement(Request)` / `verify(Request, completedAt)` | 读取 `REQUIREMENT`／`EXPECTATION`，支持按状态身份和值等值判断、数值范围及集合判断。验收需要动作完成之后的可信证据。可返回 `NEEDS_REFRESH` 及感知能力引用，复查可标记本轮已尝试刷新 |
| `WorldPlanningContext.Selector` | 由宿主按本任务授权选定属性、精确范围、可信策略及可展开字段。每轮使用独立快照。显式历史查询和字段参考各有用途标记 |

应用通过 `WorldModelConfiguration` 装配世界组件。注入的统一存储存在时，状态写入目标为 Neo4j。缺少授权选择器时，模型收到空 `worldContext`。跨引用位置映射由可选的 `SourceResolver` 提供。缺少映射时，调用方仍可读取已明确来源及授权的根字段。 [应用入口](../../../src/main/java/com/example/myhelper/MyHelperApplication.java) · [装配代码](../../../src/main/java/com/example/myhelper/world/WorldModelConfiguration.java)

业务工具与门禁需要将各自的真实观测、权限、绑定的条件或验收目标交给这些接口。感知回调返回后，调用方用新观测 ID 追加结果，再以同一精确条件引用复查。总刷新预算、调度和能力资格仍由编排与门禁提供。状态层的耗时预算限制继续读取与采纳迟到结果，底层同步请求本身由存储超时管理。

## 输入输出建议

| 合同 | 字段及语义 |
| --- | --- |
| `QueryRequest` | 当前任务或子任务的目标、只读授权范围、已知 `EntityRef`、所需字段或 `subjectId + predicate`、明确来源或上层位置映射、查询时点、查询用途、深度与数量预算。当前状态与历史查询由用途区分。 |
| 状态查询结果 | 选中的 `STATE` 与 `OBSERVATION` 引用、带类型的值、观测时间、有效期、来源和适用范围。明确返回已取得、过期、未知、冲突、指定修订不可取得或查询不完整。问题保留可追溯的证据。 |
| `ContextSnapshot` | `snapshotId`、查询时点、当前可信状态、相关历史及语义参考、冲突与未知项，以及来源和确切修订。快照只归本轮使用，不等同于库里每次追加的 `OBSERVATION`。 |

显式来源优先。还需自动定位时由世界仓储使用业务配置或绑定关系确定来源。节点类型本身不能确定存放位置。`EntityRef.revision` 固定时读取对应版本，查不到就报告不可取得。首轮可依靠每次新增 ID 的 `OBSERVATION` 查询历史感知。任意实体被覆盖前的旧修订需要独立的留存和读取合同。 [当前修订核对](../../../src/main/java/com/example/myhelper/persistence/DualWriteStore.java#L199)

## 查询与状态规则

### 标准状态与历史感知

1. 按 [09 数据合同](09-统一世界模型.md#标准状态的身份) 归一主体、属性和值，生成可重复得到的带版本状态 ID。优先用已有条件写保证同一身份去重。先确认 `STATE` 存在且内容相符，再追加本次 `OBSERVATION`，写入准确的 `stateId` 与可选修订引用。失败重试沿用本次观测 ID。两次感知即使同值也各有观测 ID。
2. 世界观测读写入口使用 `data.kind = world-state-observation` 和范围键过滤。任务记录和工具执行事实也会使用 `OBSERVATION` 枚举，沿用各自合同。观测来源、时间、范围和证据从实际感知获取。可通过追加记录更正，并使用证据引用关联原记录。
3. 当前状态按 `subjectId + predicate` 和适用范围查询。用显式策略判断 `observedAt`、`validUntil`、本次最大允许年龄、来源或置信门槛。`createdAt` 与 `updatedAt` 继续表示实体元数据。历史查询以所问的时间作为依据，可以引用已经失效的历史证据说明当时的值。断联、电源和其他属性各自解析。断联加历史开机证据可以得到 `connectivity = DISCONNECTED`、当前 `power = UNKNOWN` 及带时间来源的上次已知 `ON`。
4. 同一来源先后改变的观测按其时间和领域规则解释。多个同范围、满足可信条件且尚有效的证据给出不同结果时，只有存在明确裁决依据才选择其中一条，否则返回冲突。无时效依据时返回未知或请求感知，不使用最近更新时间代替真实观测。`STATE`、`REQUIREMENT`、`EXPECTATION` 和人格偏好各自按角色投影。

现有条件查询按 ID 分页。随机观测 ID 的顺序不能代表时间。首轮可筛选所需对象和属性、在预算内读足相关页，再按观测时间裁决。若预算用完仍有续页，报告查询不完整。数据量增大后，稳定的时间索引与有序候选读取经统一存储接入。 [查询与分页](../persistence/10-统一双写模块分析.md)

### 引用展开与图、向量分工

只展开本轮要求的 `slot` 和引用。保留直接值、同一位置的多个引用以及引用路径，按 `来源 + 类型 + ID + 修订` 去重并限制深度、条数和耗时。保留缺失、无权限与预算耗尽的原因。精确编号、属性和值的类型保留原样。

向量用于按语义发现候选。取得候选后，按其类型、身份和显式来源回读需要核实的实体，再做范围、时效和状态判断。图与向量继续支持各自的引用关系。向量命中可以进入上下文中的语义参考，强制条件和验收使用可核验的事实。能力查找按现有 `capability` 路径接续。 [字段引用和向量](09-统一世界模型.md#字段引用) · [固化回源](../capability/19-固化检索与缓存开发文档.md)

### 条件、感知刷新与执行后验收

旧版的条件链沿用 `能力 → REQUIREMENT/EXPECTATION → STATE`。条件与预期引用准确的状态和值，当前实际状态由本轮证据解析。等于与不等于可以使用规范状态 ID，范围或集合条件应比较规范后的带类型值。世界模块返回证据、判断和需要刷新的原因。 [旧版条件直达与感知](../../legacy/my.md#L4883) · [运行门禁](../gate/15-门禁与验收开发文档.md)

- 前置条件缺失、过期或可信度不够，且业务配置了可用的 `refreshUnitId` 或固定感知能力引用时，由编排与执行模块通过原有工具权限和门禁执行感知。感知结果包含主体、属性、实际值、时间、来源与证据，以新观测追加，再重新核对原条件。每项条件每轮最多刷新一次，总次数和递归深度纳入编排预算，保留失败或未知原因。
- 执行后验收根据实际执行之后的观测或明确的业务证据比较 `EXPECTATION`。一次 `COMPLETE` 或工具返回成功只触发下一阶段，验收的有效性继续由 `RuntimeGate` 及其业务实现负责。缺证据的经历可作为案例候选，技能发布仍由固化与审核模块负责。
- 本轮旧状态可留下给模型参考，已经过期的值不能支持固化直执。编排保留已确认步骤的结果，在需要重新规划时把失败或未知证据带给模型，实际要继续执行的步骤仍按现有权限和依赖决定。

## 模型上下文组装

规划器发送 `task`、`availableTools` 及独立的 `worldContext`。每轮规划根据该任务的上下文取一份不可变快照，兄弟任务和下一轮分别取证。计划输出仍使用 `submit_plan`、`finish_task`，原有任务字段和工具协议保留。世界上下文最多 30 组顶层条目，使用 32 KiB JSON 和两秒继续读取预算。冲突集有界，截断后标记 `truncated`。 [旧版模型输入](../../legacy/my.md#L4924) · [请求组装](../../../src/main/java/com/example/myhelper/orchestration/AgentCallerPlanner.java)

```json
{
  "worldContext": {
    "snapshotId": "example-01",
    "asOf": "2026-11-17T10:00:00+08:00",
    "observations": [
      {
        "subjectId": "device:living-room-light",
        "predicate": "brightness",
        "value": 35,
        "unit": "percent",
        "use": "HISTORICAL",
        "observedAt": "2026-11-16T22:00:00+08:00",
        "evidence": {"id": "observation:example-01", "revision": 1, "source": "Home Assistant"}
      }
    ],
    "conflicts": [],
    "unknown": [],
    "references": [],
    "truncated": false
  }
}
```

当前观测和历史观测分别标记 `CURRENT` 与 `HISTORICAL`，按明确字段展开的背景材料标记 `REFERENCE`。历史案例、推断、规则、人格偏好及语义候选可由其真实提供方选择具体字段作为参考。向量候选回源、跨案例规则、偏好排序和维护仍需对应模块提供。工具权限与派发核对沿用编排和门禁，固定用途说明写入 `LlmTexts`。 [现有计划绑定](../../../src/main/java/com/example/myhelper/orchestration/TaskPlan.java)

## 验收

1. **先打通观测闭环。** 完成状态身份、幂等写入、新观测追加、按对象和属性读取现状或历史。用已有存储替身检查两次同值观测共享状态、重试不重复、证据过期或冲突、断联仍区分电源状态，以及未读取完候选页时返回不完整。
2. **接通每轮世界上下文。** 以一个明确对象和属性打通从落盘到模型 JSON，保留证据修订、时刻和来源。检查有界展开、循环引用、多来源、固定修订缺失、子任务隔离、空快照及原工具协议兼容。同步 `checks` 内的规划请求合同。
3. **接通刷新及跨模块读合同。** 用本地感知工具检查刷新前后的取证、执行后验收、次数限制和证据未知。实际意图匹配、长期偏好、历史参考和维护由对应模块接入以上合同。独立通用历史修订的保存与回读需单列验证，世界观测历史的追加查询单独计入交付。
4. **验证能力内的设备查询。** 从已绑定的条件开始，检查新鲜记录直接返回带时间的证据、过期记录给出刷新依据、回交实际值后追加并复查，以及设备歧义、无权限和明确 ID 的路径。完整用户原话到实际设备的验证由循环、工具管理和门禁按现有分工联调。
