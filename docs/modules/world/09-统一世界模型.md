世界模型用统一实体保存具体对象、世界陈述、能力和抽象语义。具体内容通过明确字段及引用形成图，抽象内容保留原文、来源和向量表示；两者可以互相引用，形成多层、分支和循环关系。

## 实体与类型

所有内容都使用 [WorldEntity](../../../src/main/java/com/example/myhelper/world/model/WorldEntity.java)。类型定义分为四个独立枚举，实体中有四个对应字段。

| 实体字段 | 独立枚举 | 当前取值 |
| --- | --- | --- |
| `worldObjectType` | [WorldObjectType](../../../src/main/java/com/example/myhelper/world/model/WorldObjectType.java) | `USER`、`ROOM`、`DEVICE`、`APPLICATION`、`FILE`、`SYSTEM`、`MYHELPER` |
| `contextUnitType` | [ContextUnitType](../../../src/main/java/com/example/myhelper/world/model/ContextUnitType.java) | `STATE`、`OBSERVATION`、`FACT`、`REQUIREMENT`、`EXPECTATION`、`INFERENCE`、`PERSONALITY` |
| `unitType` | [UnitType](../../../src/main/java/com/example/myhelper/world/model/UnitType.java) | `INTENT`、`TOOL`、`MCP_TOOL`、`PLAN_STEP`、`LONG_TERM_TASK` |
| `semanticType` | [SemanticType](../../../src/main/java/com/example/myhelper/world/model/SemanticType.java) | `CONTENT`，后续按需要扩展 |

每个实体必须且只能填写一个类型字段，其余三个为 `null`。例如，空调填写 `worldObjectType = DEVICE`；一次设备观测填写 `contextUnitType = OBSERVATION`；工具填写 `unitType = TOOL`；抽象描述填写 `semanticType = CONTENT`。

类型之间通过实体引用关联。设备的抽象用途可以引用语义实体；语义实体也可以继续引用设备、观测、能力或其他语义实体。

`data` 中可使用字符串、布尔、数字、`null`、嵌套 Map 和 List。构造器只复制 `data`、`scope` 的顶层映射，嵌套数据由写入方维护。

## 状态定义与历史观测

本节把 2026-09-02 旧稿中的状态定义、历史快照和条件校验语义落到当前 `WorldEntity`。旧稿的 `WorldObject`、`ContextUnit`、`Unit` 在当前代码中对应不同类型字段。历史快照是 `contextUnitType = OBSERVATION` 的实体，不新增 `State` 或 `Snapshot` 持久化类别。旧稿见 [归档合并稿](../../legacy/my.md)，桌面原稿对应《13 - 递归世界模型、状态与历史快照》。

世界仓储已在统一实体上实现标准状态 ID、观测追加与重试去重。当前状态按对象、属性和授权范围从观测证据中裁决。条件服务返回可用证据、判断和刷新请求，由宿主负责感知工具的选择与派发。任务记录及工具执行事实也使用 `OBSERVATION` 枚举，各自保留业务标记。 [查询与装配](23-世界模型查询与上下文开发文档.md)

| `contextUnitType` | 世界状态中的含义 |
| --- | --- |
| `STATE` | 某个主体的某项属性取到某值的标准定义，例如客厅空调的 `power = ON`。定义存在不表示现实中已经成立 |
| `OBSERVATION` | 某次实际感知留下的历史记录。指向当次观测到的 `STATE`，保留时间、来源、范围和证据 |
| `FACT` | 有来源和证据支持的相对稳定陈述。按用途判断适用范围与时效，可指向相关 `STATE` |
| `INFERENCE` | 从证据推导的结论。保留推导依据、范围与置信度，可以指向推断对应的 `STATE` |
| `REQUIREMENT` | 执行前需要满足的条件。引用要求的 `STATE` 或按字段合同表达比较条件，其成立依赖本次实际证据 |
| `EXPECTATION` | 执行后要验收的目标。引用预期 `STATE` 或按字段合同表达验收条件，由本次执行后的证据判断 |
| `PERSONALITY` | 系统自身的长期行为倾向或偏好。保存来源和适用范围，与当次现场观测区分 |

### 标准状态的身份

建议在 `STATE.data` 中明确存储 `subjectId`、`predicate` 和带类型的 `value`。主体使用稳定对象 ID，属性使用约定名称，值按照该属性的领域规则归一。相同的主体、属性和规范值共享一条状态定义。状态 ID 建议按带版本的规范 JSON 元组计算，例如 `state:v1:<SHA-256>`，元组内容为 `[subjectId, predicate, normalizedValue]`。保留 JSON 值类型与数组顺序，规范对象键序和数字格式，保留可复核的原字段。避免直接用冒号拼接可能含分隔符的 ID、属性名称和值，或把数字、布尔值与同形字符串合成同一身份。

主体、属性或规范值变化时建立另一条 `STATE`。同一状态的说明、来源等内容变更需要可追溯时，仍按实体的 `id + revision` 管理。`STATE` 的修订和 `OBSERVATION` 的新身份各有用途，重复看到同一状态仍产生新观测。

现有实现保存 `data.kind = world-state`、带类型的 `data.value` 及精确规范 JSON 文本 `data.valueCanonical`。读取规范值时重新核对状态 ID。规范文本保留经过通用存储解码可能舍入的十进制值。属性的领域取值由感知提供方规范化。

### 追加观测及判断时效

每次独立感知创建一条具有新 ID 的 `WorldEntity`，填写 `contextUnitType = OBSERVATION` 和初始 `revision = 1`。标识可用独立观测 ID，同一事件重试时沿用该 ID。用 `data.subjectId`、`data.predicate`、`data.stateId` 保存可精确查询的身份，并在需要时用 `bindings` 在 `/data/state` 引用定义的类型和准确修订。精确 ID 与引用并存时由写入方检查一致性。一次新的感知不能覆盖上次观测，即使两次都连接到相同 `STATE`。更正既有观测时用新记录和证据引用说明与原记录的关系。

`data.observedAt` 表示实际观测时间，`data.validUntil` 表示已知有效期。时间值使用带明确时区的 ISO 8601 时间，确实未知时以显式 `null` 或上层问题状态表示，不从 `createdAt` 或 `updatedAt` 推断。用实体顶层 `source` 保存可定位的实际来源，`evidence` 保存能核查的实体引用，`scope` 保存观测适用范围。可用时记录 `data.confidence`，未知时保留未知。当前查询不能凭空补齐时间、来源、范围或可信度。

仓储写入 `data.kind = world-state-observation` 和精确范围的 `data.scopeKey`，在 `/data/state` 绑定确切状态修订。生产装配选择支持条件写的 Neo4j。状态定义和观测分别条件写，第二次写入遇到同编号时核对原事件。若感知写入中断，允许使用原事件 ID 重试，已保存的标准状态定义可继续复用。

读取当前状态时按 `subjectId + predicate` 和适用范围选证据，核对时间和可信条件。历史记录仍可用于追溯。超过有效期、必要字段未知、同范围可信证据互相冲突，或所需引用修订不可取得时，向上层明确报告过期、未知或冲突。需要刷新时交由世界查询与能力执行模块处理。有效期缺失时由领域规则决定是否有其他时效依据，不能长期视为当前状态。

属性维度独立保存。例如空调 `connectivity = DISCONNECTED`，并且开关状态没有新鲜证据时，可以同时报告 `power = UNKNOWN` 和 `lastKnownPower = ON`。`UNKNOWN` 在此表示读取结论，`lastKnownPower` 是带来源和时间的历史值。条件和预期不能以断联或以历史值替代本次 `power = OFF` 的实际证据。

旧稿的状态读取、历史、感知刷新、验收及模型快照按 [23 世界查询与上下文](23-世界模型查询与上下文开发文档.md) 实现。该文档同时记录意图偏好、历史参考及维护与其他模块的接线。

## 字段引用

[FieldBinding](../../../src/main/java/com/example/myhelper/world/model/FieldBinding.java) 有两个字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `slot` | `String` | 从整个统一实体根部定位的 JSON Pointer 字段路径 |
| `target` | `EntityRef` | 被引用的目标实体 |

路径示例：`/text`、`/data/value`、`/data/attributes/room`、`/data/factors/0`。字段名中的 `~` 写为 `~0`，`/` 写为 `~1`，数组元素使用下标。

同一位置可以保留确定值和多个引用。只有抽象表达时，将直接值设为 `null`，通过引用关联已有语义内容。多个引用究竟是补充说明、候选还是共同约束，由字段的使用规则决定。

[EntityRef](../../../src/main/java/com/example/myhelper/world/model/EntityRef.java) 保存：

| 字段 | 含义 |
| --- | --- |
| `id` | 目标实体稳定编号 |
| `revision` | 固定的目标修订号；为 `null` 时只引用身份 |
| `worldObjectType` | 目标世界对象类型 |
| `contextUnitType` | 目标世界陈述类型 |
| `unitType` | 目标能力类型 |
| `semanticType` | 目标语义类型 |

引用的四个类型字段也必须且只能填写一个，并与目标实体对应。需要复现的证据应固定 `revision`。

引用保存编号和类型，语义实体可以继续持有引用。世界读取按调用方提供的逐跳 slot、来源和授权展开，保留直接值和各条引用路径，并在遇到循环或预算上限时返回明确结果。执行图的防环继续由执行模块处理。 [世界引用展开](23-世界模型查询与上下文开发文档.md)

## 向量表示

[Embedding](../../../src/main/java/com/example/myhelper/world/model/Embedding.java) 保存三个字段：

| 字段 | 含义 |
| --- | --- |
| `model` | 生成向量的模型名称 |
| `modelVersion` | 模型准确版本或权重摘要 |
| `values` | 向量分量，列表长度即维数，元素必须是有限数 |

任何类别的实体都可以附带向量。向量相似度用于表达语义相关程度，精确连接通过实体编号和修订完成。修改被向量化的内容后，需要重新生成或清空旧向量，避免内容与向量不一致。

## 链路位置数组

[ChainPosition](../../../src/main/java/com/example/myhelper/world/model/ChainPosition.java) 是 `WorldEntity.chainPositions` 的数组元素，不是新的世界实体类别。每条记录描述当前实体在某份固化链路中的一次使用位置。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `chainId` | `String` | 直接包含该使用位置的组合 Unit 稳定编号 |
| `chainRevision` | `long` | 链路精确修订号，从 1 开始 |
| `branchPath` | `List<String>` | 从外到内的分支编号路径；主干使用空列表 |
| `nodeId` | `String` | 该链路版本内的一次出现编号，不是被调用 Unit 的编号或数组下标 |
| `statistics` | `ExecutionStatistics` | 所属实体版本在该链路版本、该位置下的独立执行统计 |

同一个 Unit 在同一条链路两个位置使用，就保留两条记录。分支路径支持任意有限层数，构造时复制为只读列表；分支编号不能为 null 或空白。

局部 JSON 示例：

```json
{
  "chainPositions": [
    {
      "chainId": "unit:chain-a",
      "chainRevision": 3,
      "branchPath": ["branch-1", "branch-1-2"],
      "nodeId": "n7",
      "statistics": {"successCount": 0, "failureCount": 0, "failureCauses": []}
    },
    {
      "chainId": "unit:chain-a",
      "chainRevision": 3,
      "branchPath": ["branch-2"],
      "nodeId": "n12",
      "statistics": {"successCount": 0, "failureCount": 0, "failureCauses": []}
    }
  ]
}
```

正式字段位于实体顶层，不放在 data.chainPositions。WorldEntity 构造器将 null 数组保存为空列表，并复制非空数组。原 16 参数和 17 参数构造器继续可用，未传入的 statistics 默认空统计；原四参数 ChainPosition 构造器也保留，默认空统计。当前完整构造器在链路位置数组之后接收实体 statistics。

位置数组中的定位信息可以从链路结构派生，statistics 则记录执行结果，重建索引时不能丢弃或清零已有统计。完整节点、连接、条件和参数映射仍由组合能力的链路定义保存；本字段不会自动填充、反查、读取历史版本或展开整条链路。实体在不同修订中独立保存使用位置及统计。

## 执行统计与失败归因

[ExecutionStatistics](../../../src/main/java/com/example/myhelper/world/model/ExecutionStatistics.java) 同时用于实体和链路位置：

| 保存位置 | 统计范围 |
| --- | --- |
| `WorldEntity.statistics` | 当前实体 id/revision 的总体结果；组合 Unit 表示整条链路，原子 Unit 可表示该版本能力的总体结果 |
| `WorldEntity.chainPositions[i].statistics` | 所属实体版本在 chainId/chainRevision/nodeId 这个使用位置的结果 |

统计字段为 `successCount`、`failureCount`、`failureCauses`。次数均为非负 long。空统计为 0、0、空列表，表示尚无已记录结果。统计按实体修订和链路位置分别保存。

[FailureCause](../../../src/main/java/com/example/myhelper/world/model/FailureCause.java) 保存每项归因：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `causeId` | `String` | 稳定的原因编号，可复用原因定义 |
| `category` | `FailureCategory` | 计划问题、环境问题或尚未查明 |
| `reason` | `String` | 原因或失败现象描述 |
| `analysis` | `String` | 分析说明，未知时为 null |
| `occurrenceCount` | `long` | 该原因在当前统计范围内出现的次数 |
| `evidence` | `List<EntityRef>` | 支持归因的证据，需要复现时固定修订 |

[FailureCategory](../../../src/main/java/com/example/myhelper/world/model/FailureCategory.java) 包含 `PLAN`、`ENVIRONMENT`、`UNKNOWN`。UNKNOWN 指失败原因尚未分类，不表示执行结果未知。执行结果未知不能直接当成失败计数。一次失败可能有多个原因，也可能尚未归因，因此 occurrenceCount 之和不要求等于 failureCount。

共享 causeId 不共享出现次数。实体总体、各链路位置以及不同版本分别持有统计。位置统计按所属实体 revision 和链路 chainRevision 定位，记账不会自动改变能力定义 revision。定义变更后的统计迁移、并发更新、事件去重和历史留存由后续逻辑处理。

用户要求的记账语义以本轮结果分别记录，例如 A 成功、B 失败、C 未执行：

| 范围 | 成功次数变化 | 失败次数变化 |
| --- | --- | --- |
| 整条链路 | 0 | +1 |
| 位置 A | +1 | 0 |
| 位置 B | 0 | +1 |
| 位置 C | 0 | 0 |

整链成功时，整链与实际成功的参与位置分别记录成功；未执行的位置不变。表格描述未来业务模块的记账要求，构造器没有实现自动累加、逐级传播、归因分析或可靠度计算。

### 可靠度统计合同

2026-11-15 用户确认，普通固化技能和受信任的第三方 MCP 原子工具使用同一公式。评分使用当前技能修订和本次入参命中的已验证范围内的数据。

```text
可靠度 = (初始可靠度 × 初始权重 + 实际成功次数)
       / (初始权重 + 实际成功次数 + 实际失败次数 − 已确认非方法失败次数)
```

| 输入 | 口径 |
| --- | --- |
| 初始可靠度 | `ToolReliability.Prior.successRate` 为有限 `double`，取值 `[0, 1]`。来源明确采用 `0–100` 分制时，供给方按原值除以 100 转换 |
| 初始权重 | `ToolReliability.Prior.weight` 为非负 `long`，单位是等效执行次数。普通固化技能为 0。受信任的第三方 MCP 原子工具按具体接入实例、实现版本及适用范围配置 |
| 成功、失败次数 | 累计实际确认的执行结果。已确认的非方法失败仍保留在原始失败计数和归因中 |
| 已确认非方法失败次数 | 对同一统计范围内确认应排除的失败执行按执行身份去重，一次最多排除一次，且排除数介于 0 和实际失败次数之间。归因未知的已确认失败仍计入分母 |

分母为 0 时，`ToolReliability.score` 返回 `OptionalDouble.empty()`，表示证据不足。生产 `Lookup` 负责按执行身份核对并去重，向评分传入 `Sample.externalFailures`。一个失败执行可能有多项归因，仅凭归因汇总的 `occurrenceCount` 无法得出排除数。结果未确认、未执行和门禁拦截的动作维持原始计数。

`WorldEntity.statistics` 与 `ChainPosition.statistics` 保存各自范围的实测结果。先验由工具目录提供，作为 `Lookup` 命中时的 `Sample.prior` 传给评分组件。世界模型无需新增字段。生产 `Lookup` 与目录先验来源待装配，`0.95` 和权重 `20` 是演算示例。 [工具管理的先验设计](../tools/25-工具管理与隔离运行设计.md#6-工具可靠度先验)

技能模块已实现先验加权计算。已有检查覆盖先验冷启动、结合实际计数计算和零有效样本返回空，独立检查共 142 项 JUnit 和 4 组存储检查通过。 [评分实现](../../../src/main/java/com/example/myhelper/skill/ToolReliability.java) · [检查记录](../../../checks/README.md)

## 当前结构检查

现有构造器检查实体和引用的编号、四个类型字段的互斥、修订号范围，以及字段引用的基本形式。ChainPosition 检查链路编号、链路修订、分支编号和位置编号；执行统计检查非负次数，失败归因检查编号、描述及非负归因次数。向量结构检查模型名称、模型版本、非空向量和有限分量。

目标实体是否存在、引用类型是否与目标一致、slot 是否指向真实字段，以及来源、证据、时效、合同是否充分，需要后续模块验证。当前实体层不执行工具、不生成向量，也不决定能力是否允许复用。

世界模型源码包含统一实体、四个类型枚举、引用/向量、链路位置、执行统计、失败归因及归因类别，共十二个 Java 文件。字段中文注释直接放在字段声明上方。
