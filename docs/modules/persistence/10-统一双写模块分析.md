## 用户已确认的边界

本模块只负责数据库读写、统一提交、失败补偿和错误报告。读取来源、写入目标由调用方明确指定；不根据 WorldEntity 或 EntityRef 的类型选库，不增加引用展开，不解释强弱引用的业务含义。实体类型到存储位置的映射由上层另行设计。

两个库均可保存实体内容和引用。实体的类型、embedding 是否存在，都不能改变调用方指定的目标。仅实际有写入数据的库参与操作；涉及两库时协调提交和补偿。

模块划分用于隔离职责、便于修改，当前为普通 Java 包，无独立启动或 HTTP 接口要求。后续模块同样遵守。新任务务必维护自己的文档，并同步总接续文档；务必写好职责、参数、关键流程和失败边界注释，字段注释放在声明上方。用户进一步要求本模块逐行注释：当前各生产类的字段、方法和执行语句均在上方添加中文说明，并展开原先一行多个语句的写法。

## 当前接口

2026-11-13 用户确认：单次主流程、并发循环、模型适配器及其配套模块，从数据库查询和保存都必须经过本模块。业务模块可以保留仓储/端口及内存缓存，但不能另建 Neo4j/Qdrant 客户端或直接发送数据库请求。数据库配置继续复用 `PersistenceConfiguration` 和 `application.yml`。

对外提供 **5 个查询签名（4 类操作）**，均为 Java 方法，不是 HTTP 接口：

| `DualWriteStore` 方法 | 已实现功能 |
| --- | --- |
| `read(Database, String)` | 指定库按 ID 读取当前完整实体；缺失返回空 |
| `read(Database, EntityRef)` | 读取该引用目标本身，核对四个类型字段和可选 revision；不匹配返回空，不展开后续引用 |
| `readBatch(Database, List<String>)` | 两库均一次批量请求，按输入首次出现顺序返回只读 Map；缺失省略、重复去重、空批次不访问数据库 |
| `query(Database, StorageQuery.PageRequest)` | 两库均在服务端按字段条件筛选、按 ID 分页，返回完整实体与续页游标 |
| `search(Database, StorageQuery.VectorRequest)` | Qdrant 按显式向量、模型/版本、可选条件及分数阈值返回实体与分数；指定 NEO4J 明确报不支持，不自动换库 |

保存继续使用 `write`、单库 `writeBatch` 和跨库 `writeBatch(Map<Database,List<WorldEntity>>)`。实体内容由上层组织，存储入口不替记录、画像或能力模块解释业务合同。只读操作不持有写入协调锁，可由多个循环分支并发调用；批次写入仍在同一共享协调实例内串行补偿。

`DualWriteStore.Database` 只有 `NEO4J`、`QDRANT`，是物理数据库标识，不是新增实体分类。

```java
// 显式指定单个实体的写入目标。
store.write(NEO4J, entity);
store.write(QDRANT, entity);

// 指定单库批量写入；另一库不参与准备、提交或补偿。
store.writeBatch(NEO4J, graphEntities);

// 两库可分别接收不同的数据，共用一次提交和失败补偿边界。
store.writeBatch(Map.of(
    NEO4J, graphEntities,
    QDRANT, qdrantEntities
));

// 同一实体需要存两库时，由调用方明确列入两边。
store.writeBatch(Map.of(
    NEO4J, List.of(entity),
    QDRANT, List.of(entity)
));

// 读取只访问指定库，缺失返回 Optional.empty，不自动回退到另一库。
Optional<WorldEntity> result = store.read(QDRANT, entityId);

// 上层明确指定引用来源；模块只读取这个目标，不展开引用链。
Optional<WorldEntity> referenced = store.read(NEO4J, entityRef);

// 按多个已知 ID 批量读取；这里的库由上层决定。
Map<String, WorldEntity> byId = store.readBatch(NEO4J, entityIds);

// 示例业务字段由上层定义，存储模块只执行条件。
var filter = new StorageQuery.Filter(List.of(
    new StorageQuery.Match("/data/taskId", List.of(taskId))
));
// 首次 cursor 为 null，后续原样传回 page.nextCursor()。
var page = store.query(NEO4J, new StorageQuery.PageRequest(filter, 100, null));

// queryVector 由上层嵌入服务生成；分数不表示可执行或确定事实。
var hits = store.search(QDRANT, new StorageQuery.VectorRequest(
    queryVector, embeddingModel, embeddingVersion, StorageQuery.Filter.all(), 20, 0.5
));
```

例子中的数据库标识可通过 `import static com.example.myhelper.persistence.DualWriteStore.Database.*;` 引入。

本轮移除了隐式选库的旧 `write(entity)`、`writeBatch(List)`、`read(id)` 签名。项目内调用已更新。空目标列表不产生数据库访问；同一目标内重复 ID 会在任何数据库访问前拒绝，同一 ID 可以由调用方明确写入两个目标。这里只按参数分派，不根据类型、向量或引用调整目标。

### 查询条件与分页边界

`StorageQuery.Match(pointer, values)` 使用实体的 JSON Pointer，例如 `/unitType`、`/data/taskId`、`/data/modelRef`、`/scope/tenant`。这些只是上层提供的查询参数，不构成实体类型到库的映射。条件间 AND，单个条件的 values 间 OR；支持字符串、布尔、有限数字等值与标量数组成员匹配。数字 1 和 1.0 等值，字符串 "1" 与数字不同。路径按 `~0`、`~1` 转义；不支持 null/缺失判断、范围、全文匹配、对象数组内关联、任意 Cypher 或引用遍历。向量坐标不建字段投影。

每次最多 1000 条，最多 32 个字段条件；不自动拉完整数据库。`Filter.all()` 可显式无条件分页。Neo4j 以最后返回实体 ID 接续，Qdrant 使用服务返回的 `next_page_offset`，两种游标不能跨库混用，也不应跨存储实例/条件复用。两库顺序互不等价，跨页没有快照保证；并发变更可能改变后续页面，因此此游标**不是持久事件消费位置或恢复租约**。

查询结果恢复完整 JSON，不截断引用/证据/统计。数据库错误、协议错误、缺失快照、ID 冲突、缺失分数向上抛出，不转成成功空结果。向量查询不生成 embedding，不加载权威版本，不审核发布状态；调用方按自己的业务合同使用结果。

### 字段投影与旧数据升级

保存时从完整 JSON 生成无业务含义的等值关键词：Neo4j `queryTerms`、Qdrant `payload.query_terms`。关键词编码字段路径、值类型和值；与完整实体同一条本地写入更新，失败补偿时一起恢复。Neo4j 使用参数化列表谓词，Qdrant 使用 payload `match.any`，过滤和页大小均由数据库执行。当前未创建额外物理查询索引，大规模查询性能及 Qdrant strict mode 的索引要求待真实服务验证。

旧记录没有此投影时，仍可按 ID、无条件分页和既有模型/版本过滤进行向量读取；新增字段条件无法匹配它们。升级方须显式用 `query(source, Filter.all() 的分页请求)` 分页读回，再通过 `writeBatch(source, page.entities())` 重写投影。应用升级期间须协调写入者，不能拿旧快照覆盖并发新数据。本轮没有擅自迁移真实数据库，也没有把无投影记录误称为已能按新条件检索。

## 实体与引用的保存

- `Neo4jEntityStore` 保存完整实体 JSON 与 revision；bindings 和 evidence 另外投影为 WORLD_REF 边，保留位置、类别、顺序和目标修订。完整引用中的四个目标类型字段保存在 JSON 中。图端点身份节点只是引用投影，不证明目标实体存在、属于 Neo4j 或其内容是确定事实。读取还原完整 JSON，不读取引用目标。
- `QdrantEntityStore` 将完整实体 JSON 保存在 payload.entity，保留正文、data、四个类型字段、bindings、evidence、source、scope、revision、时间及 embedding。原实体 ID 保存在 payload，点 ID 使用稳定 UUID 映射。读取使用完整 JSON，不按引用含义筛选或改写。
- 2026-11-10 世界模型新增顶层 chainPositions。EntityJson 使用统一 record 映射，未设置业务字段白名单；新字段随实体 JSON 保存，旧数据缺字段时由 WorldEntity 构造器将 null 归一为空列表。位置数组不自动投影为 WORLD_REF 边，不改变读取来源、写入目标或引用展开职责。本轮只静态核对，未编译或运行新字段往返验证。
- 同日新增 WorldEntity.statistics 和 ChainPosition.statistics，复用 ExecutionStatistics、FailureCause、FailureCategory。它们仍通过完整 record JSON 保存；旧 JSON 缺少 statistics 时由模型构造器设为空统计。本轮未修改存储代码或进行往返测试，自动记账、并发计数和统计/定义版本的一致性不属于当前读写实现。
- 指定写入 Qdrant 且 embedding 为 null 时，发送 `vector: {}`，保存只有 ID 和 payload 的点；更新会清除原来的向量而保留本次实体内容与引用。不会再删除整个实体点，不使用零向量或零维数组冒充向量。
- embedding 有值时，Qdrant 写入实际向量；Neo4j 仍按完整实体保存。向量存在与否不决定目标库。
- `EntityJson` 独立支持 record、嵌套 JSON 数据与 Instant，无需 Spring 启动。引用数据原样往返，强弱引用的解释及类型到库的映射属于上层。

当前读取各库的当前实体；没有增加引用展开或历史版本存储。`read(source, EntityRef)` 仅核对当前实体是否符合所需修订，不会查询已被覆盖的旧版本，来源仍需上层提供。

## 初始化与使用

新增 `PersistenceConfiguration`，复用 `src/main/resources/application.yml` 中现有数据库配置。上层 Spring Boot 容器扫描本包，或显式 `@Import(PersistenceConfiguration.class)` 后，可直接构造器注入 `DualWriteStore`、`Neo4jEntityStore`、`QdrantEntityStore`。装配类没有启动入口，不需要本模块独立启动。

```java
// context 为已经加载 application.yml 并注册本模块配置的上层 Spring 容器。
DualWriteStore store = context.getBean(DualWriteStore.class);
Neo4jEntityStore graph = context.getBean(Neo4jEntityStore.class);
QdrantEntityStore vector = context.getBean(QdrantEntityStore.class);
// 按实际使用的库显式初始化；仅用 Qdrant 时无需调用 graph.initialize()。
graph.initialize();
// 直接使用配置中的 vector-size 与 distance，无需在业务调用处重复填写。
vector.initialize();
store.write(QDRANT, entity);
```

| 配置 | 绑定方式 |
| --- | --- |
| `spring.neo4j.uri`、`spring.neo4j.authentication.username/password` | 复用 Boot 4.1.0-M2 的 Neo4jAutoConfiguration，创建并管理共享 Driver；已有 Driver Bean 时复用 |
| `spring.data.neo4j.database` | 可选；未配置时使用账号默认数据库 |
| `qdrant.host`、`qdrant.port`、`qdrant.collection` | 构造 REST 地址和集合路径，沿用当前文件的 localhost、6333、desktop-memory |
| `qdrant.vector-size` | 沿用当前文件的 768，绑定到无参数 initialize() |
| `qdrant.scheme`、`qdrant.distance`、`qdrant.request-timeout` | 在原文件补充 http、Cosine、30s；超时同时用于连接及单次请求 |
| `qdrant.api-key` | 在原文件以 `${QDRANT_API_KEY:}` 引用可选环境变量，空值表示不发送认证头 |

保留原手动构造入口供测试或非 Spring 场景使用；原六参数 Qdrant 构造器仍需调用 initialize(dimensions, distance)，新装配路径无需重复传集合参数。普通 AnnotationConfigApplicationContext 不会自动加载 application.yml，非 Boot 调用方须先把配置加入 Environment；配置检查程序演示了该流程。

容器装配只创建客户端和适配器，不创建集合或发起查询。initialize 创建图 ID 唯一约束、创建或检查 Qdrant 无名向量集合，需相应权限；现有集合不匹配时明确报错，不删除重建。Driver 和专用 HttpClient 生命周期由 Spring 管理，适配器不关闭共享客户端。单库操作不要求另一个库在线。episodes-collection 和 episode 等历史业务配置未接入此模块；集合业务用途、向量模型选择仍由上层负责。

## 提交与补偿

先复制并校验各目标的批次，再对非空目标按 NEO4J、QDRANT 的固定顺序取得写前快照并提交。全部参与分支成功后正常返回；失败则逆序补偿。单库操作同样支持失败补偿，但不会触及未指定的库。

`SnapshotParticipant` 恢复旧实体或移除本次新增内容；逐条尝试并汇总补偿错误。Qdrant 的无向量实体也有完整快照，可以恢复。Qdrant 写入、删除仅在收到 `completed` 后确认成功。传输中断或超时、只收到 `acknowledged`、回执损坏及未明确拒绝的服务器错误均标记为结果未知，明确拒绝的客户端错误按普通失败处理。`WriteFailure` 暴露操作编号、原始异常和补偿异常，原写结果未知或任何补偿失败时，`rollbackCompleted()` 返回 false，即使尽力补偿的请求已经成功。上层以操作编号及原目标跟踪核对，确认迟到写的影响后再决定是否重试。

这是同步快照补偿，允许中间状态可见，不是跨库原子事务或标准 TCC。要求一个共享协调实例独占同一实体的写入；没有跨进程锁、持久化操作日志或崩溃自动恢复。超时迟到请求及补偿失败仍需要调用方处理，不能保证所有故障均已回滚。未增加业务流程重跑、引用修复、业务清理策略或后台重试。

## 2026-11-15 跨窗口数据访问核查与条件写入

**用户确认：**核查其他窗口的数据操作，缺少的数据库能力由本模块直接提供，并通知所属窗口同步接线。当前源码扫描未发现 persistence 包之外直接创建 Neo4j/Qdrant 客户端、发送数据库 HTTP 或写本地业务文件；实际缺口是固化、可靠度、任务记录等生产仓储仍只有端口。内存模型绑定、Future、内容缓存或纯统计计算不是绕库写入。

**已实现：**新增两个明确指定目标的单实体条件写签名：

    // true 为本次确认提交，false 为目标 ID 已有内容。
    boolean created = store.writeIfAbsent(NEO4J, candidateEntity);
    // 完整旧快照仍一致才更新，不只核对业务 revision。
    boolean changed = store.compareAndSet(NEO4J, previouslyReadEntity, replacementEntity);

上层生成稳定 ID 和实体内容、选择目标。QDRANT 明确报不支持，不退化为“先查后覆盖”。Neo4j 先检查 WorldEntity.id 唯一约束，缺少时拒绝；部署先显式调用 graph.initialize()，本方法不隐式修改 schema。事务内通过临时属性取得数据库节点写锁并移除该属性，持锁后读取完整 JSON，条件满足才在同一事务写正文、queryTerms 和 WORLD_REF。引用占位节点没有 JSON 时视为实体内容不存在。[Neo4j 锁机制依据](https://neo4j.com/docs/operations-manual/current/database-internals/concurrent-data-access/#_lost_updates)。

比较按完整 JSON 结构进行，兼容旧记录缺省字段，与 read 的还原一致；对象字段顺序不影响比较，统计变化也会检测。旧值与替换值必须同 ID。false 表示观察到前置状态不匹配，上层应重新读取、决定重算；不在事务里执行 LLM、嵌入或业务回调。传输异常仍可能结果未知，不能断言从未提交；重放首次创建返回 false 也应读回辨认已有内容。

**边界：**仅一个 Neo4j 实体及其投影的本地原子操作，不是多实体事务 API、跨库条件事务、恰好一次、租约/fencing 或持久工作队列。更新者应遵守同一条件写合同；普通覆盖写及原跨库快照补偿仍有单写者限制，不能并发混用后声称 CAS 保护全部路径。范围、资格、审核、事件去重、业务重算和画像评分仍归上层。
