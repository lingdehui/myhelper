## 当前职责

2026-11-13 数据库边界确认：所有 Neo4j/Qdrant 查询和保存均走 [DualWriteStore](../persistence/10-统一双写模块分析.md)。本类没有直接数据库访问，本轮未改变单次调用逻辑。需要历史消息、世界实体、能力或记录时，由上层业务模块用指定库的 read/readBatch/query/search 准备输入，保存也由对应业务模块调用统一 write/writeBatch；不在 AgentCaller 中隐式选库、展开引用或增加一次查询。

每次调用只请求一次指定的 LLM；根据执行模式，直接返回模型响应，或者执行响应中的工具调用后返回。下一轮由上层准备入参并发起。本模块不承担业务门禁、任务规划、世界模型查询或技能固化。

现有 `call(Request, scopedTools)` 和 `CALL_ONLY` 已接入规划，也可作为后续模型验收的调用入口。当前 `AgentCallerPlanner` 归编排，结构化验收、任务进度与恢复由独立模块管理的方案仍待实施。通用用量、底层时限、取消及调用关联为单次侧后续建议。见[任务验收方案第 7 节](../../planned/26-任务验收进度与断点恢复设计.md#7-架构与两个主流程窗口的分工)。

当前 `ConfiguredModelAdapter` 已实现模型筛选、分支绑定和客户端解析。它实现了 `Function<String, ChatModel>`，装配方可将同一实例直接传入 `AgentCaller` 和编排器。编排侧拿到的 `Binding.modelRef` 随请求进入 `AgentCaller`，由解析函数定位已配置的 `ChatModel`。直接调用单次模块也可注入自己的解析函数。见[模型适配器](../llm/27-模型适配器开发文档.md)。

编排器九参数构造显式接收 `ModelAdapter`。八参数构造可执行无需模型的入口固化，进入模型路径会报告未装配。根运行在需要绑定时按需打开会话，实际工作结束后关闭。已打开会话的运行可以继续执行纯工具计划，该计划无需为自己分配模型。见[循环说明](../orchestration/12-并行分支循环编排设计.md)。

## 输入与输出

- 构造参数：模型解析函数 `Function<String, ChatModel>`、已注册的 `ToolCallback` 集合。
- `Request.modelRef`：本轮模型引用，交给模型解析函数获取已配置的模型。
- `Request.messages`：本轮消息列表，包括当前文本、必要历史和上一轮工具结果或失败反馈。
- `Request.toolNames`：本轮可用工具名，不能为空引用；不使用工具时传空列表。
- `Request.mode`：`CALL_ONLY` 或 `CALL_AND_EXECUTE`。
- `Result.response`：保留文本和结构化工具调用的模型原始响应。
- `Result.messages`：加入模型响应及已执行工具结果后的消息列表。
- `Result.executionAttempted`：是否进入工具执行阶段，不代表工具全部成功。

`CALL_ONLY` 返回的工具调用尚未执行；上层需处理对应结果，再把完整消息交给下一轮模型。工具执行异常转换为失败文本，模型调用及协议错误抛给调用方；本模块不自动重试。

## 实现与版本边界

面向项目当前的 Java 25、Spring AI 2.0.0-M3。通过 `internalToolExecutionEnabled(false)` 禁止模型内部自动工具执行，再按模式显式调用 `DefaultToolCallingManager.executeToolCalls`，执行完成后直接返回。

在执行任何工具前检查整个响应的工具名集合，拒绝本轮未提供的工具。要求模型只返回一个候选响应。代码已在主要语句上方逐行添加中文注释。

## 外层循环与能力复用接入（2026-11-10，已实现）

上层 `AgentOrchestrator` 通过 `AgentCallerPlanner` 调用本类。规划器在消息中提供普通工具合同、目标、参数、候选和历史执行反馈，模型用 `submit_plan` 提交计划，`TASK` 步骤由编排器递归求解。成功案例和世界上下文服务尚未接入。

[固化检索模块](../capability/19-固化检索与缓存开发文档.md)在根入口按用户目标召回一次；每次模型返回 PLAN 后，再根据 LLM 给出的总体任务与子任务重新检索数据库，匹配整条/子节点并保存本计划绑定。递归子任务和下一轮不重复入口检索。可直接执行的能力无需额外调用 AgentCaller；缓存命中仍需参数及门禁检查。

已增加 `call(Request, Collection<ToolCallback> scopedTools)`：工具仅合并到本次调用，不修改全局注册表，重名拒绝；旧 call(Request) 委托此重载。增加 toolDefinitions(toolNames)，让规划适配器读取普通工具合同。两种模式都在返回/执行前校验请求 ID 非空且不重复、工具名属于本轮允许集合，补齐原 CALL_ONLY 早返回的缺口。

规划请求采用 `CALL_ONLY`，实际开放的请求级工具是 `submit_plan` 和 `finish_task`。即使普通工具白名单为空，`AgentCallerPlanner.requirements()` 也会声明 `TOOL_CALLING`，供模型适配器筛选根模型和分支候选。规划器解析唯一一条原生工具调用中的 JSON 参数，外层再调度执行、验收或恢复审核。下一轮消息由规划上下文组装，可包含历史反馈、任务身份、当前阶段和外部恢复快照。这些数据经 `Request.messages` 传入。见[循环主流程](../orchestration/12-并行分支循环编排设计.md)和[执行链路](../orchestration/13-执行链路记录开发文档.md)。

Result 原有三个字段保持不变，未增加统一用量 DTO；运行上下文与结构化 Outcome 放在外层。CALL_AND_EXECUTE 仍用框架管理器执行，未迁移到新调度器。新增测试覆盖 CALL_ONLY 拒绝未允许工具及重复调用 ID，另有循环到真实 ToolCallback 的替身模型集成检查。实际测试运行记录见接续文档；没有真实 LLM 联调，未改环境配置。
