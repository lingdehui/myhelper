## 装配边界

[MyHelperApplication.main](../../../src/main/java/com/example/myhelper/MyHelperApplication.java) 启动非 Web Spring Boot 容器，默认关闭旧 MCP 客户端。Spring AI 根据现有配置提供对话客户端，`AgentCaller` 和 `AgentOrchestrator` 共用模型适配器。模型端点在编排器需要模型决策时才收到请求，并需支持 `submit_plan` 与 `finish_task` 工具调用协议。 [模型适配器和装配示例](../llm/27-模型适配器开发文档.md)

[TaskRuntimeConfiguration](../../../src/main/java/com/example/myhelper/interaction/TaskRuntimeConfiguration.java) 创建工作池、独立计时器、内存执行图、编排器与统一输入入口。默认使用四个工作线程、128 个排队位置、两分钟根任务时限。编排预算、工作池及执行图容量由 `myhelper.orchestration` 下的配置覆盖。输入任务真实收尾后释放对应内存图。

默认业务工具列表为空，模型结果仅做结构检查。宿主注册业务动作时提供 `ToolDirectory.Binding`、匹配的目录登记、`RuntimeGate` 和资源解析器，规划与执行共享同一批绑定。能力检索、使用检查和可靠度通过端口 Bean 装配。正式任务仓储与恢复默认启用，TaskRecoveryConfiguration 导入共享存储和 RecordsConfiguration，并接入启动扫描；数据库故障明确报告。固化业务仍按所属模块装配。

当前显式检查入口为 [checks/run.ps1](../../../checks/run.ps1)，运行说明见 [checks/README](../../../checks/README.md)。它用已有 JDK/依赖重新编译检查，并将输出放在 checks/build；不改变生产装配、不下载依赖，也不把根工程零测试当作检查通过。

模块使用同一进程内普通 Java 包及按需 Spring Bean；数据库配置装配已有实现，见[10](../persistence/10-统一双写模块分析.md)。新增组件由统一入口注入：模型注册、单次调用、能力仓储/缓存、门禁、执行器、链路存储、编排器、交互。避免每个子任务创建连接池、线程池或重复工具注册表。

模型及工具执行配额、任务轮数/时限/递归深度、缓存条数/字节/TTL、链路保留策略均使用独立配置。不得硬编码真实密钥。保持用户当前 SDK/IDE/仓库环境；确需改变时单独处理。

## 存储与恢复

2026-11-13 已统一数据库入口：业务模块只注入共享 `DualWriteStore`，查询/保存均通过其显式来源/目标接口。固化仓储现可通过 `CapabilityRepositoryConfiguration` 注入共享 `textEmbedding` 和 `DualWriteStore`，连接地址、密钥、超时与集合不再在能力模块重复配置，继续复用 application.yml。模型画像在选型回调外预加载后供本地快照读取；记录生产仓储仍待实现。新增字段条件依赖写入时生成的 queryTerms/query_terms，旧数据先通过无条件分页及统一写入重建投影，升级需协调写入者；本轮未迁移真实库。详见[10](../persistence/10-统一双写模块分析.md)。

当前 DualWriteStore 是同步提交与补偿，不是跨库原子事务，不含持久化日志和跨进程锁。新检索索引、历史能力修订、执行链路日志及运行恢复均需明确适配与验证。

首版可选择单进程运行；重启后只能恢复有持久证据的状态。运行中/副作用未知的动作先核对，不能读到未完成记录就重跑。优雅停机停止接受新任务、请求取消或等待有界收尾、保存检查点、关闭受管资源。

2026-11-12 已提供 [TaskRecoveryService](../../../src/main/java/com/example/myhelper/application/TaskRecoveryService.java)：应用可调用 resumeAvailable(limit)，向同一记录模块取得有界候选、去重并逐个恢复，单项受理失败不影响其他候选。服务不预先领取，resume 内部唯一 beginRun；扫描后暂停或被其他实例领取仍须在绑定时拒绝。该组件不是 main 或后台定时任务，生产候选查询、失联检测与领取实现仍待接入。

生产恢复条件：明确暂停或取消的原目标不自动恢复。进程强杀不依赖退出钩子，记录模块保存检测依据；租约到期不证明远端动作停止，先核对未闭合动作。正常收束或受控接管后开启新 rootRunId，沿用 taskId，加载最新指令、实际进度与证据。恢复扫描、退避和唤醒不放到 AgentCaller。完整目标见[26 第 10 节](../../planned/26-任务验收进度与断点恢复设计.md)，实际接口与限制见[28 第 10 节](../records/28-执行记录与恢复端口开发文档.md)。

## 集成验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 新目标无固化 | 模型规划、工具执行、验收、链路完整 |
| 规划前整条命中 | 条件满足时直接执行，无隐藏规划调用 |
| 规划后子节点命中 | 按 LLM 子任务目标重新查库，能找到规划前未召回的固化；匹配节点不再额外规划，未命中部分继续求解 |
| 两个独立子任务 | 同时推进，快分支不被慢分支整轮阻塞 |
| 数据依赖与共享桌面 | 依赖/资源约束被遵守，等待不耗尽工作配额 |
| 新固化发布 | 下一根入口或本任务下一次 PLAN 后检索发现，缓存没有全量增长 |
| 固化停用 | 新调用开始前核验并拒绝，已发生副作用如实报告 |
| 指令修订与取消 | 旧计划不提交新动作，迟到结果保留且不推进旧计划 |
| 局部失败及未知效果 | 不重跑已成功部分，不盲目重试未知副作用 |
| 离线模式 | 仅使用明确本地可用依赖，远程工具不可用如实报告 |

## 2026-11-15 可靠度配置装配

导入 ToolReliabilityConfiguration 并提供 SkillRuntimeConfiguration 的 ToolReliability Bean 后，应用可把所得 ToolReliabilityGate 注入 AgentOrchestrator。配置分别控制严格评分门限和普通工具的累计成功次数，默认大于 0.85 且至少 5 次成功。未提供查询时回模型。启用固化业务还需生产 Matcher、业务门禁、记录仓储及初始化；新库需准备 Neo4j ID 唯一约束和 Qdrant 集合。详见[循环模块](../orchestration/12-并行分支循环编排设计.md)和[统一存储](../persistence/10-统一双写模块分析.md)。

## 2026-11-17 正式任务恢复装配

正式入口默认要求 Neo4j 可用，并初始化实体 ID 唯一约束。配置 myhelper.records.enabled 默认 true；recovery-batch-size 默认 4，不能超过执行图容量。state-directory 缺省为用户目录下 .myhelper/task-runtime，同一安装固定使用同一路径。进程独占锁保留至 JVM 退出，只核对本安装的旧领取。后台分批恢复沿数据库游标推进，等待本批实际收尾并释放图；新任务和恢复任务由 TaskEntry 统一管理。停机使用 stopForShutdown，保留用户原目标，不改写为用户 CANCEL。

数据库不可用时不会退回内存模式。明确需要无持久恢复的独立演示才设置 --myhelper.records.enabled=false。文件锁不能证明远端动作结束，未核对的动作先保留证据并阻止原样重派。启动扫描不是永久重试服务，受理或收尾失败保留候选供显式恢复或下次启动。详见[记录模块第 13 节](../records/28-执行记录与恢复端口开发文档.md#13-2026-11-17-正式持久任务与启动恢复已实现)。

2026-11-17 装配边界整改：`TaskRecoveryConfiguration` 从已取得的 `TaskProcessLock` 创建 `records.TaskRecordOwner`。`RecordsConfiguration` 只接收此身份数据，不再反向依赖具体应用锁；文件锁仍保留至 JVM 退出。记录模块支持注入独立 `ToolReplayPolicy` 和 `ReviewPolicy`，前者只在 CAS 内作本地判断，后者在 CAS 外核验。当前接口、实现及验证进度见[记录模块第 15 节](../records/28-执行记录与恢复端口开发文档.md#15-2026-11-17-恢复策略边界与可读性整改)。
