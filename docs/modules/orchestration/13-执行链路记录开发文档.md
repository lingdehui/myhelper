## 当前实际实现

2026-11-12 用户确认模块归属：执行记录和恢复事项管理属于独立模块。循环已通过端口发送执行前数据、实际返回、异常与验收结果，并查询进度和待恢复数据。数据关联、权威状态管理、持久化、去重、恢复领取和等待队列由外部实现负责。现有 `ExecutionTraceStore` 位于 orchestration 包不改变其记录模块职责。

2026-11-12 分支模型接入：`STEP.input` 记录 `branchId` 和 `parentBranchId`，`MODEL.input` 另含 `modelRef` 和 `modelAssignment`。模型绑定由独立的 `ConfiguredModelAdapter` 会话提供，分支身份是逻辑 ID。纯工具计划内的步骤沿用计划所有者的分支，保留步骤及依赖记录，执行本身不创建模型请求记录。`SEARCH.input.enabled` 区分未启用检索和已启用但无候选。节点和边目前保存在内存。见[模型适配器](../llm/27-模型适配器开发文档.md)。

`ExecutionTracePort` 沿用 `open/add/edge/finish/close/snapshot`，DTO 暂引用 `ExecutionTraceStore`，`remove` 仍是内存实现自己的归档后清理方法。`TaskRecordPort` 提供 `create/load/beginRun/query/append/review/endRun`；`RunRecordAccess` 仅做身份和生命周期接线，不保存第二份任务进度或待办状态。本地验证使用记录替身，生产持久实现待完成。[记录与恢复端口](../records/28-执行记录与恢复端口开发文档.md)

任务事件的 `eventId` 独立去重，关联稳定 `taskId`、本次 `rootRunId`、子任务 `runId`、节点和分支；工具节点 `nodeId` 同时作为 `operationId`。`INTENT/RETURNED/VERIFIED` 分别记录派发意图、实际结果和验收结论，`OBSERVED` 接收工具主动提供的前后证据，`MODEL_FAILED` 报告模型故障，`RUN_ENDED` 在真实在途工作结束后发送。各事件带完整 details，不能用下面内存图的轻量 `Event` 替代。

新增 `RECORD_QUERY` 和 `RECOVERY_REVIEW` 节点，分别表示外部快照查询与恢复结论审核；它们不计作 LLM 调用。`NodeStatus.WAITING` 表示当前等待外部条件。模型的恢复 `COMPLETE` 是带问题编号和快照版本的提案，只有外部审核能更新待办。`TaskRecordPort.disabled()` 明确无恢复保证，旧入口不会伪造持久任务或批准恢复。

模型适配器移交时增加 NodeKind.MODEL_SESSION，用于记录 release/close 失败；input 包含 phase、branchId，output 保留已执行结果，status 为 UNKNOWN。它不是实际 LLM 请求，不计模型请求数量。对外取消可能先返回，真实收尾发生的异常仍写入该运行图。计划绑定释放失败不会丢弃已执行产物或自动重新规划。

`runs: Map<String, Graph>` 按 rootRunId 保存运行图；每图为节点 Map、边 List、事件 List 和 closed 标记。公开入口为 open、add、edge、finish、snapshot、close、remove；所有访问通过 synchronized 串行化，snapshot 返回不可变深层 JSON 数据与只读集合。当前不是单独的事件处理线程，也没有 incoming/outgoing 索引或边 ID。

节点保存 id、runId、parentId、kind、goal、planRevision、input、status、output、error、startedAt、endedAt。kind 使用 NodeKind 枚举，值为 TASK、MODEL、MODEL_SESSION、SEARCH、RECORD_QUERY、RECOVERY_REVIEW、STEP、UNIT、TOOL、GATE、VERIFY；status 使用含 WAITING 的 NodeStatus 枚举；Edge.kind 使用 EdgeKind 枚举。Java 消费者应以枚举比较，已有 JSON 名称保持原拼写。finish 的 status 参数也使用 NodeStatus。COMPLETED 表示模型/查询等动作正常返回，不等于业务 SUCCESS。事件 type 仍是由受控枚举名/创建事件常量产生的文本。STEP 的 input 保存 stepId、常量参数、bindingSources；TOOL 保存最终工具名和绑定后的实际入参；UNIT 保存命名空间、能力 ID 和 revision。边已接入 SPAWNED、DEPENDS_ON、DATA_FROM。

事件保存递增 sequence、nodeId、type、at。事件是轻量通知，不含完整节点变更载荷，不能据此重放历史快照；只有当前快照。当前 RUNNING 表示节点已纳入运行，其中包括等待依赖和排队阶段，startedAt 是建节点时间，不可作为真实工具开始时间或性能依据。后续若做统计或自动固化，需要进一步区分 PLANNED/QUEUED/实际开始，并补齐证据及验收关联。

构造参数限制运行图数、每图节点数、事件/关系数；尚无按字节大小限制。结束图由调用方消费/归档后显式 remove；活跃图拒绝删除。取消/超时可以先返回用户，但在途调用真实结束前图不关闭。主流程已接入取消后的迟到完成记录。

当前可用 `snapshot(rootRunId)` 在本进程读取关系；任务外固化的正式数据源应是持久归档后的固定快照和验收证据，该入库与读取路径尚未实现。发布技能仍需校验参数流、条件、结果和证据，不能把任何 RUNNING 或仅工具返回成功的节点自动发布。当前没有持久化、readSince、子图导出、eventId 去重、历史序号查询、用量字段或 VERIFIED_BY/RETRY_OF/SUPERSEDES 关系。

本地验证覆盖并发依赖边、参数流、快照不可变、取消后保留在途图。以下为尚待补齐的目标设计。

## 1. 职责与输入输出

接收编排、模型调用、工具执行、门禁及验收事件，建立每个根任务的执行图。输出不可变快照、按节点/子图查询、增量事件。它记录实际发生过什么，不负责规划或认定某段轨迹已具备复用资格。

建议入口：append(rootRunId, eventId, event)、snapshot(rootRunId)、readSince(rootRunId, sequence)、readSubgraph(rootRunId, nodeIds, sequence)。这些是新接口建议，不是当前类的方法。

## 2. Map 与集合

```text
ExecutionTraceStore
  runs: Map<RootRunId, ExecutionGraph>

ExecutionGraph
  nodes: Map<NodeId, ExecutionNode>
  edges: Map<EdgeId, ExecutionEdge>
  outgoing: Map<NodeId, Set<EdgeId>>
  incoming: Map<NodeId, Set<EdgeId>>
  events: 按 sequence 追加的事件流
  sequence: 本图最近应用事件序号
```

索引由 nodes/edges 派生，同一原子更新中维护。Map 不对外暴露可变引用。首版一个任务的事件由同一逻辑处理器串行应用；工作线程只提交事件。单用 ConcurrentHashMap 不能保证节点、边、状态多项更新的一致性。

## 3. 节点字段建议

| 字段 | 含义 |
| --- | --- |
| rootRunId、runId、nodeId | 根运行、所属子任务、具体执行节点身份 |
| parentNodeId | 谁创建了本节点；仅表达父子归属，不表示执行依赖 |
| planRevision、stepId | 当时的计划版本与逻辑步骤 |
| kind | TASK、MODEL_CALL、UNIT_CALL、TOOL_CALL、GATE、VERIFY |
| unitRef、implementationVersion | 能力及其固定版本、底层实现版本 |
| invocationId、modelCallId、toolCallId、attempt | 本次实际调用标识；重试建新节点，不覆盖旧结果 |
| input、outputRef、error、effectState | 输入快照、结果引用、结构化错误、副作用已知/未知 |
| bindingSources | 参数从哪个用户输入、上游结果或常量取得 |
| status、createdAt、startedAt、endedAt | 生命周期与时间 |
| scopeRef、contextSnapshotRef、evidenceRefs | 本次执行范围、所用上下文及证据版本 |
| modelRef、usage、duration、cacheSource | 模型、实际报告用量、耗时、缓存来源；缺失用量不可记为零 |

不要求把大文件、图像和全部原始响应塞进内存；保存受控结果引用及摘要。访问敏感参数按模块需要裁剪，仍保留可追溯的引用。

## 4. 边及语义

| 边类型 | 含义 |
| --- | --- |
| SPAWNED | 父节点创建子任务/调用 |
| DEPENDS_ON | 目标节点依赖源节点成功或指定结束条件，条件必须显式 |
| DATA_FROM | 目标参数从源结果的明确字段取得，保存字段路径 |
| VERIFIED_BY | 执行结果由哪个验收节点验证 |
| RETRY_OF / SUPERSEDES | 重试或计划替换关系，保留旧节点 |

节点完成时间先后不能推断依赖；依赖关系不能从工具名猜测。当前调度依赖需无环，审计关联边与世界知识引用可以有其他拓扑。重复工具调用 ID 可能在不同模型响应出现，定位时必须带运行和模型调用身份。

## 5. 固化消费者

固化模块读取固定 sequence 的已结束子图。提取步骤、参数流、依赖、版本、范围、执行前条件、验收证据；子图外的数据输入必须变成显式参数或保留的依赖，不得截掉再称完整能力。父任务失败不自动否定已独立验收的子图，但不能忽略失败暴露的限制。节点运行成功不等于业务验收通过。

支持导出一个已封闭且结果已验证的子图，其他分支仍可运行；禁止将尚未收齐结果的图快照自动发布为能力。

## 6. 生命周期与持久化

当前内存执行图只能保证进程存活期间的读取，不承诺恢复。生产记录以 [TaskRecordPort](../records/28-执行记录与恢复端口开发文档.md) 的持久确认、领取、版本审核和结束合同为实现入口；执行图增量读取、检查点与历史快照仍是扩展建议。它们不同于能力缓存，也不能直接假定 DualWriteStore 已有日志接口；长期映射到 WorldEntity 或专用运行存储的具体方案待定。

活跃图按任务预算限制节点数、深度、字节数；结束图归档后设置保留时间和内存淘汰。消费者用 sequence 游标去重，归档须确认记录可读取，不能先删内存再尝试保存。丢失完成事件时进入待核对，不自动重做有副作用的调用。

## 7. 验收

并发事件不丢节点/边；重复 eventId 不重复生效；快照能重现指定版本；失败、取消及迟到结果保留；重试不覆盖原节点；固化读取闭合子图；外部模块不能修改运行状态；达到容量限制时明确拒绝扩展；持久化未实现时不得宣称跨重启可恢复。

## 8. 与循环收尾、任务外固化的交接（2026-11-13）

技能固化窗口转来的分工已记录：循环在真实收尾时经 TaskRecordPort 提交最终执行记录；记录仓储的数据库查询/保存统一经过 persistence；固化模块在任务外消费已入库的固定图和验收证据，独立负责候选生成、审核与发布。循环不在结束回调里运行固化算法，也不直接创建数据库客户端。

源码现状：AgentOrchestrator.endRun 关闭模型会话和执行图，从支持快照的执行图端口读取固定图。RunRecordAccess 通过 RunFinalization 提交 RUN_ENDED、图或缺口。旧端口默认兼容实现只接收结束事件。RunArchivePort 已定义任务外读取合同，生产持久归档与消费装配待完成。参见[记录模块第 12 节](../records/28-执行记录与恢复端口开发文档.md)。

逐阶段事件未取得写入确认时，`evidenceGaps` 记录事件种类、节点身份和事件身份。收尾仍提交已有图、事实和产物，自动固化唤醒要求 `graphComplete` 与 `evidenceComplete()` 都通过。

后续归档应在真实工作和清理记录收齐后固定图，经任务记录端口提交；取得持久可读确认后再允许消费与内存清理。归档需带 taskId、rootRunId、固定快照身份/修订、来源节点和验收/证据关联，保留部分失败及未知结果。图内 Event.sequence 不等于 TaskRecordPort.eventId，也不能用普通数据库分页游标代替持久消费位置。具体已有标识、最终载荷建议、提交时机和生产缺口见[28 第 11 节](../records/28-执行记录与恢复端口开发文档.md)。本轮仅核对和补文档，未新增归档代码或重新执行检查。
