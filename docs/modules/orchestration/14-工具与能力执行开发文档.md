## 当前已实现接口

`SpringToolExecutor` 实现 `AgentOrchestrator.ActionExecutor`，接收工具名、已绑定 Map 参数及 CallContext。它按名称定位 ToolCallback，将 Map 转为 JSON，调用 `call(input, ToolContext)`；返回 JSON 可解析时转回对象，否则保留字符串。ToolContext 注入 rootRunId、runId、nodeId、deadline、cancellation，以及 taskId、operationId 和 executionContext。operationId 当前等于本次 TOOL 节点 nodeId；executionContext 为 CallContext，供工具报告事实。业务参数完整性由工具实现检查。

工具可在实际修改前调用 `CallContext.reportBefore(evidence)`，修改后调用 `reportAfter(evidence)`，分别发送 phase 为 BEFORE/AFTER 的 `OBSERVED` 事件。证据应来自真实资源观察，例如版本、哈希、备份引用、差异或远端操作编号。循环只冻结并转交这些数据，不自动备份文件、读取数据库旧值或猜测变化。记录启用时，执行前报告异常不得继续修改；记录禁用时该调用不提供持久确认保证。

ResourceResolver 根据实际入参提供资源键；同一执行器的固定条带锁协调多个任务。按锁序获取避免互相反向持锁，等待时周期检查取消。同名工具使用不同资源可以并发，不同工具共用同一资源则等待。该协调不负责自然语言任务拆分。

等待锁的取消检查间隔现为有说明的 LOCK_CANCEL_CHECK_INTERVAL_MILLIS 常量（50ms），不代表工具执行超时。主流程的 TOOL/TASK 分发改为 switch，工具动作独立到 executeToolStep；执行器逻辑语句已补上方中文注释，调度行为保持原约定。

工具返回统一 Outcome(status,value,error)。动作开始后抛出异常返回 UNKNOWN，动作未开始的异常为 FAILED。UNKNOWN 不自动重做；外部记录模块返回 CONSULT_MODEL 时才携带证据进入恢复决策，返回 WAIT 时报告 WAITING，无接续依据时保留 UNKNOWN。检查取消不保证外部动作已撤回。

组合执行由 `AgentOrchestrator.executePlan` 复用同一 DAG 调度，解析 TaskPlan 的 TOOL/TASK 步骤、依赖和 JSON Pointer 绑定。已匹配固化走 capability 方法，由独立 `CapabilityUsePort` 判断本次可用性后执行已有计划；兼容实现 `CheckedCapabilityUse` 组合权威版本检查和既有门禁。没有新增 executeUnit 模型工具或通用 EntityRef 解引用器。组合输出为 `stepId → {status,value,error}`，暂无自动结果投影；匹配策略必须检查替换步骤的输出兼容性。

AgentCaller 的旧 CALL_AND_EXECUTE 保留 DefaultToolCallingManager 路径；新循环使用 CALL_ONLY，由外层执行。两种路径不能同时执行同一响应；旧便捷模式尚未统一迁移到本执行器。以下各节为后续通用 Unit 合同，不代表已全部实现。

## 1. 职责

按明确能力引用和参数执行原子工具或组合能力，记录调用结果并发出链路事件。业务规划由模型或已有能力定义提供；执行器落实依赖和本次实际资源约束，不通过注册时的固定并发标志替代任务判断。

## 2. 输入输出建议

ExecuteRequest：runId、nodeId、unitRef（含 revision）、args、contextSnapshotRef、取消信号、deadline、幂等键（实现支持时）。

ExecuteResult：invocationId、status、output、errorCode、errorMessage、effectState、evidenceRefs、actualImplementationVersion。成功返回不直接宣告整个用户目标完成。超时或取消请求不证明外部执行已停止。

工具注册表保存名称、参数/输出合同、实现版本和实际回调；会话、文件等资源从具体参数及适配层获取。原子工具的说明可以有语义引用；它本身是否调用 LLM 另行声明和记录。

## 3. WorldEntity.data 合同建议

保持统一实体和四个独立类型，不在本轮修改世界模型源码。

| 类型 | 执行需要明确的内容 |
| --- | --- |
| TOOL / MCP_TOOL | 实现绑定、版本、输入输出合同、执行范围、必要条件和验收方式 |
| PLAN_STEP | 输入输出合同、steps、依赖、参数绑定、分支条件、条件/验收引用 |
| INTENT | 目标语义与实现候选引用，本身不作为空流程执行 |
| LONG_TERM_TASK | 目标及能力引用；运行游标另存执行链路，不写回共享能力定义 |

组合步骤建议含 stepId、unitRef、bindings、dependsOn。绑定只支持常量、顶层参数、上游结果的明确路径；字段路径必须可校验。条件语法首版限定为确定性谓词，未解析的自然语言条件回到求解流程。引用目标可有知识循环，当前组合展开须防止无界递归并受执行预算限制。

示意：A=queryOrders(date)、B=queryRefunds(date) 无相互依赖；C=exportCsv(A.rows,B.rows)，dependsOn=[A,B]。A、B 可以并发；失败时 C 不默认执行。使用分支和结果映射时，必须定义未选择分支、缺字段及空结果行为。

## 4. 工具入口

模型可见的执行入口建议为 executeUnit(unitId, args)，运行时绑定并记录确定 revision。编排入口提交目标子任务或明确能力调用，返回任务句柄。等待结果通过编排状态机处理，不在持有父任务配额时同步递归等待子任务。

LLM 普通工具与编排工具可以共用工具协议；不强制所有响应只能出现其中一种。执行前校验每项请求，父子关系由调用上下文注入，不能仅信任模型填入的 taskId。

## 5. 执行流程与失败

当前普通工具链路为：绑定参数 → 门禁与预算 → INTENT 确认 → 执行器取得资源并执行 → RETURNED 事实 → 验收 → VERIFIED 结论。工具内部可补充执行前后 OBSERVED。记录端口启用时，INTENT 保存失败会阻止派发；RETURNED 与 VERIFIED 分开保留，验收失败不会抹掉实际输出。生产持久保证取决于外部实现履行端口合同。

长时间排队后重新核对易变化条件、同桌面连续动作的会话级协调仍需具体执行合同支持。不同任务使用同一共享资源协调器。

组合能力子节点可直接调用执行器；只有存在未解决的目标/参数/分支时才请求模型。工具内部调用模型必须计入实际用量。“跳过规划模型”不等于该工具零 Token。

不盲目重试副作用未知的执行。已完成节点保留结果；“失败重规划只处理剩余工作”是设计要求，当前只通过反馈和提示词传给模型，尚未用持久要求进度或动作幂等强制保证。动作失败后的补偿由明确能力或上层策略提出，不能假定存在通用撤销。

2026-11-12 影响与恢复设计见[26 第 9 节](../../planned/26-任务验收进度与断点恢复设计.md#9-执行失败的影响记录优先处理与模型离线接续)。事件和证据报告入口已接通，工具的资源观察、前后版本/差异采集、核对与补偿能力仍需实现。FAILED 可能来自已执行后的验收失败，UNKNOWN 可能仍有远端在途写入，Java 锁释放不代表影响解除。补偿须检查当前版本，避免覆盖别人后续修改。循环不实现通用回滚，也不根据失败码冻结所有分支；按模型计划依赖与外部门禁落实执行关系。

## 6. 首版开发与验收

先把 AgentCaller 内工具执行职责抽成可复用实现，保持一次 LLM 调用边界；再接 Unit 解析和组合执行。旧便捷模式委托同一执行层，防止重复执行。

验收：相同参数引用得到正确结果；顺序/并发/汇合行为正确；空 INTENT 拒绝执行；同一能力多次调用产生独立节点；参数缺失、依赖失败和版本不符停止；明确已有能力路径无需 AgentCaller；嵌套 LLM 用量可追踪。

## 2026-11-11 可读性与统一文本维护

资源锁构造采用 for 循环，锁编号通过有序去重集合生成，保持原来的升序获取规则。工具固定失败反馈引用 LlmTexts，外部工具合同和实际返回内容保持动态来源。 共同规范见 [24](../../24-LLM文本与代码可读性规范.md)，本轮验证见接续文档。

## 2026-11-15 固化工具评分接线

固化定义里的 TOOL 在 bind 完整参数后先经 ToolReliabilityGate 调用 skill.ToolReliability.assess。评分严格高于配置门限（默认 0.85），且普通固化技能的累计成功次数达到配置门限（默认 5）后才直执。可信原子工具仅免除次数要求。分数或次数未达标、无适用统计或查询异常时，由父循环带实际结果调用模型。模型明确规划的普通工具保留原门禁及验收。评分失败产生判断事实，不伪造工具执行失败统计；没有通用回滚或跨计划去重保证。装配、记录和防止重复选择同一固化的细节见[循环主流程](12-并行分支循环编排设计.md#2026-11-15-固化工具执行前的可靠度判断已接线)。

`SpringToolExecutor.withBindings` 接收 `ToolDirectory.Binding(ref, callback)`。模型仍只提交调用名和参数。编排从实际执行器解析一次 `ToolRef`，按它查分并要求按同一版本派发。执行器从实际回调的绑定上报 `TOOL_BINDING`，供归档按相同身份记账。普通三参数构造仍可按名称执行，缺少版本绑定时回模型且不生成版本统计。
