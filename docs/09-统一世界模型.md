# 09 统一世界模型

> 共同开发规则（2026-11-11 用户确认）：固定 LLM 文本集中到 LlmTexts；不用 Lambda，以可读性选择循环、方法和 switch，允许 `case ... ->`。所有任务继续前阅读[24-LLM文本与代码可读性规范](24-LLM文本与代码可读性规范.md)。

世界模型用统一实体保存具体对象、世界陈述、能力和抽象语义。具体内容通过明确字段及引用形成图，抽象内容保留原文、来源和向量表示；两者可以互相引用，形成多层、分支和循环关系。

## 实体与类型

所有内容都使用 [WorldEntity](../src/main/java/com/example/myhelper/world/model/WorldEntity.java)。类型定义分为四个独立枚举，实体中有四个对应字段。

| 实体字段 | 独立枚举 | 当前取值 |
| --- | --- | --- |
| `worldObjectType` | [WorldObjectType](../src/main/java/com/example/myhelper/world/model/WorldObjectType.java) | `USER`、`ROOM`、`DEVICE`、`APPLICATION`、`FILE`、`SYSTEM`、`MYHELPER` |
| `contextUnitType` | [ContextUnitType](../src/main/java/com/example/myhelper/world/model/ContextUnitType.java) | `STATE`、`OBSERVATION`、`FACT`、`REQUIREMENT`、`EXPECTATION`、`INFERENCE`、`PERSONALITY` |
| `unitType` | [UnitType](../src/main/java/com/example/myhelper/world/model/UnitType.java) | `INTENT`、`TOOL`、`MCP_TOOL`、`PLAN_STEP`、`LONG_TERM_TASK` |
| `semanticType` | [SemanticType](../src/main/java/com/example/myhelper/world/model/SemanticType.java) | `CONTENT`，后续按需要扩展 |

每个实体必须且只能填写一个类型字段，其余三个为 `null`。例如，空调填写 `worldObjectType = DEVICE`；一次设备观测填写 `contextUnitType = OBSERVATION`；工具填写 `unitType = TOOL`；抽象描述填写 `semanticType = CONTENT`。

类型之间通过实体引用关联。设备的抽象用途可以引用语义实体；语义实体也可以继续引用设备、观测、能力或其他语义实体。

## 统一实体字段

| 字段 | Java 类型 | 含义 |
| --- | --- | --- |
| `id` | `String` | 稳定编号，内容修订时保持不变 |
| `worldObjectType` | `WorldObjectType` | 世界对象类型，非该类别时为 `null` |
| `contextUnitType` | `ContextUnitType` | 世界陈述类型，非该类别时为 `null` |
| `unitType` | `UnitType` | 意图或能力类型，非该类别时为 `null` |
| `semanticType` | `SemanticType` | 抽象语义类型，非该类别时为 `null` |
| `name` | `String` | 名称或标题，未知时为 `null` |
| `text` | `String` | 原始描述或语义原文，未知时为 `null` |
| `data` | `Map<String, Object>` | 类型相关的具体字段和语义引用位置 |
| `bindings` | `List<FieldBinding>` | 字段位置到其他实体的引用数组 |
| `embedding` | `Embedding` | 当前内容的向量表示，未生成时为 `null` |
| `revision` | `long` | 实体内容修订号，从 1 开始 |
| `source` | `String` | 消息编号、文档路径、URL、调用记录编号等准确来源 |
| `evidence` | `List<EntityRef>` | 支持当前内容的证据引用 |
| `scope` | `Map<String, Object>` | 明确适用范围，空映射表示未声明 |
| `createdAt` | `Instant` | 首次创建时间，未知时为 `null` |
| `updatedAt` | `Instant` | 当前修订更新时间，未知时为 `null` |
| `chainPositions` | `List<ChainPosition>` | 当前实体在固定版本固化链路中的使用位置；空列表表示尚未记录 |
| `statistics` | `ExecutionStatistics` | 当前实体 id/revision 的成功次数、失败次数和失败归因；null 默认为空统计 |

`data` 中可使用字符串、布尔、数字、`null`、嵌套 Map 和 List。构造器只复制 `data`、`scope` 的顶层映射，嵌套数据由写入方维护。

类型相关字段的用途示例如下。当前实体不自动检查这些键的业务合同。

| 类别 | data 中的内容示例 |
| --- | --- |
| 世界对象 | 型号、设备属性、组成、位置、控制关系 |
| 世界陈述 | `subject`、`predicate`、`object`、`value`、状态引用、置信度、观测时间、有效期 |
| 意图与能力 | 工具名称、工具版本、输入输出、前置条件、结果预期、实现描述、验证范围、失败限制 |
| 抽象语义 | 语义标签、补充描述、分解概念及继续引用的位置 |

## 陈述与现实状态

`STATE` 定义一种状态；它的存在不证明现实已经处于该状态。`OBSERVATION` 记录观测，`FACT` 记录事实陈述，`INFERENCE` 记录推断。`REQUIREMENT` 和 `EXPECTATION` 分别表达执行条件与验收目标。

例如，“空调已开启”可以是一条标准状态定义；某次读取设备后，另建观测实体，通过引用关联该状态，同时记录来源、观测时间与置信度。后续读取状态时仍需判断证据、时效及范围。

精确编号、版本、证据、时间、来源和范围保留确定字段。范围未声明不表示任意环境均适用，一次成功也不自动支持扩大能力的验证范围。

## 字段引用

[FieldBinding](../src/main/java/com/example/myhelper/world/model/FieldBinding.java) 有两个字段：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `slot` | `String` | 从整个统一实体根部定位的 JSON Pointer 字段路径 |
| `target` | `EntityRef` | 被引用的目标实体 |

路径示例：`/text`、`/data/value`、`/data/attributes/room`、`/data/factors/0`。字段名中的 `~` 写为 `~0`，`/` 写为 `~1`，数组元素使用下标。

同一位置可以保留确定值和多个引用。只有抽象表达时，将直接值设为 `null`，通过引用关联已有语义内容。多个引用究竟是补充说明、候选还是共同约束，由字段的使用规则决定。

[EntityRef](../src/main/java/com/example/myhelper/world/model/EntityRef.java) 保存：

| 字段 | 含义 |
| --- | --- |
| `id` | 目标实体稳定编号 |
| `revision` | 固定的目标修订号；为 `null` 时只引用身份 |
| `worldObjectType` | 目标世界对象类型 |
| `contextUnitType` | 目标世界陈述类型 |
| `unitType` | 目标能力类型 |
| `semanticType` | 目标语义类型 |

引用的四个类型字段也必须且只能填写一个，并与目标实体对应。需要复现的证据应固定 `revision`。

引用只保存编号，不嵌入完整实体，因此语义实体可以继续持有引用，关系网不预设中间节点数量、固定层数或拓扑。遍历和执行时的防环规则由后续模块处理。

## 向量表示

[Embedding](../src/main/java/com/example/myhelper/world/model/Embedding.java) 保存三个字段：

| 字段 | 含义 |
| --- | --- |
| `model` | 生成向量的模型名称 |
| `modelVersion` | 模型准确版本或权重摘要 |
| `values` | 向量分量，列表长度即维数，元素必须是有限数 |

任何类别的实体都可以附带向量。向量相似度用于表达语义相关程度，精确连接通过实体编号和修订完成。修改被向量化的内容后，需要重新生成或清空旧向量，避免内容与向量不一致。

## 数据示例

下面是一个设备实体的结构示例：设备的用途没有确定值，通过 `bindings` 关联抽象语义。编号、时间和来源仅作示意。

```json
{
  "id": "device:living-room-ac",
  "worldObjectType": "DEVICE",
  "contextUnitType": null,
  "unitType": null,
  "semanticType": null,
  "name": "客厅空调",
  "text": null,
  "data": {
    "purpose": null
  },
  "bindings": [
    {
      "slot": "/data/purpose",
      "target": {
        "id": "semantic:comfortable-environment",
        "revision": 1,
        "worldObjectType": null,
        "contextUnitType": null,
        "unitType": null,
        "semanticType": "CONTENT"
      }
    }
  ],
  "embedding": null,
  "revision": 1,
  "source": "manual:device-registration",
  "evidence": [],
  "scope": {},
  "createdAt": "2026-11-09T01:00:00Z",
  "updatedAt": "2026-11-09T01:00:00Z",
  "chainPositions": [],
  "statistics": {
    "successCount": 0,
    "failureCount": 0,
    "failureCauses": []
  }

```

目标仍使用同一个 `WorldEntity`，填写 `semanticType = CONTENT`、`text = "舒适的室内环境"`，并保存来源及可选向量。它还可以在 `data` 中声明因素位置，通过自身的 `bindings` 连接观测、用户偏好或其他抽象概念：

```text
客厅空调
  → 舒适的室内环境

          → 用户的温度偏好
          → 安静和柔和的氛围
```

## 链路位置数组

[ChainPosition](../src/main/java/com/example/myhelper/world/model/ChainPosition.java) 是 `WorldEntity.chainPositions` 的数组元素，不是新的世界实体类别。每条记录描述当前实体在某份固化链路中的一次使用位置。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `chainId` | `String` | 直接包含该使用位置的组合 Unit 稳定编号 |
| `chainRevision` | `long` | 链路精确修订号，从 1 开始 |
| `branchPath` | `List<String>` | 从外到内的分支编号路径；主干使用空列表 |
| `nodeId` | `String` | 该链路版本内的一次出现编号，不是被调用 Unit 的编号或数组下标 |
| `statistics` | `ExecutionStatistics` | 所属实体版本在该链路版本、该位置下的独立执行统计 |

同一个 Unit 在同一条链路两个位置使用，就保留两条记录。分支路径支持任意有限层数，构造时复制为只读列表；分支编号不能为 null 或空白。

局部 JSON 示例：

```json
{
  "chainPositions": [
    {
      "chainId": "unit:chain-a",
      "chainRevision": 3,
      "branchPath": ["branch-1", "branch-1-2"],
      "nodeId": "n7",
      "statistics": {"successCount": 0, "failureCount": 0, "failureCauses": []}
    },
    {
      "chainId": "unit:chain-a",
      "chainRevision": 3,
      "branchPath": ["branch-2"],
      "nodeId": "n12",
      "statistics": {"successCount": 0, "failureCount": 0, "failureCauses": []}
    }
  ]
}
```

正式字段位于实体顶层，不放在 data.chainPositions。WorldEntity 构造器将 null 数组保存为空列表，并复制非空数组。原 16 参数和 17 参数构造器继续可用，未传入的 statistics 默认空统计；原四参数 ChainPosition 构造器也保留，默认空统计。当前完整构造器在链路位置数组之后接收实体 statistics。

位置数组中的定位信息可以从链路结构派生，statistics 则记录执行结果，重建索引时不能丢弃或清零已有统计。完整节点、连接、条件和参数映射仍由组合能力的链路定义保存；本字段不会自动填充、反查、读取历史版本或展开整条链路。实体在不同修订中独立保存使用位置及统计。

## 执行统计与失败归因

[ExecutionStatistics](../src/main/java/com/example/myhelper/world/model/ExecutionStatistics.java) 同时用于实体和链路位置：

| 保存位置 | 统计范围 |
| --- | --- |
| `WorldEntity.statistics` | 当前实体 id/revision 的总体结果；组合 Unit 表示整条链路，原子 Unit 可表示该版本能力的总体结果 |
| `WorldEntity.chainPositions[i].statistics` | 所属实体版本在 chainId/chainRevision/nodeId 这个使用位置的结果 |

统计字段为 `successCount`、`failureCount`、`failureCauses`。次数均为非负 long。空统计为 0、0、空列表，只表示尚无已记录结果；不据此认定能力不可靠或从未执行。当前不新增会随成功/失败直接加减的可靠度分数，后续可根据计数和归因另行制定评分公式。

[FailureCause](../src/main/java/com/example/myhelper/world/model/FailureCause.java) 保存每项归因：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `causeId` | `String` | 稳定的原因编号，可复用原因定义 |
| `category` | `FailureCategory` | 计划问题、环境问题或尚未查明 |
| `reason` | `String` | 原因或失败现象描述 |
| `analysis` | `String` | 分析说明，未知时为 null |
| `occurrenceCount` | `long` | 该原因在当前统计范围内出现的次数 |
| `evidence` | `List<EntityRef>` | 支持归因的证据，需要复现时固定修订 |

[FailureCategory](../src/main/java/com/example/myhelper/world/model/FailureCategory.java) 包含 `PLAN`、`ENVIRONMENT`、`UNKNOWN`。UNKNOWN 指失败原因尚未分类，不表示执行结果未知。执行结果未知不能直接当成失败计数。一次失败可能有多个原因，也可能尚未归因，因此 occurrenceCount 之和不要求等于 failureCount。

共享 causeId 不共享出现次数。实体总体、各链路位置以及不同版本分别持有统计。位置统计按所属实体 revision 和链路 chainRevision 定位，记账不会自动改变能力定义 revision。定义变更后的统计迁移、并发更新、事件去重和历史留存由后续逻辑处理。

用户要求的记账语义以本轮结果分别记录，例如 A 成功、B 失败、C 未执行：

| 范围 | 成功次数变化 | 失败次数变化 |
| --- | --- | --- |
| 整条链路 | 0 | +1 |
| 位置 A | +1 | 0 |
| 位置 B | 0 | +1 |
| 位置 C | 0 | 0 |

整链成功时，整链与实际成功的参与位置分别记录成功；未执行的位置不变。表格描述未来业务模块的记账要求，构造器没有实现自动累加、逐级传播、归因分析或可靠度计算。

统计局部 JSON 示例：

```json
{
  "statistics": {
    "successCount": 5,
    "failureCount": 1,
    "failureCauses": [
      {
        "causeId": "cause:device-offline",
        "category": "ENVIRONMENT",
        "reason": "设备离线",
        "analysis": null,
        "occurrenceCount": 1,
        "evidence": []
      }
    ]
  }
}
```

## 当前结构检查

现有构造器检查实体和引用的编号、四个类型字段的互斥、修订号范围，以及字段引用的基本形式。ChainPosition 检查链路编号、链路修订、分支编号和位置编号；执行统计检查非负次数，失败归因检查编号、描述及非负归因次数。向量结构检查模型名称、模型版本、非空向量和有限分量。

目标实体是否存在、引用类型是否与目标一致、slot 是否指向真实字段，以及来源、证据、时效、合同是否充分，需要后续模块验证。当前实体层不执行工具、不生成向量，也不决定能力是否允许复用。

世界模型源码包含统一实体、四个类型枚举、引用/向量、链路位置、执行统计、失败归因及归因类别，共十二个 Java 文件。字段中文注释直接放在字段声明上方。
