# 自主探索开发文档

> 共同开发规则（2026-11-11 用户确认）：固定 LLM 文本集中到 LlmTexts；不用 Lambda，以可读性选择循环、方法和 switch，允许 `case ... ->`。所有任务继续前阅读[24-LLM文本与代码可读性规范](24-LLM文本与代码可读性规范.md)。

更新：2026-11-10。开发设计，未实现；本轮未授权启动后台探索或外部操作。

## 职责与输入输出

针对明确知识/能力缺口寻找证据、尝试允许的实现并提交候选。ExploreRequest 包含目标、缺口、已知事实、允许工具/范围、预算、停止条件和来源运行；ExploreResult 包含发现、证据、失败限制、未解决项与能力候选引用。

通过[编排入口](12-并行分支循环编排设计.md)运行任务，复用单次调用、执行、门禁和链路。探索不是另一套无限 Agent 循环，不绕过用户任务范围；探索结果进入[固化审核](16-技能固化开发文档.md)，不直接成为可复用事实。

## 流程

缺口请求 → 查询已知能力和证据 → 确定探索计划 → 受预算执行 → 验收与记录 → 提交候选/缺口报告。相同缺口可合并，但必须区分环境和版本。新用户任务需要资源时，可取消或暂停探索，在恢复时重新核对上下文。

自动定时探索、空闲检测、持续自学习仅保留扩展点，启用条件另行配置；不因旧文档已有定时器就自动启动。需要生成新工具时调用[工具生成流程](22-扩展模块开发边界.md)，验证与加载分开。

## 失败与验收

最大模型轮数、调用数、总时限、递归深度和成本预算必须有界；重复失败输出缺口，不无限重试。观测、推断与确认事实分开保存。验收覆盖预算停止、取消、环境变更、已有能力复用、候选不直接发布，以及探索轨迹可供固化复查。
