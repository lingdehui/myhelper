## 装配边界

2026-11-11 源码复核：当前缺少应用级 main / SpringBootApplication，生产代码没有 new AgentOrchestrator 或调用 submit 的入口。下一层应用装配须创建真实依赖、接收输入并显式调用 AgentOrchestrator.submit；当前文档中的构造示例只说明依赖关系，不是已存在的启动方法。原测试/检查及请求快照已移到独立 checks 目录，不纳入根工程默认测试源码路径。

模块使用同一进程内普通 Java 包及按需 Spring Bean；数据库配置装配已有实现，见[10](10-统一双写模块分析.md)。新增组件由统一入口注入：模型注册、单次调用、能力仓储/缓存、门禁、执行器、链路存储、编排器、交互。避免每个子任务创建连接池、线程池或重复工具注册表。

模型及工具执行配额、任务轮数/时限/递归深度、缓存条数/字节/TTL、链路保留策略均使用独立配置。不得硬编码真实密钥。保持用户当前 SDK/IDE/仓库环境；确需改变时单独处理。

## 存储与恢复

当前 DualWriteStore 是同步提交与补偿，不是跨库原子事务，不含持久化日志和跨进程锁。新检索索引、历史能力修订、执行链路日志及运行恢复均需明确适配与验证。

首版可选择单进程运行；重启后只能恢复有持久证据的状态。运行中/副作用未知的动作先核对，不能读到未完成记录就重跑。优雅停机停止接受新任务、请求取消或等待有界收尾、保存检查点、关闭受管资源。

## 集成验收场景

| 场景 | 必须观察到的结果 |
| --- | --- |
| 新目标无固化 | 模型规划、工具执行、验收、链路完整 |
| 规划前整条命中 | 条件满足时直接执行，无隐藏规划调用 |
| 规划后子节点命中 | 按 LLM 子任务目标重新查库，能找到规划前未召回的固化；匹配节点不再额外规划，未命中部分继续求解 |
| 两个独立子任务 | 同时推进，快分支不被慢分支整轮阻塞 |
| 数据依赖与共享桌面 | 依赖/资源约束被遵守，等待不耗尽工作配额 |
| 新固化发布 | 下一根入口或本任务下一次 PLAN 后检索发现，缓存没有全量增长 |
| 固化停用 | 新调用开始前核验并拒绝，已发生副作用如实报告 |
| 指令修订与取消 | 旧计划不提交新动作，迟到结果保留且不推进旧计划 |
| 局部失败及未知效果 | 不重跑已成功部分，不盲目重试未知副作用 |
| 离线模式 | 仅使用明确本地可用依赖，远程工具不可用如实报告 |

## 验证口径与性能

当前本地检查包括：AgentCaller 两种模式及预检；循环到单次调用再到 ToolCallback；根入口仅检索一次（递归和重规划不重复），每次 PLAN 总目标及子目标重新查询；整条/局部复用；并发、依赖传参、递归单线程完成；UNKNOWN 停止及取消后保留在途图；缓存容量/版本/停用；本地 HTTP 查询协议。真实服务、在途指令修订、用户补充后恢复、离线运行和性能对比未验证。共享资源锁等待会占用工具工作线程，调用方须据实际负载配置池；父任务等待子任务不占工作线程。

静态检查、编译、替身测试、本地协议检查、真实服务联调分别记录。与串行/无复用基线比较同等任务的模型调用数、实际用量、总耗时、关键路径、DB 查询次数及缓存字节量。并发不保证所有任务提速，必须计入排队和服务限流；未经测量不填写性能提升百分比。
