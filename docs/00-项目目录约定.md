# 00 - 项目目录约定

> 文档入口与阅读顺序见 [文档中心](README.md)。`docs/00`～`docs/13` 描述当前实现；
> `history/reference/audits` 分别表示历史、研究参考和阶段审计，不作为当前代码事实。

本文规定 MyHelper 文件的唯一归属。新增代码、AI 生成内容、诊断结果和个人数据均应遵守此结构，避免文件重新堆到项目根目录。

## 根目录

根目录只保留工程入口：

- `pom.xml`：唯一构建入口，项目不再保留无构建文件支撑的 Gradle wrapper。
- `docker-compose.yml`：基础设施编排。
- `start-env.bat` / `start-env.ps1` / `setup.sh`：启动与环境准备入口。
- `README.md`、`.gitignore`、`.gitattributes`：仓库元信息。

禁止把查询 JSON、调试日志、崩溃日志、音频样本、DLL 运行副本和小说素材直接写到根目录。

## 代码与资源

```text
src/main/java/com/example/myhelper/
├── world/          统一世界模型
├── memory/         Unit、图谱、向量和经验
├── service/        对话回合与通用运行服务
├── exploration/    自主探索
├── optimization/   元自我优化
├── autogen/        工具生成基础设施
├── generated/      AI 生成的 Java 工具
├── registry/       工具注册中心
├── integration/    Home Assistant 等外部集成
├── novel/          小说子系统
├── dialog/         对话状态机
├── schedule/       定时任务
├── config/         Spring 配置与模型路由
├── common/         跨模块的轻量公共代码
└── util/           底层工具类
```

`src/main/resources` 只存随应用发布的资源：配置、Prompt、Skill、日志配置及确需打包的模型。诊断输入输出不得放入 resources。

## 文档

- `docs/01`～`13`：当前权威设计。
- `docs/audits/`：问题清单、查缺补漏和阶段审计。
- `docs/reference/`：尚未全部实现的参考设计或研究稿。
- `docs/history/`：已经退役的历史架构，只用于追溯演进。

参考稿和历史稿不得作为当前运行逻辑的依据；发生冲突时，以当前编号文档和代码为准。

## 脚本

- `scripts/diagnostics/`：Neo4j、Qdrant、小说图谱等诊断脚本和无敏感信息的请求样例。
- `scripts/diagnostics/output/`：诊断输出，Git 忽略。
- `scripts/network/`：SSH 隧道等网络辅助脚本。

脚本必须使用 `$PSScriptRoot` 或项目相对路径，不得写死开发机绝对路径；凭据必须来自环境变量。

## 数据、模型与本地依赖

- `data/novel-materials/`：需要版本管理的创作素材。
- `data/private/`：联系人、Cookie、Token、接口抓包等本机私密数据，Git 忽略。
- `novels/`：小说正文和运行输出，Git 忽略。
- `models/`：不随应用包发布的外置推理模型。
- `lib/native/`：native DLL 的唯一源目录；构建时复制到 `target/classes/native`，根目录不保留副本。

## 生成物

以下内容必须保持未跟踪状态，并可安全重新生成：

- `target/`、`build/`、`.gradle/`
- `*.log`、`hs_err_pid*.log`、调试 `*.wav`
- `scripts/diagnostics/output/`
- 根目录运行时 DLL 副本
- `data/meta-optimizer/` 等运行状态目录
