# 13 - 内在驱动力引擎设计文档

> 最后更新：2026-08-10 | 版本：v2.1  
> 适用范围：myhelper v1.5+  
> 新增模块：预测误差驱动引擎、语义好奇心引擎、内驱力调度器、安全约束层  
> 状态：设计阶段，未开始实现

## 1. 概述

### 1.1 背景与愿景

当前 myhelper 的学习行为完全由外部规则驱动——空闲超时触发探索、失败次数达阈值聚合模式、成功次数足够标记脚本化。这些机制的共同特征是：**系统自身没有学习的欲望**，只是被动响应预设条件。

本设计文档旨在赋予 myhelper 两种根本性的内在驱动力：

| 驱动力 | 生物学类比 | 计算实现 |
|--------|-----------|---------|
| **驾驭感** | 婴儿反复扔勺子，直到能预测勺子的落点 | 预测误差最大化 → 反复实验 → 误差最小化 |
| **好奇心** | 儿童不断追问“这是什么”“为什么” | 未知概念检测 → 自动生成探索问题 → 知识图谱填充 |

加上这两个引擎后，myhelper 将从“被动的工具执行器”转变为“主动的认知建构者”。

### 1.2 核心设计原则

1. **零模型改动**：基于现有 `qwen3:30b` 的推理能力，所有内驱力通过外围认知脚手架实现，不对模型进行任何微调或 RLHF。
2. **安全第一**：好奇心必须在硬性约束边界内运作，危险操作永远需要用户确认。
3. **用户优先**：内驱力任务可以被用户随时打断和挂起，用户指令拥有最终仲裁权。
4. **可观测**：所有内驱力活动有完整日志、状态查询接口和可视化指标。
5. **渐进式集成**：作为现有自主探索引擎的扩展，不破坏已有三层缓存、Episode 学习等核心机制。

### 1.3 术语定义

| 术语 | 定义 |
|------|------|
| **世界模型** | 系统对“执行动作 X 后会发生什么”的内部预测模型，基于 LLM 推理实现。 |
| **预测误差** | 世界模型的预测结果与实际执行结果之间的语义差异，量化值 0.0~1.0。 |
| **内在奖励** | 由预测误差直接映射的驱动力分数。误差越大，奖励越高，驱动力越强。 |
| **驾驭感任务** | 由高预测误差场景触发的反复实验任务，目标是降低误差至阈值以下。 |
| **未知概念** | 在文本流中抽取的名词短语/专有名词，在知识图谱和向量库中均无足够关联。 |
| **语义好奇心任务** | 对未知概念自动生成的“探索-理解-存储”任务，优先级高于普通探索。 |
| **恐惧引擎** | 安全约束层的通俗称呼，对潜在危险操作产生负向驱动力，抑制好奇心。 |

### 1.4 实现难度总览与优先级

> ⚠️ **前置依赖**：当前探索引擎存在基础问题（AI找不到工具、死循环、100%失败率），必须先将 P0 修复验证通过后再开始本设计。

| 模块 | 新增类 | 难度 | 说明 |
|------|:--:|:--:|------|
| **安全约束层** | 4 | ⭐ | 纯规则匹配 + 简单LLM调用，无复杂依赖 |
| **语义好奇心引擎** | 5 | ⭐⭐⭐ | NER + Neo4j/Qdrant 查询，多步流水线 |
| **预测误差驱动引擎** | 7 | ⭐⭐⭐⭐ | 每步需LLM预测→执行→比较，增加大量延迟 |
| **内驱力调度器** | 4 | ⭐⭐⭐ | 优先级算法 + 资源监控，逻辑复杂但无外部依赖 |
| **集成改动** | — | ⭐⭐ | 修改9个现有文件，~150行 |
| **总计** | 20 | — | 5个Prompt + 1个配置文件 |

### 1.5 建议实施路线（分三期）

| 阶段 | 内容 | 理由 |
|:--:|------|------|
| **Phase 1** | 安全约束层（4个类） | 最简单，独立模块，不依赖其他改动。先建好护栏再放好奇心。 |
| **Phase 2** | 语义好奇心引擎（5个类） | 价值最高——从文本流中发现未知概念并自动学习，用户体验提升明显 |
| **Phase 3** | 预测误差驱动引擎（7个类） | 最复杂且影响面最大——每次工具调用前都要LLM预测，增加延迟。先验证 Phase 1+2 稳定后再做 |
| **后期** | 内驱力调度器（4个类） | 依赖前三期都就绪后才能有效调度 |

> **建议**：先完成 Phase 1（3-5天），观察系统稳定性，再逐步推进。

## 3. 预测误差驱动引擎 ⭐⭐⭐⭐

### 3.1 概述

这个引擎实现了“驾驭感”的内驱力循环：

```
┌──────────────────────────────────────────────────────────┐
│              预测误差驱动的学习循环                        │
│                                                          │
│   ┌──────────┐    执行动作     ┌──────────────┐          │
│   │ 世界模型  │ ────────────→ │  实际环境     │          │
│   │ (预测)   │               │  (真实结果)   │          │
│   └──────────┘               └──────────────┘          │
│        │                            │                   │
│        │    ┌───────────────────┐   │                   │
│        └───→│ 预测误差评估器    │←──┘                   │
│             │ (语义差异 0~1)    │                       │
│             └───────────────────┘                       │
│                     │                                   │
│                     ▼                                   │
│             ┌───────────────┐                           │
│             │ 内在奖励映射器 │                           │
│             │ 误差高→奖励高  │                           │
│             └───────────────┘                           │
│                     │                                   │
│                     ▼                                   │
│             ┌───────────────┐                           │
│             │ 驾驭感任务     │                           │
│             │ "反复尝试直到   │                           │
│             │  误差<阈值"    │                           │
│             └───────────────┘                           │
│                     │                                   │
│                     ▼                                   │
│             再次执行动作（循环）                          │
└──────────────────────────────────────────────────────────┘
```

### 3.2 WorldModelService

**文件路径**：`com.example.desktopbrain.drive.prediction.WorldModelService`

**职责**：在执行动作前，基于当前环境状态和待执行动作，生成结构化预测。

**接口定义**：
```java
@Service
public class WorldModelService {

    private final ChatClient localChatClient;  // qwen3:30b
    private final PromptLoader promptLoader;

    /**
     * @param stateDescription  环境描述（屏幕元素列表、系统状态摘要）
     * @param actionDescription 即将执行的动作（工具名 + 参数）
     * @return 结构化预测结果
     */
    public Prediction predict(String stateDescription, String actionDescription);

    /**
     * 批量预测，用于比较多个候选动作的预期结果
     */
    public List<Prediction> predictBatch(String stateDescription, List<String> actionDescriptions);
}
```

**Prediction 数据结构**：
```java
public record Prediction(
    String id,                    // UUID
    String expectedOutcome,       // 预期结果的文本描述
    double confidence,            // 预测置信度 0.0~1.0
    List<String> observableSignals, // 可观测的验证信号
    Instant timestamp
) {}
```

**Prompt 模板**（`prompts/world-model-predict.txt`）：
```
你是一个桌面环境的预测模型。给定当前环境和即将执行的动作，预测会发生什么。

当前环境：
{state_description}

即将执行的动作：
{action_description}

请以严格 JSON 格式输出你的预测：
{
  "expected_outcome": "详细描述你预期的结果，包括视觉变化、系统响应等",
  "confidence": 0.0~1.0,
  "observable_signals": ["信号1", "信号2"]  // 可用来验证预测是否正确的具体信号
}
```

**实现逻辑**：
1. 构造 Prompt，注入环境描述和动作描述。
2. 调用本地 `qwen3:30b`（复用 `myhelperConfig.localChatClient()`）。
3. 解析 JSON 响应，构造 `Prediction` 对象。
4. 异步存储到 `PredictionMemory` 供后续分析。
5. 超时保护：3 秒未响应则返回一个默认低置信度预测。

### 3.3 PredictionErrorEvaluator

**文件路径**：`com.example.desktopbrain.drive.prediction.PredictionErrorEvaluator`

**职责**：比较预测结果与实际执行结果，输出量化的误差分数。

**接口定义**：
```java
@Service
public class PredictionErrorEvaluator {

    /**
     * 评估单个预测的误差
     * @param prediction 世界模型预测
     * @param actualOutcome 工具回调返回的实际结果描述
     * @return 误差分数 0.0~1.0，及详细原因
     */
    public ErrorEvaluation evaluate(Prediction prediction, String actualOutcome);

    /**
     * 快速评估：仅基于 observableSignals 进行规则验证
     * 用于高频场景的性能优化
     */
    public ErrorEvaluation evaluateFast(Prediction prediction, String actualOutcome);
}
```

**ErrorEvaluation 数据结构**：
```java
public record ErrorEvaluation(
    double score,                 // 0.0~1.0，0=完全匹配，1=完全不符
    String reason,                // 简要说明差异
    List<String> matchedSignals,  // 匹配到的信号
    List<String> missedSignals    // 未匹配到的信号
) {}
```

**实现逻辑**：

**方案 A（语义比较，默认）**：
1. 使用 Prompt `prompts/prediction-error.txt`，输入预测的 `expectedOutcome` 和实际的 `actualOutcome`。
2. LLM 输出一个 0.0~1.0 的分数及简要原因。

**方案 B（规则优先，优化路径）**：
1. 如果预测中包含 `observableSignals`，先进行规则匹配：
    - 检查 `actualOutcome` 中是否包含每个信号的文本描述。
    - 如果所有信号都匹配 → `score = 0.0`（完美预测），无需调用 LLM。
    - 如果有信号缺失 → `score = 缺失信号数 / 总信号数`。
2. 如果没有 `observableSignals` 或规则匹配不确定，回退到方案 A 的语义比较。

**Prompt 模板**（`prompts/prediction-error.txt`）：
```
比较以下预测结果和实际结果，评估它们的语义差异。

预测结果：
{predicted_outcome}

实际结果：
{actual_outcome}

请以严格 JSON 格式输出：
{
  "score": 0.0~1.0,           // 0=完全一致，1=完全不同
  "reason": "简要说明差异所在"
}
```

**配置参数**（`desktopbrain-drive.yml`）：
```yaml
prediction:
  error-evaluation:
    use-fast-path: true       # 是否优先使用规则匹配
    llm-fallback: true        # 规则匹配不确定时是否调用 LLM
    llm-timeout-ms: 2000      # LLM 比较超时
```

### 3.4 IntrinsicRewardMapper

**文件路径**：`com.example.desktopbrain.drive.prediction.IntrinsicRewardMapper`

**职责**：将预测误差映射为内在奖励，并决定是否以及如何生成驾驭感任务。

**接口定义**：
```java
@Service
public class IntrinsicRewardMapper {

    /**
     * 处理一次预测误差，返回可能的好奇心任务
     * @param error 误差评估结果
     * @param context 任务上下文
     * @return 驾驭感任务（如果误差超过阈值），否则 null
     */
    public CuriosityTask mapToTask(ErrorEvaluation error, TaskContext context);

    /**
     * 检查某场景是否处于冷却期
     */
    public boolean isInCooldown(String sceneId);

    /**
     * 获取当前所有活跃的驾驭感任务
     */
    public List<CuriosityTask> getActiveTasks();
}
```

**CuriosityTask 数据结构**（继承自 `ExplorationTask`）：
```java
public class CuriosityTask extends ExplorationTask {
    private String sceneId;           // 场景唯一标识
    private double initialError;      // 初始预测误差
    private double currentError;      // 当前误差（动态更新）
    private double targetError;       // 目标误差阈值
    private int maxAttempts;          // 最大尝试次数
    private int attemptsMade;         // 已尝试次数
    private String actionDescription; // 反复尝试的动作描述
    private List<ErrorEvaluation> errorHistory; // 误差变化历史
}
```

**核心决策逻辑**：
```java
public CuriosityTask mapToTask(ErrorEvaluation error, TaskContext context) {
    // 1. 误差太低，世界模型已掌握，不需要好奇心
    if (error.score() <= config.getCuriosityThreshold()) {
        updateWorldModelConfidence(context, true);  // 强化世界模型
        return null;
    }

    // 2. 场景在冷却期，跳过
    if (isInCooldown(context.getSceneId())) {
        return null;
    }

    // 3. 检查是否已有该场景的活跃任务
    CuriosityTask existingTask = findActiveTask(context.getSceneId());
    if (existingTask != null) {
        // 更新误差历史
        existingTask.getErrorHistory().add(error);
        existingTask.setCurrentError(error.score());
        existingTask.setAttemptsMade(existingTask.getAttemptsMade() + 1);

        // 误差已下降足够？标记完成
        if (error.score() <= existingTask.getTargetError()) {
            completeTask(existingTask);
            return null;
        }

        // 已达最大尝试次数？标记失败并归档
        if (existingTask.getAttemptsMade() >= existingTask.getMaxAttempts()) {
            archiveTask(existingTask);
            return null;
        }

        // 继续尝试
        existingTask.setPriority(calculatePriority(error.score()));
        return existingTask;
    }

    // 4. 创建新的驾驭感任务
    CuriosityTask newTask = new CuriosityTask();
    newTask.setSceneId(context.getSceneId());
    newTask.setInitialError(error.score());
    newTask.setCurrentError(error.score());
    newTask.setTargetError(config.getTargetError());
    newTask.setMaxAttempts(config.getMaxCuriosityAttempts());
    newTask.setAttemptsMade(0);
    newTask.setActionDescription(context.getActionDescription());
    newTask.setPriority(calculatePriority(error.score()));  // 误差越大优先级越高
    newTask.getErrorHistory().add(error);

    // 5. 记录场景触发时间，用于冷却控制
    recordSceneTrigger(context.getSceneId());

    return newTask;
}

private double calculatePriority(double errorScore) {
    // 误差映射到 1-10 的优先级
    return Math.min(10.0, errorScore * 10.0);
}
```

**配置参数**（`desktopbrain-drive.yml`）：
```yaml
prediction:
  intrinsic-reward:
    curiosity-threshold: 0.5       # 误差低于此值不触发好奇心
    target-error: 0.2              # 任务完成的目标误差
    max-curiosity-attempts: 30     # 单场景最大尝试次数
    cooldown-minutes: 60           # 同场景冷却时间
    max-active-tasks: 3            # 同时活跃的驾驭感任务上限
```

### 4.2 UnknownConceptDetector

**文件路径**：`com.example.desktopbrain.drive.curiosity.UnknownConceptDetector`

**职责**：从文本流中抽取命名实体，过滤已知概念，输出未知概念列表。

**接口定义**：
```java
@Service
public class UnknownConceptDetector {

    /**
     * 从文本中检测未知概念
     * @param text 输入文本
     * @param source 文本来源（USER_INPUT / TOOL_RESULT / WEB_CONTENT / SYSTEM_LOG）
     * @return 未知概念列表
     */
    public List<UnknownConcept> detect(String text, TextSource source);

    /**
     * 批量检测（用于长文本分段处理）
     */
    public List<UnknownConcept> detectBatch(List<String> textSegments, TextSource source);
}
```

**UnknownConcept 数据结构**：
```java

    String id,                    // UUID
    String name,                  // 概念名称
    String contextText,           // 发现该概念的上下文（前后各 100 字）
    TextSource source,            // 来源
    double noveltyScore,          // 新颖性评分 0.0~1.0（知识库中越陌生越高）
    double relevanceScore,        // 与当前任务的关联度
    Instant discoveredAt
) {}
```

**实现逻辑**：

**Step 1：实体抽取**
- 使用 Prompt `prompts/ner-extract.txt`，调用本地模型。
- 提取：名词短语、专有名词、缩写、技术术语、错误代码等。
- 对长文本先分段，每段不超过 500 字，并发处理。

**Step 2：已知度检查**
对每个候选实体，并行查询：
```java
// Neo4j 精确/模糊匹配
boolean inGraph = knowledgeGraphService.existsConcept(name);

// Qdrant 向量相似度
double maxSimilarity = vectorMemoryService.getMaxConceptSimilarity(embed(name));

// 综合判定
boolean isKnown = inGraph || maxSimilarity > config.getConceptSimilarityThreshold();
```

**Step 3：噪音过滤**
- 过滤长度 < `min-concept-length` 的实体。
- 过滤纯数字、纯符号。
- 过滤常见停用词列表中的词。

**Step 4：新颖性评分**
```java
double noveltyScore = 1.0 - Math.max(
    inGraph ? 1.0 : 0.0,
    maxSimilarity
);
```

**综合评分算法**：
```java
public double calculateCuriosityScore(UnknownConcept concept) {
    double score = 0.0;

    // 1. 新颖性（越陌生越想学）
    score += concept.noveltyScore() * 4.0;  // 权重 40%

    // 2. 与当前任务的关联度
    score += concept.relevanceScore() * 3.0;  // 权重 30%

    // 3. 来源权重
    score += switch (concept.source()) {
        case USER_INPUT  -> 2.0;  // 用户说的话中的新词，优先学
        case SYSTEM_LOG  -> 1.5;  // 系统日志中的未知错误码
        case TOOL_RESULT -> 1.0;
        case WEB_CONTENT -> 0.5;
    };

    // 4. 概念类型加成
    if (isErrorCode(concept.name())) score += 1.0;  // 错误码更值得学
    if (isFilePath(concept.name())) score += 0.5;

    return Math.min(10.0, score);
}
```

**核心决策逻辑**：

```java
public ArbitrationDecision arbitrate(UserCommand userCommand) {
    // ──── 第一层：安全门禁 ────
    // 如果有任何需要用户确认的操作挂起，不处理内驱任务
    if (userConfirmGate.hasPendingConfirmation()) {
        return new ArbitrationDecision(DecisionType.IDLE, null,
            "等待用户确认危险操作", false);
    }

    // ──── 第二层：用户指令存在 ────
    if (userCommand != null && !userCommand.isEmpty()) {
        // 2a. 用户指令是反馈（"有用/没用"）→ 最高优先
        if (userCommand.isFeedback()) {
            return new ArbitrationDecision(DecisionType.EXECUTE_USER_COMMAND, null,
                "处理用户反馈", false);
        }

        // 2b. 用户指令是打断/紧急 → 挂起所有内驱任务
        if (userCommand.isUrgent()) {
            suspendAllDriveTasks();
            return new ArbitrationDecision(DecisionType.EXECUTE_USER_COMMAND, null,
                "用户紧急指令，挂起所有内驱任务", false);
        }

        // 2c. 普通用户指令 → 比较优先级
        DriveTask topDriveTask = getTopPriorityDriveTask();
        if (topDriveTask != null &&
            topDriveTask.getPriority() > userCommand.getPriority() + 2) { // 需要明显更高
            return new ArbitrationDecision(DecisionType.EXECUTE_DRIVE_TASK, topDriveTask,
                "内驱任务优先级显著高于用户指令", true);  // 通知用户
        } else {
            // 用户指令优先
            return new ArbitrationDecision(DecisionType.EXECUTE_USER_COMMAND, null,
                "执行用户指令", false);
        }
    }

    // ──── 第三层：无用户指令 → 处理内驱任务 ────
    DriveTask topDriveTask = getTopPriorityDriveTask();
    if (topDriveTask != null) {
        // 资源检查
        if (!resourceGuard.canExecute(topDriveTask)) {
            return new ArbitrationDecision(DecisionType.IDLE, null,
                "资源不足，等待释放", false);
        }
        return new ArbitrationDecision(DecisionType.EXECUTE_DRIVE_TASK, topDriveTask,
            "执行内驱任务", false);
    }

    // ──── 第四层：完全空闲 ────
    return new ArbitrationDecision(DecisionType.IDLE, null,
        "无任务，空闲等待", false);
}
```

**优先级体系**：

| 优先级 | 任务类型 | 说明 |
|--------|---------|------|
| 10 | 用户反馈处理 | “有用/没用” |
| 9 | 用户紧急指令 | 打断、停止等 |
| 8 | 用户普通指令 | 默认 |
| 7-9 | 语义好奇心任务 | 高分未知概念 |
| 5-8 | 驾驭感任务 | 高预测误差 |
| 1-4 | 普通探索任务 | 工具学习等 |

## 12. 预期效果与迭代路线

### 12.1 短期（集成后 1-2 周）
- 系统在遇到不熟悉的界面元素时，会在空闲时反复探索直至掌握。
- 遇到新术语/错误码会自动搜索并存入知识图谱。
- 用户可感知：助手变得“更好奇”，偶尔会主动报告“我在学习 XX”。

### 12.2 中期（1-3 个月）
- 世界模型覆盖常用操作场景，工具调用更稳健。
- 知识图谱自动增长，语义理解能力逐步提升。
- 可能的问题：好奇心任务过多消耗资源，需根据日志调优阈值。

### 12.3 长期演进
- 引入**元认知**：系统对自己“哪些场景掌握得好/差”形成自我模型。
- 引入**目标层级**：好奇心不再是无差别的，而是服务于更高层的认知目标。
- 探索**跨场景泛化**：在一个场景中学到的规律，能否迁移到类似场景。
