# 交互与语音开发文档

> 共同开发规则（2026-11-11 用户确认）：固定 LLM 文本集中到 LlmTexts；不用 Lambda，以可读性选择循环、方法和 switch，允许 `case ... ->`。所有任务继续前阅读[24-LLM文本与代码可读性规范](24-LLM文本与代码可读性规范.md)。

更新：2026-11-10。开发建议，当前仅留有模型资源和旧文档，不能认定重写语音功能已接通。

## 职责与入口合同

文字、语音或其他入口统一产生 UserInstruction：instructionId、sessionId、关联 rootRunId（可选）、正文、时间、来源和明确的新增/修改/取消标记（若入口能提供）。输出消费运行事件和最终结果，展示等待用户、执行中、部分失败和取消。

入口不自行拆自然语言任务；把指令交给[编排器](12-并行分支循环编排设计.md)。多条同时到达的指令允许并行，不用一条全局聊天消息列表承载所有任务。指代及业务先后由模型或明确入口关系解析。

## 语音流水线

音频采集 → VAD/分段 → ASR → 语句组装 → 统一指令入口；输出经文本事件 → TTS → 播放。唤醒、声纹、设备选择作为入口策略，优先恢复文字入口再接音频。旧资源路径、模型许可与兼容性实施时核对。

## 打断与追加

停止播音不等于取消工具；取消任务必须带运行身份。用户追加要求更新受影响任务版本，无法确定指代时询问；不能把所有新发言当作取消前一任务。事件去重避免一次语音被重复提交。模型等待用户时保留关联信息，补充回复只恢复对应任务。

## 验收

相同指令 ID 不重复执行；同时指令不串上下文；打断播音与取消执行分开；音频失败可以报告或回退文字；长任务持续显示真实进度；最终回复能关联执行证据；语音链路单独验证，不以资源文件存在代替可运行。
