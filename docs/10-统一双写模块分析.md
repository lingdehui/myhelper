# 统一数据库读写与双写模块

> 共同开发规则（2026-11-11 用户确认）：固定 LLM 文本集中到 LlmTexts；不用 Lambda，以可读性选择循环、方法和 switch，允许 `case ... ->`。所有任务继续前阅读[24-LLM文本与代码可读性规范](24-LLM文本与代码可读性规范.md)。

更新：2026-11-10（本轮补调用方边界，代码和原验证记录未变）。当前实现位于 `src/main/java/com/example/myhelper/persistence/`。

## 用户已确认的边界

本模块只负责数据库读写、统一提交、失败补偿和错误报告。读取来源、写入目标由调用方明确指定；不根据 WorldEntity 或 EntityRef 的类型选库，不增加引用展开，不解释强弱引用的业务含义。实体类型到存储位置的映射由上层另行设计。

两个库均可保存实体内容和引用。实体的类型、embedding 是否存在，都不能改变调用方指定的目标。仅实际有写入数据的库参与操作；涉及两库时协调提交和补偿。

模块划分用于隔离职责、便于修改，当前为普通 Java 包，无独立启动或 HTTP 接口要求。后续模块同样遵守。新任务务必维护自己的文档，并同步总接续文档；务必写好职责、参数、关键流程和失败边界注释，字段注释放在声明上方。用户进一步要求本模块逐行注释：当前各生产类的字段、方法和执行语句均在上方添加中文说明，并展开原先一行多个语句的写法。

## 当前接口

`DualWriteStore.Database` 只有 `NEO4J`、`QDRANT`，是物理数据库标识，不是新增实体分类。

```java
// 显式指定单个实体的写入目标。
store.write(NEO4J, entity);
store.write(QDRANT, entity);

// 指定单库批量写入；另一库不参与准备、提交或补偿。
store.writeBatch(NEO4J, graphEntities);

// 两库可分别接收不同的数据，共用一次提交和失败补偿边界。
store.writeBatch(Map.of(
    NEO4J, graphEntities,
    QDRANT, qdrantEntities
));

// 同一实体需要存两库时，由调用方明确列入两边。
store.writeBatch(Map.of(
    NEO4J, List.of(entity),
    QDRANT, List.of(entity)
));

// 读取只访问指定库，缺失返回 Optional.empty，不自动回退到另一库。
Optional<WorldEntity> result = store.read(QDRANT, entityId);
```

例子中的数据库标识可通过 `import static com.example.myhelper.persistence.DualWriteStore.Database.*;` 引入。

本轮移除了隐式选库的旧 `write(entity)`、`writeBatch(List)`、`read(id)` 签名。项目内调用已更新。空目标列表不产生数据库访问；同一目标内重复 ID 会在任何数据库访问前拒绝，同一 ID 可以由调用方明确写入两个目标。这里只按参数分派，不根据类型、向量或引用调整目标。

## 实体与引用的保存

- `Neo4jEntityStore` 保存完整实体 JSON 与 revision；bindings 和 evidence 另外投影为 WORLD_REF 边，保留位置、类别、顺序和目标修订。完整引用中的四个目标类型字段保存在 JSON 中。图端点身份节点只是引用投影，不证明目标实体存在、属于 Neo4j 或其内容是确定事实。读取还原完整 JSON，不读取引用目标。
- `QdrantEntityStore` 将完整实体 JSON 保存在 payload.entity，保留正文、data、四个类型字段、bindings、evidence、source、scope、revision、时间及 embedding。原实体 ID 保存在 payload，点 ID 使用稳定 UUID 映射。读取使用完整 JSON，不按引用含义筛选或改写。
- 2026-11-10 世界模型新增顶层 chainPositions。EntityJson 使用统一 record 映射，未设置业务字段白名单；新字段随实体 JSON 保存，旧数据缺字段时由 WorldEntity 构造器将 null 归一为空列表。位置数组不自动投影为 WORLD_REF 边，不改变读取来源、写入目标或引用展开职责。本轮只静态核对，未编译或运行新字段往返验证。
- 同日新增 WorldEntity.statistics 和 ChainPosition.statistics，复用 ExecutionStatistics、FailureCause、FailureCategory。它们仍通过完整 record JSON 保存；旧 JSON 缺少 statistics 时由模型构造器设为空统计。本轮未修改存储代码或进行往返测试，自动记账、并发计数和统计/定义版本的一致性不属于当前读写实现。
- 指定写入 Qdrant 且 embedding 为 null 时，发送 `vector: {}`，保存只有 ID 和 payload 的点；更新会清除原来的向量而保留本次实体内容与引用。不会再删除整个实体点，不使用零向量或零维数组冒充向量。
- embedding 有值时，Qdrant 写入实际向量；Neo4j 仍按完整实体保存。向量存在与否不决定目标库。
- `EntityJson` 独立支持 record、嵌套 JSON 数据与 Instant，无需 Spring 启动。引用数据原样往返，强弱引用的解释及类型到库的映射属于上层。

当前按 ID 读取各库的当前实体；没有增加引用展开或历史版本查询。EntityRef 的类型、ID、revision 被完整保存，不代表模块会自动定位目标或查询历史修订。

## 初始化与使用

新增 `PersistenceConfiguration`，复用 `src/main/resources/application.yml` 中现有数据库配置。上层 Spring Boot 容器扫描本包，或显式 `@Import(PersistenceConfiguration.class)` 后，可直接构造器注入 `DualWriteStore`、`Neo4jEntityStore`、`QdrantEntityStore`。装配类没有启动入口，不需要本模块独立启动。

```java
// context 为已经加载 application.yml 并注册本模块配置的上层 Spring 容器。
DualWriteStore store = context.getBean(DualWriteStore.class);
Neo4jEntityStore graph = context.getBean(Neo4jEntityStore.class);
QdrantEntityStore vector = context.getBean(QdrantEntityStore.class);
// 按实际使用的库显式初始化；仅用 Qdrant 时无需调用 graph.initialize()。
graph.initialize();
// 直接使用配置中的 vector-size 与 distance，无需在业务调用处重复填写。
vector.initialize();
store.write(QDRANT, entity);
```

| 配置 | 绑定方式 |
| --- | --- |
| `spring.neo4j.uri`、`spring.neo4j.authentication.username/password` | 复用 Boot 4.1.0-M2 的 Neo4jAutoConfiguration，创建并管理共享 Driver；已有 Driver Bean 时复用 |
| `spring.data.neo4j.database` | 可选；未配置时使用账号默认数据库 |
| `qdrant.host`、`qdrant.port`、`qdrant.collection` | 构造 REST 地址和集合路径，沿用当前文件的 localhost、6333、desktop-memory |
| `qdrant.vector-size` | 沿用当前文件的 768，绑定到无参数 initialize() |
| `qdrant.scheme`、`qdrant.distance`、`qdrant.request-timeout` | 在原文件补充 http、Cosine、30s；超时同时用于连接及单次请求 |
| `qdrant.api-key` | 在原文件以 `${QDRANT_API_KEY:}` 引用可选环境变量，空值表示不发送认证头 |

保留原手动构造入口供测试或非 Spring 场景使用；原六参数 Qdrant 构造器仍需调用 initialize(dimensions, distance)，新装配路径无需重复传集合参数。普通 AnnotationConfigApplicationContext 不会自动加载 application.yml，非 Boot 调用方须先把配置加入 Environment；配置检查程序演示了该流程。

容器装配只创建客户端和适配器，不创建集合或发起查询。initialize 创建图 ID 唯一约束、创建或检查 Qdrant 无名向量集合，需相应权限；现有集合不匹配时明确报错，不删除重建。Driver 和专用 HttpClient 生命周期由 Spring 管理，适配器不关闭共享客户端。单库操作不要求另一个库在线。episodes-collection 和 episode 等历史业务配置未接入此模块；集合业务用途、向量模型选择仍由上层负责。

## 提交与补偿

先复制并校验各目标的批次，再对非空目标按 NEO4J、QDRANT 的固定顺序取得写前快照并提交。全部参与分支成功后正常返回；失败则逆序补偿。单库操作同样支持失败补偿，但不会触及未指定的库。

`SnapshotParticipant` 恢复旧实体或移除本次新增内容；逐条尝试并汇总补偿错误。Qdrant 的无向量实体也有完整快照，可以恢复。`WriteFailure` 暴露操作编号、原始异常和补偿异常，`rollbackCompleted()` 对已识别的传输未知结果返回 false。

这是同步快照补偿，允许中间状态可见，不是跨库原子事务或标准 TCC。要求一个共享协调实例独占同一实体的写入；没有跨进程锁、持久化操作日志或崩溃自动恢复。超时迟到请求及补偿失败仍需要调用方处理，不能保证所有故障均已回滚。未增加业务流程重跑、引用修复、业务清理策略或后台重试。

## 验证与实际限制

本轮用本地 Jackson 2.21.1 / annotations 2.21、Neo4j Driver 6.0.2、Spring Framework 7.0.6、Boot 4.1.0-M2，JDK17 独立编译世界模型、存储类、配置类及检查程序通过；未修改世界模型数据结构或机器环境配置。

- `DualWriteStoreCheck`：显式单库写入/读取、同类型不同目标、读不到不回退、两库不同批次、空分支跳过、同库重复 ID 在访问前拒绝、跨库同 ID、双库失败补偿、补偿失败报告及单库补偿检查通过。
- `QdrantEntityStoreCheck`：实际 HttpClient 对本地 HTTP 测试服务器检查通过，覆盖明确选库、包含多类型/多位置/循环引用和证据的完整实体往返、无向量实体插入/更新、向量清空后正文保留、部分成功补偿、恢复无向量快照、不展开引用。
- `Neo4jEntityStoreCheck`：Driver 接口替身边界检查通过，验证完整 JSON 与引用字段往返、引用投影数量、旧实体恢复，以及不读取引用目标；不代表 Cypher 或真实数据库验证。
- `PersistenceConfigurationCheck`：读取项目实际 application.yml，验证 Spring Bean 装配、Neo4j 地址与账号密码绑定、Qdrant 地址覆盖/原集合名/原维数、无参数初始化，以及装配时不访问数据库。网络只指向本地测试服务器，不输出真实认证信息。

尚未执行真实 Neo4j/Qdrant 联调。本轮未重跑完整 Maven 构建，也未继续排查或修改 IDE/SDK/仓库环境。总接续文档已记录另一任务使用现有 JDK25 配置完成过 Maven compile，该历史结果不能替代本轮配置改动的完整项目验证。已通过的本地检查不能替代真实服务验证。
