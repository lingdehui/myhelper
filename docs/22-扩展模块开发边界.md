# 扩展模块开发边界

> 共同开发规则（2026-11-11 用户确认）：固定 LLM 文本集中到 LlmTexts；不用 Lambda，以可读性选择循环、方法和 switch，允许 `case ... ->`。所有任务继续前阅读[24-LLM文本与代码可读性规范](24-LLM文本与代码可读性规范.md)。

更新：2026-11-10。旧项目相关模块的开发入口；均未在当前重写中实现。本文按模块列出职责和首版验收，不将旧功能清单视为本轮实施授权。

## 1. 工具生成与动态加载

输入明确能力缺口、参数/输出合同、允许依赖及测试用例；输出候选源码/制品、版本、测试证据和限制。流程为生成 → 隔离构建/测试 → 审核 → 注册特定版本 → 小范围验证 → 发布。生成代码不能直接进入当前进程执行，也不能仅凭编译成功取得复用资格。

注册、停用和版本变更交给工具注册与能力发布合同；缓存只按需加载。验收覆盖不兼容版本、构建失败、测试未通过不注册、加载失败不污染现有工具、来源与制品可追溯。沙箱和加载机制尚待选型。

## 2. 记忆维护与价值评估

输入能力复用统计、观测时效、证据质量、依赖关系和保留策略；输出归档/降级/刷新建议及可审计变更。质量分仅作排序或审核辅助，不能直接替代门禁和验证。

默认先标记归档，不能删除仍被运行、能力定义、证据或历史版本引用的数据。定时清理需明确配置，当前不自动启动。验收覆盖引用保护、过期观测不再当现状、归档后候选筛除和幂等维护。物理删除与长期保留策略另行确认。

## 3. 元自我优化

输入可比较的性能/成本/质量指标、允许调整的配置白名单和回退版本；输出试验记录与配置建议。不得自行扩大权限或修改生产代码。先离线回放验证，再由明确策略应用，效果下降能回退。验收以固定任务集对比，不把更低 Token 当作任务质量提升。

## 4. 业务扩展（小说辅助、设备与应用集成）

小说质量规则、Home Assistant、桌面/MCP 等作为领域能力和合同接入统一入口；不另起一套固化/编排引擎。输入领域目标和数据，输出能力调用或验收结果，状态及证据仍按世界模型保存。

首版只恢复明确被选择的业务链路；验收具体到设备状态、文件内容或领域质量条件。旧工具数量、包名、接口清单需要逐项映射，不宣称旧功能自动兼容。

## 5. 接入顺序

先完成[主路径与集成验收](21-装配部署与集成验收.md)，再按实际缺口接入工具生成、维护、领域模块，最后考虑优化试验。每个模块开始实现时在本文对应节扩充实际接口或拆出独立文档，并同步总入口及进度。
