## 3. 已确认的世界模型方向

1. 世界模型同时表达具体与抽象：具体信息用图表达，抽象信息保留原文、来源和向量表示。
2. 对象、陈述、能力、语义均具有稳定身份，可以相互引用。语义实体本身也能持有引用，允许多层、分支和循环，不能限定为单层附件或固定长度链。
3. 所有语义位置通过 bindings 字段引用数组连接；同一位置可有直接值和多个引用。仅有抽象描述时可以留空直接值，不伪造具体对象。
4. 精确编号、版本、证据、时间、来源和适用范围应精确保存；语义相似不等于满足执行条件。
5. 用户要求一个统一实体，类型定义分为四个独立枚举，而不是把所有取值放到一个 EntityType 中。字段注释放在字段声明上方。
6. 模型生成能力属于候选，需要独立审核；一次成功不支持自动跨环境泛化，需记录验证范围、工具版本、证据和失败限制。

## 5. 整体架构与拆分建议

模块分类来自用户；细分包名为建议。用户已确认按职责隔离，不要求独立启动、部署、Maven 子模块或 HTTP 接口。

| 逻辑模块 | 职责 | 边界 |
|---|---|---|
| world 世界模型 | 保存与查询四类实体、引用、事实、证据和语义 | 提供知识依据；执行资格由门禁判定 |
| persistence 数据库读写 | 所有 Neo4j/Qdrant 查询和保存的统一入口；按指定来源执行 ID/批量/字段/向量查询，协调指定目标的提交及补偿 | 用户已明确：不根据类型选库、不展开引用、不解释引用强弱；业务仓储组织条件和实体，数据库客户端仅在本包 |
| agent 核心流程 | 根据入参调用 LLM，按模式返回模型结果或执行工具后返回 | 协调其他模块，不自行承担存储、门禁策略和固化审核 |
| orchestration 循环编排 | 接收目标/能力调用、组织单次调用、递归子任务与调度，向外发送事实并查询进度 | 依赖由模型/能力定义提出；只持有当前调度状态，不自建权威进度/恢复库 |
| records 执行记录与恢复事项 | 保存任务、执行事实、证据、进度、问题和版本，提供查询、运行领取及审核入口 | 合同和循环接线已实现；生产存储与策略待外部模块开发 |
| capability 固化检索与缓存 | 规划前后找整条/子能力，缓存当前计划所需版本 | 不负责固化生成，不用语义相似度直接放行执行 |
| gate 门禁 | 检查输入合同、适用条件、证据和执行范围 | 返回放行、阻断或需要补充的依据 |
| skill 技能固化 | 管理候选、审核结果、验证范围及失败限制 | 接收轨迹和证据；不把一次成功自动升级为通用能力 |
| exploration 自主探索 | 针对知识或能力缺口探索、补证据、提出候选 | 经共同执行与门禁协议开展动作 |
| llm 模型接入 | 封装调用、模型选择及协议转换 | 向核心流程返回决策候选，不直接绕开执行约束 |
| execution 工具执行 | 执行 Unit 或工具，返回实际结果 | 不自行宣告任务目标已完成 |
| tools 工具管理与隔离运行（建议） | 管理工具版本、生成与动态发布、受限运行、公共变量及精确调用入口 | 组合技能沿用编排和固化，执行统计沿用世界模型 |
| interaction 输入输出 | 文字、语音等任务入口及结果展示 | 对接核心流程，不承载核心业务规则 |

外层编排器通过独立检索、上下文、门禁和执行模块组织任务。AgentCaller 保持一次调用边界；已固化能力可以绕过它直接执行。执行链路供固化等模块只读消费。数据库模块不接管类型路由、引用展开或缓存。完整依赖见项目总文档。

## 6. 核心流程模块要做什么

AgentCaller 职责保持“调用一次 LLM → 返回”，或“调用一次 LLM → 执行本轮工具 → 返回”。新增的循环编排在外层；单次类不负责生命周期、知识查询或固化审核。

当前 Request 已实现 modelRef、messages、toolNames、mode；Result 保持 response、messages、executionAttempted。新增请求级工具重载及工具定义读取；两种模式都预检工具名及调用 ID。外层用 CALL_ONLY 解析 submit_plan/finish_task；运行上下文、结构化 Outcome、调度和链路放在 orchestration，不扩大单次类职责，见 docs/11～14。

工具名由注册表解析为工具定义和回调，参数来自结构化响应。任务类别、默认工具、成功案例和上下文由外层准备，固化检索独立于单次类。

已实现 CALL_ONLY / CALL_AND_EXECUTE。下一轮由外层驱动，不在单次类内部循环；编排工具递归提交任务，运行时限制轮数、时限和递归深度。直接执行已有能力不应先无条件调用模型。

上一轮反馈建议包含工具调用编号、工具名、参数、失败原因及已知实际结果，保留与原调用的对应关系；不自动重试。上下文准备、任务级循环、门禁、验收、知识写入和固化由上层负责。

Spring AI 实现 API 随版本变化；pom 当前为 2.0.0-M3，编码时核对该版本依赖，不能直接套用最新文档接口。
